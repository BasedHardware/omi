## Summary

Makes the mobile store release lane self-driving end to end, per David's 2026-10-14 direction. The daily gate (merged in #21477) already owns dispatch; this PR removes the last human queue points:

1. **iOS: `AFTER_APPROVAL` + automatic phased release.** App Store Connect has no API to issue a MANUAL developer-release command, so queue-for-human builds piled up approved-but-unreleased (1.0.562 sat approved ~2 days; releasing it was a manual console press). Submissions now release on Apple's approval, and the brake moves post-release: the 7-day phased rollout is pausable in App Store Connect. Constants `RELEASE_TYPE` / `PHASED_RELEASE` keep `MANUAL` / no-phased one flip away (preservation tests included).
2. **Android: staged production rollout at 5%.** Candidates now go to production as `inProgress` with `userFraction 0.05` (haltable in Play Console) instead of a console draft. `STAGED_ROLLOUT_FRACTION=None` restores draft mode (preservation test included).
3. **Fixes the broken replace path** (root-caused 2026-10-14): Apple strips the `appStoreVersion` relationship from items of COMPLETED review submissions, so `review_submission_for_version()` could never succeed post-completion — the 1.0.563 train failed on exactly this and the failure was silent to GH-side monitoring. The lookup now reads `GET /v1/reviewSubmissions/{id}/items?include=appStoreVersion` (the only API surface that still resolves the linkage) with a stdlib ES256 JWT minted from the `APP_STORE_CONNECT_*` credentials already on the Codemagic machine (kid in the JWT header; DER signature converted to raw r‖s; openssl CLI fallback). **Validated against live App Store Connect today: HTTP 200, and the include-lookup resolves the real submission for version `a3837c3f…` even post-release.**
