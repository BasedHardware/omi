# M-skeleton assumptions

- The lifecycle kernel uses `provisional`, `canonical`, `deferred`, and `rejected` only as bookkeeping states. `defer_review` is a consolidation disposition, while liveness/retraction remains outside this offline experiment.
- `scope_ref` is nullable to represent explicit scope abstention; its non-null value is intentionally opaque and strategy-owned.
- Fixture timestamps and monotonic sequence values are synthetic deterministic test data, not production defaults.
- T7 is an offline placement experiment: it validates an already-supplied batch shape but does not implement the B3 lease, transaction, outbox, or concurrency contract. `defer_review` is bounded by the supplied retry budget and requires a re-resolution trigger.
- T9/T10 provide hermetic composition plus SQLite atomicity only: there is no Postgres adapter or real-concurrency proof. `sha256-canonical-redacted-v1` recursively sorts object keys by JavaScript UTF-16 order, preserves array order, JSON-encodes primitives, rejects undefined and non-finite numbers, and replaces values only for the exact fixed keys `api_key`, `authorization`, `raw`, `raw_text`, `secret`, and `token` with `[REDACTED]`; graph payloads are otherwise already redacted. Entity queries do not fabricate a durable entity filing for a provisional claim.
- D21 sharing slice deferred: the reader≠owner residuals remain known-open. These are unrecognized-label joins restricting a reader (FIX 2), novel policy strings failing closed for non-owners (FIX 3), reader-relative liveness through tree/dogfood as well as project/B5 (FIX 4), and full tree+dogfood two-reader noninterference fixtures (FIX 5). The existing grant and reader-relative foundation is intentionally retained but not extended in this single-owner skeleton.
