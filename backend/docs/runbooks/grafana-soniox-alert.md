The workflow uploads that artifact before the apply step starts. The apply re-reads the target, aborts if its content or resource version changed since the snapshot, sends Grafana's versioned AlertRule API precondition, and verifies the resulting rule by read-back. ## Roll back that apply

Dispatch **Provision Grafana dashboards** on `main` with `environment=prod`, `alert_scope=soniox-alert`, `alert_operation=restore`, `source_run_id=<apply run ID>`, and `source_sha=<full apply SHA>`. This uses the same prod approval and concurrency lock and downloads only that apply's artifact.

The restore tool is dry-run by default. The workflow supplies its explicit apply confirmation only after artifact validation. If the rule was absent before apply, rollback `DELETE`s the Soniox UID with a resource-version precondition and verifies absence. If it existed, rollback `PUT`s the captured resource with the current resource version and verifies it. On production's legacy storage, those preconditions are advisory; the restore checks live content immediately before writing and verifies the final state afterward, but a concurrent UI edit between the read and write can still be overwritten. The goal owner accepts this residual race for this single rule. No other alert UID, dashboard, folder, contact point, or notification policy is written.
