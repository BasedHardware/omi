# Chat voice staged-input custody

SCA-4775 moves chat voice scratch cleanup from URL creation to actual consumer termination. Delayed VAD/download/provider work therefore cannot delete the only staged generation before use. Expected silence and terminal provider failure also schedule cleanup, and SSE cancellation leaves the executor worker in control until it exits. SSE multi-language calls retain their existing `detect_language=False` behavior; REST language detection is unchanged.

Cleanup uses the uploaded GCS generation rather than a path alone. Every cohort stages chat scratch only in `BUCKET_TEMPORAL_SYNC_LOCAL`; regional-cache routing does not move multipart or decoded inputs to `BUCKET_AUDIO_DERIVED`. Account deletion still takes precedence and checks both supported layouts (`/tmp/{uid}_…` and `syncing/{uid}/…`) in the configured temporary and derived buckets. Exact-owner predicates apply to both erasure listing and verification without losing hold or generation checks. Consent and transcript-retention behavior is unchanged.

New uploads carry a per-object `customTime` one day after staging. `deploy/storage-lifecycle/voice-scratch-lifecycle.json` deletes only explicitly stamped objects once their date is reached; unmarked legacy staging never matches. Before promotion, Release must verify that exact scoped backstop with `backend/scripts/check_sync_staging_lifecycle.py --bucket syncing-local --require-voice-scratch-backstop` (adding every explicitly selected chat target). No live backstop is claimed from source alone, and no historical sweep or retroactive deletion is authorized. Soft-delete/versioning and privacy-erasure checks remain prerequisites.

After release, compare only bounded aggregate `omi_voice_transcription_completed_total{route="voice_chat_sse"}` and `omi_voice_transcription_completed_total{route="voice_rest_multipart"}` outcomes and latency on the new serving revision; do not export account, object, transcript or URL data.
