# Explicit reminder Candidate contract

LIFECYCLE: permanent

The existing notes packet may annotate explicit reminders on the desktop staged
path; there is no new model pass, capture loop, speaker assignment or automatic
acceptance. Exact cited turns and the recording clock feed deterministic reminder
validation. `capture_timezone` is source evidence; missing capture-time timezone
retains an unresolved date instead of reading the owner's current timezone.

Date-only `due` keeps `due_at=null`, produces no scheduled notification, and is
rendered all day by the web consumer. The existing Candidate transaction commits
a creation receipt and integration intent on explicit acceptance. Undelivered
intents carry the policy revision so the default-on
`ACTION_ITEM_REMINDER_REDESIGN_ENABLED=false` override can stop new work without
changing existing tasks. See [the contract and release handoff](../../action-item-reminders.md).
