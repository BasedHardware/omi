# Episode wait and empty-member bug repairs

The all-members-complete compose gate, episode boundaries and audio lifecycle are unchanged.

`EPISODE_COMPOSE_SETTLED_TERMINAL_ENABLED` defaults on. Only affirmative STT-terminal empty evidence settles a completed member's transcript wait. The projector validates `silence` or `no_recoverable_speech` before assigning an empty record span; that existing assignment transaction now banks `record_transcription_empty` containing merged empty coverage spans, the projection revision and both pending timestamps. Coverage must span the entire closed audio, without open upload sessions or partial-audio debt. Summary-output exhaustion, a below-floor verdict, an ordinary projection revision and empty text alone never qualify. Registered/untranscribed audio or an incomplete coverage set keeps its normal anchored wait. A registered server-batch row missing legacy pending stamps uses its stable finished/created timestamp as the wait anchor; empty text alone adds no wait. No job lookup, transactional read, STT call, audio mutation or lifecycle transition is added.

Old projectors preserve the unknown receipt and increment `record_projection_revision`, safely invalidating it; changed pending stamps or extended audio bounds also invalidate it. New empty projections discard stale spans after an old-writer revision change. Historical rows without positive STT evidence retain the bounded wait; this change does not invent evidence or backfill production data. Late speech still changes the normal fingerprint/receipt. Off restores the prior transcript-wait decision. Receipt writes stop when both this switch and `HOME_SETTLED_EMPTY_WIRE_ENABLED` are off. No composer-version bump or fleet regeneration.

Every composer host must receive these repairs: backend, backend-integration, backend-sync, backend-sync-backfill and listen/any process starting `main.py`'s local retry task. No GPU image or provider backlog change. All validation is local; integration/rollout/physical Home acceptance belongs to the lead.

## Per-blocker wait cap

`EPISODE_COMPOSE_ANCHORED_WAIT_ENABLED` defaults on. The additive `compose_transcript_wait_observations` map stores `pending_at` and `observed_at` per member. A continuing blocker generation keeps its observation across membership/blocker changes; a new pending stamp receives its own limit. Legacy blockers seed from the existing aggregate wait start. Each member deadline is the earlier of pending+limit and first-observed+limit; the effective wait is the earliest deadline of the currently blocking set. Expired observations survive unrelated receipt clearing so another blocker cannot renew them. Late transcripts and new pending generations are reevaluated normally.

Old images ignore the map and may rewrite/clear legacy aggregate wait fields. New readers cap those fields using the per-member observations, so old membership resets cannot extend an already-observed blocker. A stale observation for a replaced pending generation can cause an early reevaluation, but the member read refreshes its full independent deadline before any model call. The cap is fleet-wide only after every old composer replica is drained. Off ignores the map and restores aggregate-start reset behavior. The existing transcript-wait enable switch and 1,200-second limit remain authoritative. No new index or production migration.

## Empty-live membership cleanup

`EPISODE_EMPTY_MEMBER_CLEANUP_ENABLED` defaults on. The existing guarded empty-live transaction now reads the linked episode(s) before its first write, then removes the deleted stub from standard membership arrays and per-member maps, deletes its reverse link, invalidates partition proof and advances the episode version/topology fence atomically with the existing session tombstone and conversation deletion. If a stale conversation owner differs from the authoritative reverse link, both referenced memberships are cleaned. Bounds, notes, audio custody and capture status rules are untouched. Registered `audio_files` additionally refuse this cleanup; existing content/server-batch audio guards remain. No recording with registered audio is eligible under this switch.

Home projection supplies a private read-only absent-ID observation to the wait comparison. Legacy dangling references therefore do not repeatedly defeat stored-wait suppression merely because the wire omits them. A removed actual blocker still gets one reevaluation; its stale transcript wait can be cleared once all stored blockers were observed, even if an active member still deliberately holds composition. Missing members already stay out of composer counts/fingerprints and wire IDs. A genuinely uncomposed active episode remains eligible for the existing recovery attempts; this is deliberate behavior, not a claim that it now composes.

Old images understand the standard membership removal and reverse-link deletion and ignore the private read marker (not stored or sent). Transactional episode/fence reads conflict with concurrent attachment; state_version fences old composer writes. Off restores the prior cleanup transaction and mismatch comparison. No historical data repair, index or production access.
