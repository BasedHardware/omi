# Episode wait and empty-member bug repairs

The all-members-complete compose gate, episode boundaries and audio lifecycle are unchanged.

`EPISODE_COMPOSE_SETTLED_TERMINAL_ENABLED` defaults on. Only affirmative STT-terminal empty evidence settles a completed member's transcript wait. The projector validates `silence` or `no_recoverable_speech` before assigning an empty record span; that existing assignment transaction now banks `record_transcription_empty` containing merged empty coverage spans, the projection revision and both pending timestamps. Coverage must span the entire closed audio, without open upload sessions or partial-audio debt. Summary-output exhaustion, a below-floor verdict, an ordinary projection revision and empty text alone never qualify. Registered/untranscribed audio or an incomplete coverage set keeps its normal anchored wait. Registered server-batch work missing legacy pending stamps receives a first-observed cap when both wait repairs are on; capture age cannot expire a newly observed upload. Repeated reads cannot move that cap. Turning either repair off restores the old unstamped decision; empty text alone adds no wait. No job lookup, transactional read, STT call, audio mutation or lifecycle transition is added.

Old projectors preserve the unknown receipt and increment `record_projection_revision`, safely invalidating it; changed pending stamps or extended audio bounds also invalidate it. New empty projections discard stale spans after an old-writer revision change. Historical rows without positive STT evidence retain the bounded wait; this change does not invent evidence or backfill production data. Late speech still changes the normal fingerprint/receipt. Off restores the prior transcript-wait decision. Receipt writes stop when both this switch and `HOME_SETTLED_EMPTY_WIRE_ENABLED` are off. No composer-version bump or fleet regeneration.

Every composer host must receive these repairs: backend, backend-integration, backend-sync, backend-sync-backfill and listen/any process starting `main.py`'s local retry task. No GPU image or provider backlog change. All validation is local; integration/rollout/physical Home acceptance belongs to the lead.

## Per-blocker wait cap

`EPISODE_COMPOSE_ANCHORED_WAIT_ENABLED` defaults on. The additive `compose_transcript_wait_observations` map stores `pending_at` and `observed_at` per member. A continuing blocker generation keeps its observation across membership/blocker changes; a new pending stamp receives its own limit. Legacy blockers seed from the existing aggregate wait start. Each member deadline is the earlier of pending+limit and first-observed+limit; the effective wait is the earliest deadline of the currently blocking set. Expired observations survive unrelated receipt clearing so another blocker cannot renew them. Late transcripts and new pending generations are reevaluated normally.

Old images ignore the map and may rewrite/clear legacy aggregate wait fields. New readers cap those fields using the per-member observations, so old membership resets cannot extend an already-observed blocker. A stale observation for a replaced pending generation can cause an early reevaluation, but the member read refreshes its full independent deadline before any model call. The cap is fleet-wide only after every old composer replica is drained. Off ignores the map and restores aggregate-start reset behavior. The existing transcript-wait enable switch and 1,200-second limit remain authoritative. No new index or production migration.

## Empty-live membership cleanup

`EPISODE_EMPTY_MEMBER_CLEANUP_ENABLED` defaults off. Only explicit true opts into the following transactional detachment. The existing guarded empty-live transaction now reads the linked episode(s) before its first write, then removes the deleted stub from standard membership arrays and per-member maps, deletes its reverse link, invalidates partition proof and advances the episode version/topology fence atomically with the existing session tombstone and conversation deletion. If a stale conversation owner differs from the authoritative reverse link, both referenced memberships are cleaned. Bounds, notes, audio custody and capture status rules are untouched. Registered `audio_files` additionally refuse this cleanup; existing content/server-batch audio guards remain. No recording with registered audio is eligible under this switch.

Home projection supplies a private read-only absent-ID observation to the wait comparison. Legacy dangling references therefore do not repeatedly defeat stored-wait suppression merely because the wire omits them. A removed actual blocker still gets one reevaluation; its stale transcript wait can be cleared once all stored blockers were observed, even if an active member still deliberately holds composition. Missing members already stay out of composer counts/fingerprints and wire IDs. A genuinely uncomposed active episode remains eligible for the existing recovery attempts; this is deliberate behavior, not a claim that it now composes.

Old images understand the standard membership removal and reverse-link deletion and ignore the private read marker (not stored or sent). Transactional episode/fence reads conflict with concurrent attachment; state_version fences old composer writes. Off restores the prior episode-reference cleanup transaction. Dangling-ID read tolerance, membership acknowledgement and registered-audio protection remain active independently of this switch. No historical data repair, index or production access.

## Transactional cleanup ramp (quality-lead ruling)

The three wait/wire repairs remain default on. Only the extra episode/fence/reverse-link mutation during empty-live deletion is default off, in code and all six dev/prod hosts. This boolean has no account cohort. The quality lead owns an explicit 1% then 100% cleanup-serving traffic ramp, completed within 48 hours after this image serves on both listen and pusher. Use canary revisions/worker pools with the flag true and route 1% of cleanup-serving traffic to them; all other replicas stay false. A single pod is not a 1% cohort unless measured routing establishes that share. If the deployment cannot route that share, keep it off and have the quality lead establish the canary before expanding. Expand only after a clean observation window at 1%; rollback false on the canary at the first attach-contention regression. Existing authorization still belongs to the release lead; this PR performs no rollout.

There is no dedicated attach-abort metric. Existing attach failure logs are `event=episode_attach outcome=error exception_type=Aborted` (utils/episodes/service.py), `event=episode_sync_intake_attach outcome=error exception_type=Aborted` (finalize.py/service.py), and `event=episode_batch_audio_close_attach exception_type=Aborted` / `event=episode_batch_admission_attach exception_type=Aborted` (batch_close.py). On the canary versus control release identities, filter Cloud Logging with `SEARCH("episode_attach") OR SEARCH("episode_sync_intake_attach") OR SEARCH("episode_batch_audio_close_attach") OR SEARCH("episode_batch_admission_attach")`, combined with `SEARCH("Aborted") OR SEARCH("409") OR SEARCH("Lock timeout")`. Also watch the broader existing `Firestore transaction retryable, restarting` and `Firestore transaction expired, restarting` logs from database/_client.py for retries recovered before an attach failure is logged; these lack an operation label and cannot alone identify the attach path. Keep attach abort/409/lock-timeout counts and the broader retry rate clean relative to matched control traffic. No new telemetry series is claimed.

The loopback emulator regression runs a one-second stub's real cleanup concurrently with the next real attachment to the same episode, with this switch explicitly on and off. Both must preserve the next member and complete inside the existing three fresh transactions / five SDK commit attempts per transaction. The test adds no production retries or timing settings. A passing two-writer regression is functional evidence, not proof of a safe fleet contention rate.
