# Soniox v6 adoption

The existing live client defaults to `stt-rt-v6` and the existing async adapter
uses `stt-async-v6`. Provider routing and admission are unchanged. The
[ordered-finalize contract](../../listen_pusher_pipeline.mdx) admits both v6 and
v5 under its existing opt-in switches, endpoint and 16 kHz PCM restrictions.

Soniox's [November 3 changelog](https://docs.soniox.com/stt/models) declares v6
API-compatible. It changes currency and alphanumeric text formatting; Omi passes
that text through. Token fields, API URLs, finalize/keepalive controls and typed
rejections retain their existing API contracts. No SDK change is needed: these
adapters use WebSocket and HTTP directly.

Rollback live with `SONIOX_MODEL=stt-rt-v5` and restart the process; this restores
the prior clock selection as well. Batch rollback is one edit to
`SONIOX_HELD_RECOVERY_MODEL` in `config/prerecorded_stt.py`. Soniox says v5 IDs
will automatically route to v6 after December 15, 2026, so rollback cannot pin
old provider behavior beyond that date.

The v5-measured 120 ms finalize quantum is not live-probed on v6. The ordered
clock remains opt-in, and mismatched progress invalidates capture placement.
Official v6 examples retain mono `pcm_s16le` at 16 kHz. No live vendor smoke or
latency comparison was run; no confirmed dev key was available. Rate cards are
unchanged: public streaming pricing remains approximately $0.12/hour (async
approximately $0.10/hour), with token-based billing described on the
[pricing page](https://soniox.com/pricing), checked November 10, 2026.

Separately, Soniox has [deprecated start-message API key authentication](https://docs.soniox.com/authentication/migrate-websocket-authentication)
from January 15, 2027. It still works for v6 today; migrating authentication and
its connection-timeout semantics is outside this model adoption.
