# Sync utilities

This package owns uploaded-audio sync admission, decoding, transcription orchestration, persistence fencing, and playback reconstruction.

## Boundaries

- `pipeline.py` coordinates job/run leases, segment processing, persistence fences, and terminal outcomes. `assignment_errors.py` distinguishes terminal user authority from corrupt/mismatched intake.
- `files.py`, `content_id.py`, and `capture_manifest.py` normalize uploads and identities. `input_limits.py` bounds historical batches before custody transfer and each worker attempt, including codec expansion and retryable tmpfs pressure. Capture assignment never grants fresh-lane provenance.
- `capture.py` derives retry-stable incoming IDs from the VAD-segment timestamp. VAD exports speech segments only; empty VAD/STT creates no conversation or bridge and bills no speech.
- `lanes.py`, `backfill.py`, and `rate_limit.py` classify work and enforce admission policy. `uid_sequencer.py` dispatches accepted backfill jobs through the Firestore owner/pending registry in `database/sync_backfill_sequencer.py`; it owns no STT or conversation writes. See `backend/docs/runbooks/sync-two-lane.md` for lease, cutover, and monitoring details.
- `merge_audio.py` and `merge_dedupe.py` contain deterministic merge helpers; `playback.py` reconstructs audio artifacts.
- `provenance.py` and `telemetry.py` provide bounded attribution and operational labels.
- `recording_lineage.py` (default) and `recording_session_target.py` (kill-switch path) choose explicit live targets for safety-WAL uploads that carry a recording id; they only read, and intake stays in `assignment.py`.

Keep HTTP routing and database implementations outside this package. Changes must preserve run-lease, durable result, and conversation-persistence fences in `pipeline.py`.

## Capture assignment

The capture refactor's `CAPTURE_COVERAGE_MODE` defaults to shadow. Its committed
source-frame ledger and shared bridge/incoming dedupe live in
[`../capture/`](../capture/README.md). Serve checks WAL/batch audio before STT,
keeps only proven uncovered frame ranges, and records surviving transcript
frame interiors after assignment. Shadow retains the legacy paths described
below and reports would-skip audio and dedupe disagreements. Known capture
positions never use speaker labels or wall time as coverage evidence.

**Hard serve-ramp gate (lead ruling):** CAPTURE_COVERAGE_MODE must not move from shadow to serve unless capture-proven drops (incoming and donor) require the lexical novelty/protected-token checks: #23811 and this PR both serving.
This also applies to a serve cohort configured while the mode is shadow.
Capture proof qualifies transcript segments for the Residual overlap lexical
checks below; it never bypasses them, including through the fuzzy fallback.
There is no capture-coverage startup/configuration guard; this cross-PR release
prerequisite is documented here and in the flag registry rather than inferred
from the generic mode parser.

Serve can bind a ledger-derived same-key owner and accepts discovered open
same-key live rows before their first transcript. The database discovery layer
still needs the integration change described in the L1 report for unledgered
open rows without device metadata; assignment itself revalidates each hint.

The 2026-09-19 incident was **sync adopting live-flap stubs**: failed live STT caused reconnects about every 35 seconds, creating empty conversations with near-zero extent. The legacy timestamp lookup chose a different nearest stub for each 60-second WAL, even within an ordered job. The observed jobs were legacy backfill without explicit targets or turnstile timeouts. Cross-job lookup/create races addressed by #15106 are a separate, older class.

`lifecycle.ingest_sync_conversation` admits uploads through `database.conversations.assign_sync_conversation`. `assignment.py` computes connected capture components in one Firestore transaction, using codecs supplied by the database adapter. Every transactional read precedes writes. Decode/storage errors propagate; there is no uncoordinated create fallback.

`assignment_index.py` stores metadata-only UTC day buckets under `users/{uid}/sync_assignment`. Every occupied day indexes the component. Buckets do not evict entries; Firestore size limits fail visibly. The old `recent` document remains a bounded migration hint and serialization fence, alongside the legacy timestamp-query hint. Pre-index history is not comprehensively backfilled. `_OrderedTurnstile` reduces bridge work within a job; correctness does not depend on it.

`models/conversation_continuity.py` owns the gap predicate: an uncovered gap **at least 120 seconds** splits. Both paths measure speech silence. Sync uses the VAD-segment origin through the last word end, exactly as before; no quiet-file coverage expands that interval. Source, device ID, lock state and an estimated-clock run (`utils/sync/clock_run.py`: a `_clke<run>_` filename token the app sets when it had to estimate the recording time) form disjoint partitions; untagged rows are one device-clocked partition. Any retained `sync_capture_id` is provenance only; an explicit existing target is authoritative independently of temporal assignment, except an unproven literal `stamp_fallback` rejected by the extent guard below. Missing device ID is its own partition, never a wildcard joining two known devices. Every provenance-compatible, non-deleted authoritative explicit target retains its ID, including an empty live record or an existing sync row. Fresh admission can verify server capture proof before any live transcript exists; emptiness is not evidence to reject that target. Missing or tombstoned explicit targets use ordinary temporal assignment, subject to independent retry-lineage deletion fences. Ordinary near-time hints never adopt live stubs. With `SYNC_LIVE_OVERLAP_ENABLED` (default on), a separate bounded metadata query discovers strictly overlapping live rows with content from the same known device, source and lock partition, in completed or in-progress state. The assignment transaction rechecks every candidate and uses the greatest overlap as its target. It retains the live identity and the existing transcript, relevance, revision and speaker merge semantics. Other live identities are never donated. Explicit targets retain priority. Set the env to `false` to restore the prior admission path. Discovery failure publishes through ordinary sync intake immediately; a full live document uses the existing size-rollover path. No hidden donor or pending-merge queue is introduced, so neither failure needs a later upload or cleanup scheduler to make retained speech visible. Commit/storage failures remain retryable rather than bypassing persistence fences. Explicit live targets acquire `sync_live_target` and remain excluded from automatic bridges after sync adds content and revisions. Shared, photo-bearing or user-curated sync rows also stay intact; they cannot donate content or change identity automatically.

A live conversation folded into its predecessor by smart merge (`utils/conversations/smart_merge.py`) is a redirect tombstone marked `smart_merge.role=donor`. An explicit target that is such a donor resolves through `sync_merged_into` to its survivor, which then acts as the explicit live target (text-deduplicated repair audio, no temporal re-creation of the donor); a deleted survivor supersedes the chunk. Sync bridge donors keep the temporal fallback.

Without an authoritative explicit target, when matches exist the survivor is the existing row with earliest `started_at`, then smallest ID on a tie. Incoming chunk IDs create records only when nothing matches. Ordinary append keeps its visible ID; genuine bridges retain redirect tombstones. For unattended temporal intake, partition and absolute content converge across permutations, not the survivor ID. Explicit targets retain their ID and lifecycle authority; user-deleted targets are never reused. This does not authenticate client provenance. Transcript ranges remain absolute through rebasing; `finished_at` is the last word end; the existing duration helper controls displayed speech duration.

Bridge writes increment survivor and donor `sync_content_revision`. Processors reject deleted rows and stale revisions. `sync_merged_from` persists ancestry with the transcript, so `bridge.py` can replay external effects after a failed attempt. The only completion call is after segment audio persistence in `process_segment`; transactional lifecycle intake has no external cleanup. It calls the public `retract_sync_bridge_source` and `copy_sync_bridge_audio` seams in `merge_conversations.py`; those fix retention and strict-copy policy while keeping the general merge/delete machinery private. `database/sync_bridges.py` checkpoints `sync_bridge_cleaned_revision` on each tombstone with a revision compare-and-set, and later appends skip completed retraction. `sync_bridge_audio_target` tracks the copy destination: later bridges and late donor audio copy without repeating completed retraction. Donor retraction does not take the exclusive per-account destructive gate; if that gate is already held, retraction is deferred (logged `event=sync_bridge outcome=deferred`) and retried on the next append via the missing receipt. Copy and checkpoint failures still propagate to the job retry path; concurrent attempts may repeat effects until a receipt commits. Original audio and donor tombstones remain while uploads can finish; user/source deletion purges retained sources through `delete_conversation_with_sync_sources`, called by the deletion service and developer delete endpoint; the raw database hard-delete primitive does no external orchestration. In-flight donor audio is recopied when its worker finishes; the previous copy receipt is cleared first, so failed late copying remains pending on retry without a transient source hint. There is no independent cleanup scheduler: recovery depends on a retried job or later intake. Search-index writes retain their existing best-effort semantics.

## Recording lineage binding

One phone recording (the client id R that the phone sends as `client_conversation_id` and on every WAL) becomes one live row per silence rollover, each with its own server recording id. With `SYNC_LINEAGE_RESOLVE_ENABLED` on (default; unset means on, any unrecognized value means off), `/v4/listen` stamps every generation with `external_data.recording_origin_id = R`, and an upload that carries R plus audio bounds is bound per VAD segment, after VAD, by `recording_lineage.py`. One bounded, indexed read (`conversations_recording_lineage`: R, `started_at <= latest segment end + 5 s` and `finished_at >= earliest segment start`, ordered by start and finish descending, at most 9 documents) returns the recording's generations projected to the routing field paths — metadata only, widened to include each row's `capture_evidence` envelope only when the frame-ownership tiebreak below could decide (the same read window and document ceiling, just a wider selection); generations created before the stamp are found only through the row bound to R itself (same projection, at most 6 more documents, read only when that row is absent from an untruncated window). A segment binds when the strict pass yields one canonical generation; canonical uniqueness still wins first and the chosen row resolves through the same donor-redirect path. When several strict generations carry distinct canonicals and the dedupe gate admits the uid, the tiebreak runs in a fixed order over that pass's matches. First, visibility: a row that IS its canonical — present, not deleted and not discarded — proves its canonical has a live surface competing for the segment, while a discarded rollover, a deleted donor redirect or a canonical id absent from the matches proves nothing; when any visible covering canonical exists the eligible set narrows to the rows canonicalizing to those canonicals, so a hidden stamp can never outvote a visible covering row. Second, the phone's stamp picks one eligible canonical exactly as before. Third, frame ownership: `lineage_frame_evidence.py` admits exactly one eligible canonical whose stored live `capture_evidence` yields a validated committed run (`committed_coverage.py`'s shared envelope/lifetime checks, applied to all eligible envelopes together so a competing same-root lifetime abstains the decision) that covers the segment's decoded source-frame coordinates — partial frames at the endpoints included — or exactly adjoins them (the run ends at the segment's first frame or starts at its last; any frame gap or mere overlap abstains), with the run's receipt-wall anchors independently reproducing both segment endpoints within 2 s. Adjacency is ownership evidence, not suppression: the adjoining segment is still transcribed and saved. The decoded per-segment source maps that already flow decode→coverage→VAD are the map input; the planner stays pure and the resolver requests the `include_capture_evidence` projection only when the gate admits, a nonempty map exists. A claim alone authorizes nothing; malformed, receipt-only, conflicting or multi-supported evidence all return no answer rather than raising into the fail-open path. Fourth, exactly one visible canonical wins regardless of absent or non-deciding evidence. Anything else keeps no target and the `ambiguous_pending` token, is rechecked against a fresh lineage read at most three times per plan, then defers through the existing retryable `sync_persistence_failed` failed-segment path rather than guessing a row. When no visible covering canonical exists the eligible set is the whole match, so a discarded-only unique canonical or compatible stamp keeps the pre-tiebreak behavior. With the gate off the overlap is an ordinary interval miss and the stamp or temporal fallback applies; the permanent S1 claim requirement still admits only uploads carrying complete per-file claims — a claimless upload takes the pre-existing whole-batch resolver path rather than any newly fail-closed per-segment outcome — while an admitted segment whose decoded map or stored evidence is missing, malformed or non-deciding simply gets no frame-ownership vote: two visible covering canonicals stay pending and a lone visible canonical now wins. Failing that, the `recording_session_target` allowance applies (the segment must overlap the generation, may start 5 s before it and end 60 s after its last word). Source, device and lock state must match. Smart-merge donors stay in the lineage and canonicalize to their survivor; when only the donor is visible, intake follows its redirect and a deleted survivor supersedes the audio. Every potentially overlapping row is considered, including an old survivor or stamp-extended row. A truncated overlap set proves no target; the whole plan falls back rather than assuming older rows cannot overlap. Zero, negative or non-finite audio spans also prove no target. The document-read ceiling is 16 (typically a few overlapping generations plus the legacy origin lookup); multi-range index-entry reads are billed separately and have no measured ceiling here. When a clean lookup — not degraded, failed or truncated — returns zero rows and the live-dedupe gate admits the uid, one extra metadata-only document read addressed by the recording id itself runs once and classifies that exact row as `missing`, `unstamped`, `source`, `device`, `lock`, `deleted`, `interval` or `compatible` (`id_probe`); it never joins the targets, changes fallback or recreates anything, and `missing` only proves absence at read time, not whether the row raced the index or was never written. With the dedupe switch off or the uid outside the cohort the probe never runs and the resolve line keeps the pre-diagnostics field set, restoring main reads and log bytes exactly.

A bound segment is an explicit target through the existing `assign_in_transaction` path, so live-target dedupe, identity retention, `sync_live_target` and user-managed protections are unchanged. A unique generation different from the phone's stamp overrides it. Without a unique generation the segment keeps the stamp subject to the transactional extent guard below (otherwise the pre-#19424 behavior) or, when unstamped, stays on temporal assignment, which never adopts live rows — except a strict multi-canonical overlap under the gate, which keeps no target and the pending token instead of guessing, and a key once proven pending stays pending across the plan's rechecks unless a later pass binds it. The plan is a pure function of rows, segment spans, stamp and the decoded per-segment source maps; retries skip landed segments through the processed-segment ledgers and bind the rest the same way against the same rows. If the lineage query fails (for example while its composite index is still building), the origin-row read still runs, so binding degrades to the whole-batch resolver's candidate set, per segment (`window=origin_row_only`). Any other lookup or planning error, including span construction or executor failure at the coordinator boundary, falls back to the stamp or temporal path and never fails the job. Each decision emits `omi_sync_lineage_resolve_total{outcome}` and one `event=sync_lineage_resolve` log line with segment counts and no ids; outcomes are `bound`, `split_across_generations`, `stamp_overridden`, `stamp_fallback`, `no_rows`, `truncated`, `interval_miss`, `lookup_failed`, `disabled`, `not_allowlisted`. When the live-dedupe gate admits the uid the line also carries per-binding counts and stage counts over the returned candidates only — `candidates`, `accepted`, `dropped_invalid|unstamped|deleted|source|device|lock|interval` and `unstamped_origin`, each capped at 16 at emission while the plan keeps truthful totals; these are not the recording's total inventory, and a degraded, failed or truncated lookup leaves the cause unknown. Off, the whole batch resolves as before: only a row whose recording id is R, containing the whole upload, binds, and a miss drops the stamp.

With the flag on, sync enrichment defers while an explicit live target is `in_progress`, so SYNC_UPDATE cannot prematurely complete an open recording. Finalization processes it once live closes. A fresh live speech write to a sync-enriched target advances `sync_content_revision` atomically with the changed transcript; a processor that read earlier is fenced. An unchanged live retry leaves the revision intact. Sync intake also preserves a live row's durable `audio_timeline` first-audio origin: rebasing it for an early WAL would shift later live offsets. Buffered speech before that pin keeps its exact negative relative timestamp and is marked `audio_alignment=unplaced`, because released clients cannot seek negative v2 offsets; its text is retained. Completed targets still reprocess per finishing job. On retry, durable append receipts restore pending enrichment even when every landed segment is skipped, excluding fenced targets and retaining the stored conversation language. Retries can repeat enrichment; this is not an exactly-once LLM guarantee. OFF leaves these prior lifecycle behaviors intact.

### Staged rollout (uid allowlist)

`SYNC_LINEAGE_RESOLVE_UID_ALLOWLIST` (comma-separated uids, whitespace-trimmed; empty or unset admits every user) gates the per-segment binding request by the owning uid (`lineage_resolution_requested`, independent durable refresh debt survives later narrowing). The gate is `config/sync_lineage.sync_lineage_resolve_active_for`: the kill switch wins, then the list. For a uid outside a non-empty list binding behaves exactly as with the kill switch off. Live-target origin pinning in `assign_in_transaction` and live `sync_content_revision` advances in `database/conversations.update_conversation_segments` are unconditional: once sync and live share a row, cached live offsets and late finals must stay safe even without `audio_timeline` or lineage admission. Open-live enrichment always defers to live finalization. The `/v4/listen` origin stamp is metadata only and stays under the kill switch alone, so widening later finds lineage already stamped. An eligible upload refused by the list records `outcome=not_allowlisted` on the metric and log line with `job_ref=none` (no uid, job or conversation id).

Per-segment binding always requires a complete validated S1 claim set for the exact uploaded basename set, checked through `parse_sync_file_claims` after lineage kill-switch and cohort admission. The HTTP router passes upload `filenames` and parsed claims into batch intake; `with_context` freezes both in the authenticated staged WAV and projection uses those same names after queue delivery. Optional `raw_capture_paths` are storage references, may be empty by consent/policy or digest-named, and never define the claim basename set when `filenames` is present. Pre-deploy queued contexts lacking that field alone retain the former archive-basename check during drain; a present empty or null field never borrows archive names. Duplicate same-name upload parts remain fail-closed as `count_mismatch`. Revalidation calls the same parsed-structure validator as the HTTP parser, without serializing again or reapplying the 4096-byte wire limit to canonicalized metadata. This admits both a 3996-byte compact header previously inflated by whitespace and a 4041-byte short-UUID header that canonicalizes to 4101 bytes; the wire limit remains enforced at HTTP intake. The S1 requirement and capture-evidence producer flags graduated on 2026-10-20; neither cohort admission nor the lineage kill switch was widened. An absent, invalid, incomplete, wrong-filename or otherwise malformed claim set returns false and the upload takes the pre-lineage whole-batch resolver — even for admitted users and with an empty allowlist. Each refused validation check emits one bounded `s1_refused` outcome on `OMI_SYNC_LINEAGE_RESOLVE_TOTAL` and one log line with a closed reason (`no_claims`, `parse_failed`, `count_mismatch`, `filename_mismatch`, `not_admitted`), stage (`http_boundary`, `intake`, `batch_projection`, `coordinator`), `job_ref=none`, and no ids, filenames, roots or claim content. A supplied invalid HTTP header reports `parse_failed` at `http_boundary`; absent headers are quiet there. The queued empty mapping may subsequently report `no_claims` at intake or projection: these count checks, including per-part evaluations and retries, not unique uploads. Only `count_mismatch` carries claim/file count buckets `0|1|2_5|6_10|11_20|gt_20` (unavailable is `none`); other reasons carry `none`. The metric uses the same stage and count labels; non-refusal outcomes use `none` for all three. After decode and coverage, a coordinator check disables lineage and resolves the same whole-batch target when the observed source-position mapping count differs from the surviving WAV set, emitting `count_mismatch` with those two counts bucketed once before that resolution; valid decoded prefixes still count as observed mappings, and a fully committed suppression leaves no segments to bind. No new policy runs inside `process_segment`, so direct legacy callers keep the old contract.

The gate uses the service env and the row's owning uid; the env is fixed per revision/pod. Landed segments stay skipped, and a changed allowlist controls only the remaining appends. An admitted append checkpoints `lineage_enrichment_pending` before its processed-segment marker, in both the job and durable content receipts. Narrowing the list or turning the kill switch off must still finish that existing refresh debt for a completed row, using its stored language, without reappending audio. Fenced targets are excluded. A retry refresh of an open live row still defers to live finalization even after narrowing. This is completion of an already admitted effect, not a pinned permission for new appends; untouched refused owners retain the exact OFF outcome. Pre-marker receipts restore under an admitted attempt only. Widening may put remaining segments on different rows, but never rebinds landed speech. Avoid changing membership while a user's live recording or retry job is running: mixed revisions can disagree on binding (and older code can disagree on origin and revision fencing). Drain first when narrowing; disabling does not undo doubled speech.

Invalid timing or observation failure reports incomplete/unknown; numeric zeros on such a line do not establish absence. Retained donor timing is compared with the pre-bridge live speech union; overlap is a triage alarm, never deletion proof. Observed retained overlap wins even when measurement is incomplete; complete measured absence is clear, everything else is unknown. `incomplete_reason` is closed: `none|target_sync|segment_cap|receipt_cap|unsupported_content|invalid_timing|observation_error`. Sync-only transfers cannot certify live clearance. Failed or aborted transaction attempts, unchanged ancestry and receipt-only cleanup emit none; telemetry failures never abort persistence. Bridge observations have their own denominator: exclude them from resolver decision/truncation and new-row assignment denominators. Require actual bridge observations before widening, and restart the watch after deployment. Rollback: `SYNC_LINEAGE_LIVE_DEDUPE_ENABLED=false` or revert; neither repairs historical transcripts.

For a complete watch over the same admitted cohort and time window, let A be the committed fresh live-append `event=sync_lineage_append` lines and B the committed donor-transfer `event=sync_lineage_resolve stage=bridge target_kind=live` lines. Compute the doubled-speech numerator N as `sum(A.appended_seconds_overlapping_live) + sum(B.donor_seconds_retained_overlapping_live)` and the retained-speech denominator D as `sum(A.appended_seconds) + sum(B.donor_seconds_retained)`. The gate is `N / D <= 0.10`, with D > 0; D = 0 is unmeasured. The append line's `appended_seconds_overlapping_live` uses the same eligible-live timing union and is rounded to 0.1 s, or `unknown` when timing is invalid or the measurement is absent. `appended_seconds` retains its existing 0.01 s precision. `donor_seconds_in` and `donor_seconds_dropped` audit the input/retained partition; neither dropped speech nor `dropped_as_repeat_seconds` enters N or D. Repeat-only acknowledgments contribute zero; receipt replay contributes no new transfer. A bridge's fresh triggering intake belongs only in A, and its stored donor speech only in B. Count each source contribution once on entry into live; if ancestry shows a contribution already counted in A or an earlier live transfer, reconcile it rather than summing it again. Sync-only transfers and bridge cleanup logs are outside this live-transfer ratio. Missing/older append fields, incomplete bridge measurements (including an overlap line with a non-`none` reason), lost lines or unreconciled revision counts make the watch unknown and block widening; do not silently omit them from the sums. Reconcile with conversation revision metadata when counts look short, including paths that emitted no append line. Unresolved retained overlap still requires triage even when the aggregate is below 10%. Account for per-line rounding uncertainty before certifying a ratio at the threshold.

Residual overlap: a WAL is uploaded whole when any frame missed the socket, so bound segments repeat speech live already transcribed. With `SYNC_LINEAGE_LIVE_DEDUPE_ENABLED` on (unset means on, any unrecognized value means off, and the lineage uid allowlist still gates it), fresh intake first asks `capture_repeat_evidence.py` which incoming segments carry independent capture proof: each segment's own `sync_vad` receipt must uniquely identify a nonempty source-frame span (unique within the intake — a duplicated incoming or receipt id proves neither side), and the canonical live row's `origin=live` S1 snapshot must positively cover every touched frame for the same capture root, clock epoch, mono channel and rate, with valid endpoint sample offsets and `conflicts=0`; missing, malformed, partial or mismatched evidence yields no proof. On that incoming path only a capture-proven segment may drop, and only when its normalized tokens (NFKC, casefolded, punctuation-neutral) fit, multiplicity-included and minus a fixed filler set, inside one contiguous window of one to three chronologically adjacent live segments (gaps at most 15 s): difflib ordered-token matches must cover at least 85% of incoming and 75% of window tokens, at least two distinct shared trigrams are required, the duration ratio must sit inside 0.5-2.0, and the midpoints must be within 1800 s of each other. Live windows resolve on `audio_capture_start/end` or, for the v2 pinned timeline, the pinned origin plus offsets; otherwise `started_at` plus offsets, and WAL timestamps are never rewritten from text. An incoming repeat never drops on time coverage alone — and never on lexical match alone: an unproven segment, even an identical second utterance, is legitimate repetition and is kept before any candidate work. Protected tokens (negations, correction cues and any token containing a digit) must match the window exactly, and every other substantive incoming token must be counter-included, so novel words, numbers, negation changes and correction markers keep the whole segment; filler differences are tolerated. The pass abstains conservatively: with no verified indices, or more than 4096 stored live segments, nothing is scanned or tokenized; a midpoint-sorted live index is built once and bisected to the ±1800 s neighborhood, and a neighborhood over 128 candidates keeps the segment before any candidate sort or tokenization. After lexical coverage a safe exact-retry pass drops only identical normalized text at an identical absolute range or segment id — and only for a capture-proven segment or one sharing a nonempty `sync:` speaker scope with the stored line; exact retries against unproven live text, ranges or bare ids are kept, and a canonical row over 4096 stored segments returns every incoming segment unchanged rather than suppressing against a truncated pool. An upload whose survivors are all repeats acknowledges with no writes, index changes, donor tombstones or revision bump — an overlapping donor never forces consolidation or rollover of an all-repeat intake; enrichment is suppressed unless the dropped speech was a canonical sync-scoped exact retry — that intake completes previously admitted work (`existing_completion=True` on the append line, the owed debt enrolled, finish invoked without new audio), while pristine live repeats and `sync_merged_from` ancestry alone invent no debt; explicitly owed `_merged` debt remains. Failure modes: paraphrase or synonym rewording misses the lexical match and stays doubled, a legitimately repeated long phrase can drop in error, and there is no guarantee production lands under the 10% goal above. Strict-overlap ambiguity still keeps no target and the `ambiguous_pending` token rather than guessing a row unless the ordered tiebreak decides it — a compatible stamp among visible covering canonicals, then uniquely proven frame ownership, then a single visible canonical — and the listen side never clamps `started_at`, a spec divergence from the pinned `audio_timeline` origin. Literal stamp fallback has no interval proof. Before writing, assignment compares the planned explicit live target's date extent to its transactionally reread extent. Growth greater than 300 s refuses that fallback regardless of survivor count. With retained new speech it excludes that live row and replans through ordinary unstamped temporal assignment. For a lineage-eligible intake, the read-only guard first requests discovery from the database adapter. Outside the transaction, the adapter runs the same bounded indexed metadata query as untargeted intake (at most 128 rows, no plaintext), with completeness diagnostics, once per assignment call. It then restarts the transaction, rechecking the explicit target, retry/deletion and caller fences. Discovery on the reroute is observation-only: the transaction rereads every candidate for contention and the conservative gate-3 observation, but candidate ids never become targets on this path. The refused live row is excluded, and ordinary unstamped temporal assignment creates a new sync row or appends to a neighbouring sync row; no live row is adopted or has its extent changed by the reroute. Failed or capped discovery remains incomplete. Targets that keep their target and repeat-only acknowledgments incur no discovery query. Non-lineage intake retains its prior routing. With no retained speech it acknowledges a repeat-only no-op against the existing retry owner, otherwise the live target, without committing the widened plan or performing an empty replan: live and already landed sync rows and indexes stay untouched, including donors drawn into the pre-dedupe extent. No fallback can stretch the live row merely because dedupe removed its incoming lines. Exactly 300 s or less is unchanged. Interval-bound targets, explicit non-fallback targets, repeat-only no-ops, redirect/deletion authority and landed-speech retry fences retain their existing behavior; already stored speech is never rebound. The guard ships on without a new flag and is independent of the lexical-dedupe switch. A successful reroute emits `event=sync_lineage_stamp_append outcome=stamp_gap_refused span_delta_bucket=0` plus shared policy fallback telemetry after assignment; the marker is transient and never persisted. Rollback is revert. After deploy start a fresh 48 h David-only watch with the seven-day gates above; this change does not widen the cohort or rewrite historical extents. Telemetry is content-free: `event=sync_lineage_append` carries `span_delta_bucket`, the chosen row's date-extent growth bucketed `none|0|0_60|60_300|gt_300|unknown` — a repeat-only no-op reports `0`, and a size rollover onto a new sync row is never attributed to live stretch; `event=sync_lineage_stamp_append` marks stamp-fallback live appends while the gate is on. With dedupe off the intake writes no dedupe markers and emits neither append-growth line; stamp-gap refusal telemetry remains independent of that switch. Historical captures, clock-offset calibration, uploads that bind to no row and exactly-once enrichment are not solved here.

Frame-level audio coverage: lexical dedupe can only drop repeats a VAD segment still carries, so WALs that mostly repeat live speech still pay full STT. With `SYNC_WAL_AUDIO_COVERAGE_ENABLED` on (unset or blank means on, any unrecognized value means off, and the lineage uid allowlist still gates it), the upload path joins the opt-in S1 source-position evidence: each decoded WAL file's upload claim (`capture_root`, `clock_epoch`, mono channel, `rate_hz`, source-frame start/count) is matched against `capture_evidence` snapshots on provenance-compatible rows from the same bounded lineage read, and `utils/sync/audio_coverage.py` removes exactly the source frames a committed live transcript proof covers, before VAD/STT. Only `version=1`, `capability=source_position`, `origin=live`, `proof=committed_transcript_v1`, `coverage` mapped or incomplete, `conflicts=0` envelopes donate proof — receipt-only snapshots carry no `proof` and abstain — and `utils/sync/committed_coverage.py` additionally requires the envelope's bounded lifetime history (version 1, complete, conflict-free, at most 16 root/epoch entries) to contain every committed run's ordinals and receipt window. The check is negative and clock-based: the run's receipt wall anchors must independently reproduce the decoded WAL's actual basename-timestamp clock and uniform frame geometry within 2 s, so a stale or competing same-root lifetime (overlapping source ranges with disjoint receipt windows) abstains the whole batch rather than guessing; time agreement alone never proves a frame received. A same-root/epoch envelope with nonzero conflicts, malformed matching runs, a wrong type on `rate_hz`, more than 32 runs per envelope or more than 13 envelopes all abstain the whole batch, and unknown, unmapped or mismatched envelopes contribute nothing. Recall stays conservative — in-socket ordinal resets are caught by the producer high-water, while very close cross-socket resets additionally depend on the independent app root-rotation release rather than any cryptographic proof. Kept intervals expand by at most 0.25 s of whole adjacent frames per side as bounded context: the margin may re-include already live-received edge frames (a small bounded duplicate — context is not zero-duplication) and may span a small covered hole where two expanded intervals overlap, but it never concatenates non-contiguous captures beyond that bound, so an upload writes per-interval derivative WAVs under a `<stem>.coverage/` sibling directory named with the original phone-clock start plus sample offset, each carrying a rebased `source_frame_map`. Split derivatives carry an internal `coverage_trimmed` marker that lets the 1 s VAD minimum-span floor admit genuinely new sub-second slices; unmarked audio keeps the floor unchanged. Abstention at any step — no decoded map, lookup degraded or truncated, no matching evidence, invalid WAV geometry — keeps the original bytes, path and map; an upload with no S1 claim never reaches the consumer, costs no lookup and emits no log. A fully covered file skips VAD/STT entirely and the job ledger records success rather than expected silence. One bounded `event=sync_wal_audio_coverage` line reports kept/dropped/context seconds, file count and suppressed count with no ids; ordinary failures report the shared `record_fallback` (`from=sync_lineage to=temporal reason=other outcome=degraded`) and retain everything. Cancellation mid-split preserves the pre-handoff inputs like decode does, abandons the derivative adoption, and any generated files already tracked are removed on internal error; the consumer never deletes inputs it did not create. The lexical receipt matcher is disabled on this production seam: it is invoked with no WAL context with which to prove live ranges, so only committed frame proof suppresses audio — exact sync-scoped retries at intake remain unchanged, and the bounded context margin conservatively preserves repeats.

Offline replay: `scripts/sync_live_dedupe_replay.py` replays supplied STT candidates through the same `capture_repeat_evidence`/`live_speech_dedupe`/`audio_coverage` primitives with no env, network or provider imports, for incident investigation against a local JSON. The input carries `live_segments` and `sync_segments` (absolute `start`/`end` seconds plus `text`), optional `live_capture_evidence`/`sync_capture_evidence` envelopes in the stored shapes, an `intake_sizes` pattern of successive intakes (integers 2 through 5, default `[2,3,4,5]`, expanded so a two-or-more-segment remainder never leaves a trailing one-segment intake), and an optional `audio_coverage` block (`live_received_ranges` envelopes and `wal_frames` descriptions with `capture_root`, `clock_epoch`, `source_frame_start`, `rate_hz`, `codec` and decoded `frame_samples`, plus an optional declared `frame_count` that must be at least the decoded prefix length) that runs the production planner and reports per-file kept/dropped/context seconds and kept frame ranges. Each intake feeds fresh `sync:replay:<n>` scopes and prunes supplied `sync_vad` receipts to its batch; a candidate whose source-frame span straddles kept and removed audio is retained whole and marked `partial_audio` — transcript totals are supplied-candidate outcomes, not an estimate of post-trim STT recall. The replay models incoming receipt-union behavior: an append without donor consolidation can still replace the live envelope with sync receipts. Admitted donor consolidation preserves the independent live run envelope at its own content-transfer boundary; the donor lexical fallback works even when earlier appends lost that frame context. Malformed input exits 2 with a generic message and never leaks a path, id or text. Each WAL may additionally supply wal_start_seconds as the offline description of its observed decoded WAV basename timestamp; committed proofs require this context and frame_samples, while an absent wall anchor retains audio.

## Conversation size

Before absorbing donors, assignment and smart merge size the fully encoded
projected survivor and every donor/ancestor redirect patch against
`CONVERSATION_ABSORPTION_BYTE_CAP` (`utils/conversations/size_limit.py`):
**800 KiB**. The estimate uses the real conversation write encoder, including
compression, encryption and protection upgrades, retained stored fields and
projection removals. It reuses transactional snapshots and runs before any
transaction write. The 224 KiB below Firestore's 1 MiB ceiling includes the
existing 124 KiB sync reserve plus 100 KiB for subsequent derived processing.

Assignment stops adding donors and replans without them or their bridge
intervals. Every replan rejects excluded/existing IDs as new creates; when
removing a bridge strands its own incoming anchor, the old survivor stays
separate and speech appends/deduplicates at the durable donor. Unabsorbed
donors retain their earlier speech. The cap stops **donor absorption**: incoming
speech that still fits on the canonical under the 900 KiB append budget stays
there; a cap stop alone does not require rollover. Ordinary appends
retain the **900 KiB** whole-document preflight and the size-limit commit
backstop: speech that cannot fit goes to a new or neighbouring sync row,
without truncation or dropping speech. Batch live-record replacement uses the
same encoded pre-write budget and honours commit-proven full IDs on retry.
If no existing or ordinary new anchor is safe, assignment creates deterministic
fresh sync rows containing only incoming speech. Inputs larger than one row
split at segment boundaries in order, with every part sized before any write.
A single segment that cannot fit rejects the whole transaction and retains the
input for retry; no oversized write is staged. Smart-merge absorption uses that
backstop too; a rejected absorb keeps its already durable donor separate, so
normal finalization produces its own summary. No redirect, ancestry or audit
write from the rejected absorb commits. Existing oversized rows are not migrated.
Users can see long recordings as adjacent conversations with separate summaries.

Assignment and absorb logs carry content-free `projected_size_bucket` bands
`lt_500k|500_700k|700_800k|800_900k|900k_1m|gt_1m` (KiB; exactly 1 MiB is in
`900k_1m`). `size_cap_stop` is the closed cap-stop outcome/reason.
`omi_sync_intake_total` also carries this bounded label after commit. A caller
without a projection observation emits only the legacy intake log; it never
invents a size band.

The existing `sync_assignment_target` event uses `reason=size_rollover`,
`size_rollover_unavailable` or `size_limit_retry` with closed
`outcome=rolled_over|rejected`. `size_rollover_unavailable` is reserved for an
indivisible input that cannot fit, with `outcome=rejected` and attribution.
Cap-triggered changes of destination emit the same keyed rollover event with
`trigger=size_cap` and the actual new/sibling target kind. Size-backstop rollover success is
emitted after commit (`stage=commit`); transaction-body-only callers explicitly
report `stage=plan`. These events and size-related `sync_persistence_exception`
lines carry `job_ref` and `attempt_ref` through `bounded_correlation_ref`:
UUIDv4 inputs normalize then hash to 32 hexadecimal characters; absent or
non-UUIDv4 inputs become `none`. This also keeps job/segment refs joinable;
older releases emitted normalized UUIDs, so references change across this release.
Raw conversation IDs and UIDs never enter these fields. Calls without sync-job
context, including standalone smart merge, report `none` refs.
`segments_bucket` and `speech_seconds_bucket` reuse the conversation-shape
histogram upper bounds (plus `+Inf`, or `unknown` when no decoded payload is
available). They describe the attempted document that hit the limit, before
rollover, rather than the smaller destination. `rollover_target_kind` is
`new_row|sibling_row|none`; a rejected write has `none`. A final size exception
retains the last rejected document's buckets for the persistence log. This
attribution is transient and never stored on conversation rows or metric labels.
Rollback: revert.

## Assignment outcomes

Labeled non-target donors are excluded before extending the capture interval. A labeled
row may remain the survivor for temporal appends, but never donate its receipt into
another speaker namespace. Retargeting a labeled retry anchor is permanent supersession.

Deleted anchors, deleted redirect lineage and user-managed or labeled retargeted retry anchors raise
`SyncAssignmentSuperseded`. `process_segment` consumes them quietly with no error,
content usage or response IDs. It returns false, letting sibling segments proceed;
a zero-error job commits the content-completion ledger before publishing completed
(inline and Cloud Tasks). The bounded log is `sync_assignment outcome=superseded`;
this does not masquerade as speech silence. Provenance mismatches and redirect cycles
raise `SyncAssignmentConflict` and remain loud retryable upstream errors under the
existing job error taxonomy. Copy/checkpoint failures also retain retry behavior.
Donor retraction that collides with the account destructive-operation gate is
deferred and converges on a later append; it does not fail the accepted chunk.

Batch projection uses the same terminal assignment outcome: a metadata-only ready
receipt records `disposition=superseded`, contributes zero content speech usage,
and advances the ordered cursor only after the final part. Successful parts and
siblings retain their own receipts and usage. The content ledger completes with
zero errors and `superseded_segments`, without returning IDs for rejected parts.
Settlement rechecks the existing privacy, deletion, binding and ledger fences;
privacy revocation remains owned by erasure, not by this acknowledgment.

## Speaker identity

Speaker IDs are conversation-local. Each independently transcribed WAL chunk
carries a retry-stable content scope (legacy direct intake uses capture time).
After duplicate removal, the transaction hydrates the surviving conversation's
allocator and allocates incoming and donor identities. Legacy donors receive a
stable conversation/speaker scope. Provider labels and recognized person IDs are
preserved; equal provider numbers never establish that two voices are the same.
Conversation-wide resolution uses stored private-cloud audio after each sync
job's append and reprocess. If audio is unavailable or its timeline cannot be
trusted, the resolver marks the cross-chunk IDs `unavailable` and logs the
anonymous skip reason; clients must treat those labels as provisional. A sync
bridge's redirect tombstone remains available to owner detail reads and manual
speaker assignment: the assignment transaction follows the survivor chain and
maps the donor's selected speaker number through stable segment IDs so it never
labels a different survivor voice.

## Fleet safety-WAL dual-write suppression

`SYNC_SAFETY_WAL_DEDUPE_ENABLED` is on in dev/prod runtime config for Cloud Run
backend, backend-sync, backend-sync-backfill and backend-integration; code defaults

coverage, transcript dedupe and provider stamps to their previous behavior.
Playback merge is unchanged, including negative gaps and nested legacy chunks.

Before VAD/STT, stored chunks are listed and decoded once per conversation per job.
A uniquely locked clock offset is reused, but each six-second WAL tile requires
its own non-silent envelope correlation and per-bin energy agreement before it
can supply coverage. Spans alone and an opening fingerprint authorize no cut.
One-second margins and unmatched tiles remain; this path always retains boundary
audio and cannot authorize a suppress-all SUCCESS. Future derivative filenames,
weak or silent probes, unknown legacy batch gaps and lookup failures keep originals.
Existing S1-mapped paths retain their separate committed-frame handling.

Live text drops require an explicitly corroborated offset or two independent exact
anchor lines agreeing within two seconds. Each matched live line is consumed once,

identity can match; provider-local labels are not identity proof. After clock

is no default-zero offset. The token floor is eight: 8–11 tokens require exact
tokens; longer lines require an order-sensitive sequence ratio of at least 0.95.

No clock slop is removed after a sync revision.

suppression remains separate. #20688 touches different VAD/cleanup hunks in
`pipeline.py`; #21362 touches client WAL recovery.

`live_cap_journal.py` owns encrypted emergency staging when GCS is unavailable.
