# Shared diarizer qualification

The small truth format is a JSON object mapping arbitrary conversation keys to
lists of `{"start": 0.0, "end": 0.5, "speaker": "reference-a"}`. Times are seconds
in the submitted PCM clock. No transcript text is needed. `null`, empty, unsure,
noise and mixed labels are excluded. Turns JSON maps the same keys to exclusive
`{"start": 0.0, "end": 1.0, "speaker": "anonymous-0"}` turns.

From the repository root:

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/diarization_eval/score.py \
  --truth /private/truth.json --turns /private/exclusive-turns.json
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/diarization_eval/score.py \
  --truth ~/.local/share/labels/speaker-truth-2026-10/build/truth.json \
  --decision-mill --turns /private/crop-relative-exclusive-turns.json
```

Without `--turns`, decision-mill mode scores its cached per-word `pyannote`
predictions as a baseline. That baseline alone does not qualify assignment code.
The turns command runs the same `assign_words` code as both batch consumers.
Cached whole-file predictions must be cropped/rebased by each `conv_*.json`'s
`t0` before comparison. Missing-turn words count as misses; word-to-turn
assignment chooses maximum temporal overlap, midpoint on a tie, and abstains in
gaps. Overlap activity never changes the exclusive label.

The scorer computes optimal per-conversation 1:1 permutation with Hungarian
matching, many-predicted-to-one-reference accuracy, and speaker counts. Pooled
scores sum correct words before dividing; never average conversation percentages.
It prints only aggregate counts and rates, never names, text, paths or audio.
Private truth, turns and biometric vectors stay outside Git. Synthetic tests in
`tests/unit/test_final_pass_assignment.py` guard the scorer and assignment seam
through the repository's existing backend unit selector.

Every backend/pipeline/model revision needs the same truth and word-clock set,
plus public audio capacity checks; changing the corpus or exclusions is a new
qualification, not an improvement claim. Record model revision, pipeline version,
embedding space, RTF, peak CUDA allocation/device VRAM, failures and speaker count.

Existing private pyannote caches containing overlapping `intervals` can be scored
without inference or writing a derived private fixture:

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/diarization_eval/score.py \
  --truth ~/.local/share/labels/speaker-truth-2026-10/build/truth.json \
  --decision-mill --cached-activity-dir \
  /Volumes/Ephemeral/scratch/diar-nemotron-2026-10-12/phase1/predictions/pyannote_no_oracle
```

This crops/rebases existing activity and uses the deterministic longest-active-turn
exclusive fallback, then production word assignment. It qualifies that fallback;
it does not claim to reconstruct community-1's native acoustic exclusive output.
Report `scored_conversations`: all-unsure/unlabeled entries are not scored evidence.

Authoritative promotion changes only speaker fields on the stored transcript.
`segment_remap.py` first verifies correspondence to final-pass segments; different
candidate speakers within one stored segment veto promotion. Text, IDs, clocks,
translations and structured references remain unchanged. Existing manual receipts
are resolved to stored segment IDs, and an owner disagreement without provenance
is conservatively protected as a manual edit in either direction. This intentionally
limits authoritative word-level segmentation until edited word clocks are available.
Sync uses absolute WAV clocks for evidence and returns the legacy first-word origin
for persistence and upload-end calculation.

`tests/unit/fixtures/transcription_shadow_main.json` is synthetic output captured by
executing `_make_pass` from `origin/main` commit
`e2edc7c15ca93c6a4c5ac3d373dd3b18ff4e37f2`, with the input mocks and fixed UUID in
`test_flag_off_output_is_byte_identical_to_legacy`. Both missing and explicit-legacy
flags must equal those captured bytes; the expected output is never generated by
the implementation under test.

## Local production-path scorecard

Use a dedicated Python 3.11 evaluation environment on scratch storage, not the
backend service environment. Install `requirements-eval.txt` there. The direct
model dependency pins are the serving image's pins; macOS resolves platform
transitives separately. The local loader explicitly uses CPU FP32. Serving still
requires exactly one CUDA GPU and BF16 ASR; no CPU numerical parity is implied.

Prepare an explicit private manifest with `prep_speaker_task.py --create-manifest`
using `--archive`, repeated `--audio-dir`, `--snapshot-dir` and `--output` arguments.
The command imports closed judgments and preserves archived crop offsets and
word clocks. Outputs must be outside Git. It predeclares owner/person identities
from the supplied snapshot, and reserves the first clean 6–10 seconds per voice
for a separate enrollment-rich diagnostic. The automatic gate retains all scored
words; only that diagnostic excludes enrollment-overlapping words.
The permitted corpus declares English separately from undecided container tags;
that declaration travels through the existing staged-audio context. Admission
uses decoded PCM duration because archived crop durations can be rounded. Neither
the frozen crop nor the reference-word denominator changes.

```bash
nice -n 10 env PYTHONPATH=backend /path/to/external-eval-env/bin/python \
  backend/scripts/diarization_eval/run_local.py --manifest /private/corpus.json
```

Run through the workspace's `bin/omi-heavy run --` when available. This invokes
`create_local_worker`, `PipelineWorker.process_batch`, and `Projector.assign_parts`
with filesystem audio/result/session/assignment adapters. Scores come from the
persisted projected segments, not a fitted mapping of raw model channels. Local
assignment does not qualify Firestore transactions, deployment, or client UI.
No gallery, cloud credential, remote transcription or Firestore client is needed.
The snapshot's compatible enrolled gallery is local; absent batch centroids print
an explicit naming abstention. Inference caches bind audio/crop hashes, model
revisions, dependency versions, decoding policy and source-file hashes; projection
always reruns. The corpus file is frozen by digest before scoring.
Legacy persisted transcript groups can overlap even when diarizer turns were
exclusive. The scorer chooses the persisted identity with maximum word overlap,
then midpoint containment and earliest clock; it does not repair or relabel the
stored output. The enrollment-rich diagnostic uses only the predeclared held-out
spans and excludes their intersecting reference words. Without production naming
evidence, richer enrollment still leaves the persisted baseline anonymous.

The engineering gate uses pooled owner/enrolled word accuracy >=90%, wrong-name
plus false-owner <=1% of all scored words, and speaker count within one on every
recording. Strict all-word identity accuracy and Hungarian **oracle diagnostic**
are always separate. Anonymous strangers do not count as correctly hand-named
people. Fixed reference clocks keep ASR omissions in the identity denominator.
All-excluded recordings, missing model references and blocked model inference
are explicit non-results, never a quality pass. Non-English is NOT EVALUATED
unless the manifest explicitly supplies a separate authorized corpus.

`run_reference.py` reruns `faster-whisper-base`, `mlx-whisper-base`, and
`mlx-whisper-large-v3` on identical crops. The first uses CPU int8, beam 1 and
VAD; MLX base disables previous-text conditioning. Each engine pins its immutable
model revision before inference and records dependency versions, file hashes,
crop and decoding settings. Use separate engine environments when dependencies
conflict; never reuse the service environment. These are fresh explicit engines,
not inferred provenance for the archived words. Supply `--reference-files` to
`run_local.py`, or place the generated index under the manifest's sibling
`references/mlx-whisper-large-v3/`. Available base-engine indexes there add WER
comparisons using identical normalization and substitution/deletion/insertion
counts. Large-v3 is a **model reference, not human truth**.
The separate `requirements-reference-fw.txt` and `requirements-reference-mlx.txt`
pin those engine environments independently of the NeMo evaluation runtime.

`build_viewer.py --reference /private/gate-t-reference.json --runs
/private/pr1/runs.json` builds a blinded decision-mill pair task outside Git.
The default task is `local-quality-2026-10`; use `--output-dir` for later immutable
rounds. Each approximately five-minute section has balanced seeded A/B letters,
real persisted production text/names/turns, and the archived reference with strict
<2-second joins. Model identity and provenance remain hidden. Missing production
output leaves the task waiting, with no invented comparison. Existing judgments
are never overwritten. Validate with decision-mill's `validate.js --labels` and
inspect every rendered card before presenting the task.

For an expensive completed run, `--inference-archive /private/archive.json`
explicitly reuses unchanged original inference after verifying its source commit,
ordered source hashes, original key, corpus/audio/crop PCM/payload hashes, package
and model pins, effective provider configuration, and resolved worker switches
(speech-only, short-single, empty-ASR recovery/disposition, silence/validation
disposition and long-speech handoff). Missing switch evidence blocks archive reuse. Older receipts
may append explicitly reconstructed original-launch switch evidence while keeping
the original hashed settings and key intact. The output retains the
original receipt and whether configuration was captured or reconstructed from the
original launch. Archive reuse never claims the current full worker executed;
projection runs again and preserves its own provenance. The archive and all
receipts stay private. Keep the model environment outside the source tree on
scratch storage to avoid staging it during runtime-image preflight checks.

Reused ASR/diarization output is enriched through the same bounded centroid hook
as serving; the original artifact is immutable. Private output retains the
original inference receipt, current enrichment hashes and projection fingerprint
as composed provenance, explicitly marking `full_current_worker_executed=false`.
Snapshot and enrollment-rich naming both use actual persisted production
projection. The rich run is diagnostic and excludes its frozen enrollment spans;
its persisted view is `runs-enrollment-rich.json`.

### Split-unit continuity qualification

After single-unit naming is integrated, `split_quality.py` consumes saved real
worker payloads. It runs no model jobs, cloud clients or gallery reads:

```sh
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/diarization_eval/split_quality.py \
  --manifest /path/to/private/splits.json --output /path/to/private/split-output
```

The private JSON manifest contains `crop_seconds`, `reference_words` (the same
frozen reference clocks and speaker labels used by the unsplit score),
`identity_table`, `excluded_spans`, an optional `snapshot` path, `unsplit` (a
one-unit array), and `cases` (at least two arrays of split units). Each unit has
`offset` in seconds from the whole-crop origin and `payload`, a saved worker
result JSON path. Units must exactly tile the same whole crop. Cases must use
distinct boundaries and include a boundary inside a reference word. The optional
snapshot JSON holds already-authorized `owner_profile`, `people`, and
`named_allowed`; held-out enrollment remains separate from scored words.

Production projection builds each part, then the production conversation voice
registry and allocator commit its local encrypted state. Every part recreates
its allocator from persisted segments and decrypts the previous registry. Output
artifacts and model logs stay in permission-restricted local files; stdout has
aggregates only. The scorer receives identical reference words, identities and
exclusions for every case. Each split must retain the unsplit denominator,
single-unit engineering gate and at most two percentage points of automatic
identity loss. This adapter does not substitute for the Firestore emulator's
transaction/receipt and deletion tests.

Split qualification also requires immutable inference provenance. The manifest
names `source_audio` plus frozen `source_sha256`, `crop_audio` (canonical PCM WAV)
plus frozen `crop_pcm_sha256`, `crop_start_seconds`, and the complete pinned
`inference_config` mapping. Every unit also names its canonical PCM `audio` WAV
and its `receipt` JSON written when inference completed. Receipt fields are:
`source_sha256`, `crop_pcm_sha256`, `crop_start_seconds`, `offset`,
`duration_seconds`, `input_pcm_sha256`, `payload_sha256`, and
`inference_config_sha256`. The config digest uses sorted, compact JSON. PCM
digests cover decoded mono16kHz16-bit frames, excluding WAV/container metadata.

The evaluator checks actual payload bytes and PCM hashes, exact receipt clocks,
common model/config digests, and that concatenated unit PCM equals the frozen
whole-crop PCM for every case. Missing or stale provenance is `BLOCKED` before
projection/scoring. Receipts establish local cache provenance; they do not
cryptographically authenticate an untrusted inference runner.
