# Contributing to Omi

Start here:

1. **Product fit**: read [`PRODUCT.md`](PRODUCT.md) and the
   [product invariant registry](product/invariants/).
2. **How to contribute**: follow the full guide:
   [Contribution Guide](https://docs.omi.me/doc/developer/Contribution)
   (source: [`docs/doc/developer/Contribution.mdx`](docs/doc/developer/Contribution.mdx)).
3. **Engineering bar**: [`AGENTS.md`](AGENTS.md) Definition of Done applies to
   every PR (humans and AI agents).

Large or ambiguous features should start as a GitHub issue so maintainers can
align on scope and direction before major implementation work begins.

## What we want most

Bug reports with reproductions and logs, apps and integrations built on the
platform, and community ports (Windows/Linux clients, new device integrations).
Core PRs are welcome under the quality bar in the guide. Contributors who land
significant work get the Discord Contributor role; the team occasionally sends
hardware or credits to standout contributors.

## Bounties

Only the Omi team posts bounties, on GitHub issues labeled "Paid Bounty 💰".
Each bounty states a written proof spec (measurable target, how it is verified,
real-hardware demo where relevant) and names the maintainer who judges it.
The race is open. The first PR that meets the spec wins, and tasks are never
locked. Payment happens only after the work ships in a release; claim by
emailing [team@basedhardware.com](mailto:team@basedhardware.com) with the
bounty link. Full rules: [Bounties](https://docs.omi.me/doc/contribute/bounties).
