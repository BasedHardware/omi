# omi-cli ਨਾਲ ਤੁਰੰਤ ਸ਼ੁਰੂਆਤ

ਇਹ ਗਾਈਡ ਮੂਲ ਕਮਾਂਡਾਂ ਪੰਜਾਬੀ ਵਿੱਚ ਸਮਝਾਉਂਦੀ ਹੈ। ਕਮਾਂਡਾਂ ਦੇ ਨਾਮ ਅਤੇ ਪ੍ਰੋਗਰਾਮ
ਸੁਨੇਹੇ ਅੰਗਰੇਜ਼ੀ ਵਿੱਚ ਹੀ ਰਹਿੰਦੇ ਹਨ। ਹੇਠਾਂ ਦਿੱਤੀਆਂ ਉਦਾਹਰਣ ਕਮਾਂਡਾਂ ਤੁਹਾਡੀਆਂ
ਯਾਦਾਂ, ਗੱਲਬਾਤਾਂ, ਐਕਸ਼ਨ ਆਈਟਮਾਂ ਜਾਂ ਟੀਚਿਆਂ ਨੂੰ ਨਹੀਂ ਬਦਲਦੀਆਂ।

## ਪ੍ਰੋਗਰਾਮ ਇੰਸਟੌਲ ਕਰਨਾ

ਲੋੜਾਂ: Python 3.10 ਜਾਂ ਨਵਾਂ ਅਤੇ Omi ਖਾਤਾ।

ਜੇ `pipx` ਇੰਸਟੌਲ ਹੈ:

```sh
pipx install omi-cli
omi --help
```

ਜਾਂ ਚਾਲੂ ਕੀਤੇ Python virtual environment ਵਿੱਚ ਇੰਸਟੌਲ ਕਰੋ:

```sh
python -m pip install omi-cli
omi --help
```

ਜੇ ਟਰਮੀਨਲ `omi` ਨਹੀਂ ਲੱਭਦਾ, ਤਾਂ ਦੇਖੋ ਕਿ virtual environment ਚਾਲੂ ਹੈ ਜਾਂ
`pipx` ਵੱਲੋਂ executable ਰੱਖੇ ਗਏ ਫੋਲਡਰ `PATH` ਵਿੱਚ ਹਨ।

## ਆਪਣਾ ਖਾਤਾ ਜੋੜਨਾ

ਇੰਟਰੈਕਟਿਵ ਗਾਈਡ ਚਲਾਓ:

```sh
omi auth login
```

ਬ੍ਰਾਊਜ਼ਰ ਲੌਗਿਨ ਚੁਣੋ ਜਾਂ Omi ਡਿਵੈਲਪਰ API key ਪੇਸਟ ਕਰੋ। ਇੰਟਰੈਕਟਿਵ ਇਨਪੁੱਟ key
ਨੂੰ ਲੁਕਾਉਂਦਾ ਹੈ; ਇਸਨੂੰ ਟਰਮੀਨਲ ਇਤਿਹਾਸ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਹੋਣ ਵਾਲੀਆਂ ਕਮਾਂਡਾਂ ਵਿੱਚ
ਸਿੱਧਾ ਨਾ ਲਿਖੋ।

ਬ੍ਰਾਊਜ਼ਰ ਸਿੱਧਾ ਵਰਤਣ ਲਈ:

```sh
omi auth login --browser
```

ਉਸੇ ਕੰਪਿਊਟਰ ਉੱਤੇ ਲੌਗਿਨ ਕਰੋ ਜਿੱਥੇ ਟਰਮੀਨਲ ਹੈ, ਕਿਉਂਕਿ ਪ੍ਰਮਾਣੀਕਰਣ ਸਥਾਨਕ callback
ਪਤਾ ਵਰਤਦਾ ਹੈ। ਸਕ੍ਰੀਨ ਉੱਤੇ ਦਿਸਣ ਵਾਲੀਆਂ ਹਦਾਇਤਾਂ ਦੀ ਪਾਲਣਾ ਕਰੋ।

ਲੌਗਿਨ ਤੋਂ ਬਾਅਦ ਕੌਂਫਿਗਰੇਸ਼ਨ ਅਤੇ API ਪਹੁੰਚ ਦੀ ਜਾਂਚ ਕਰੋ:

```sh
omi auth status
omi auth whoami
```

`status` ਸਥਾਨਕ ਸਥਿਤੀ ਦਿਖਾਉਂਦਾ ਹੈ ਅਤੇ ਭੇਤਾਂ ਨੂੰ ਮਾਸਕ ਕਰਦਾ ਹੈ, ਪਰ ਇਹ ਨਹੀਂ ਦੇਖਦਾ
ਕਿ ਸਰਵਰ ਉੱਤੇ ਉਹ ਵੈਧ ਹਨ। `whoami` ਪ੍ਰਮਾਣਿਤ ਬੇਨਤੀ ਭੇਜਦਾ ਹੈ; ਜੇ ਸਫਲ ਹੋਵੇ ਤਾਂ
ਤੁਹਾਡੇ credentials ਕੰਮ ਕਰ ਰਹੇ ਹਨ — ਤੁਹਾਡਾ ਨਾਮ ਦਿਖਾਏ ਬਿਨਾਂ।

ਕੌਂਫਿਗਰੇਸ਼ਨ ਡਿਫੌਲਟ ਰੂਪ ਵਿੱਚ `~/.omi/config.toml` ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਹੁੰਦੀ ਹੈ।
ਇਸ ਫਾਇਲ ਨੂੰ ਸਾਂਝਾ ਨਾ ਕਰੋ ਕਿਉਂਕਿ ਇਸ ਵਿੱਚ credentials ਹੋ ਸਕਦੇ ਹਨ।

## ਆਪਣਾ ਡਾਟਾ ਪੜ੍ਹਨਾ

```sh
omi memory list --limit 5
omi conversation list --limit 5
omi action-item list --open
omi goal list
```

ਖਾਲੀ ਸੂਚੀ ਦਾ ਮਤਲਬ ਹੋ ਸਕਦਾ ਹੈ ਕਿ ਫਿਲਟਰ ਨਾਲ ਕੋਈ ਆਈਟਮ ਨਹੀਂ ਮਿਲੀ। ਹਰ ਕਮਾਂਡ ਦੇ
ਵਿਕਲਪ help ਵਿੱਚ ਵੇਖੋ:

```sh
omi memory list --help
omi action-item list --help
```

## JSON ਪ੍ਰਾਪਤ ਕਰਨਾ ਅਤੇ ਪੰਨੇ ਖੋਲ੍ਹਣਾ

ਗਲੋਬਲ `--json` ਵਿਕਲਪ ਨੂੰ ਕਮਾਂਡ ਗਰੁੱਪ ਤੋਂ **ਪਹਿਲਾਂ** ਰੱਖੋ:

```sh
omi --json memory list --limit 25 --offset 0
omi --json memory list --limit 25 --offset 25
```

ਪਹਿਲੀ ਕਮਾਂਡ ਪਹਿਲੀਆਂ 25 ਯਾਦਾਂ ਮੰਗਦੀ ਹੈ; ਦੂਜੀ ਅਗਲੀਆਂ 25। ਇੱਕ ਪੰਨਾ ਪੂਰਾ ਬੈਕਅਪ
ਨਹੀਂ ਹੁੰਦਾ। JSON ਆਉਟਪੁੱਟ ਪੂਰੀਆਂ ID ਰੱਖਦੀ ਹੈ, ਜਦਕਿ ਟੇਬਲ ਦਿਖਾਅ ਲਈ ID ਛੋਟੀਆਂ
ਕਰ ਸਕਦੀ ਹੈ।

ਇੱਕ ਪੰਨਾ ਫਾਇਲ ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਕਰਨ ਲਈ:

```sh
omi --json memory list --limit 25 --offset 0 > memory-page-1.json
```

ਰੀਡਾਇਰੈਕਸ਼ਨ ਸਥਾਨਕ ਫਾਇਲ ਬਣਾਉਂਦੀ ਜਾਂ ਉਸਨੂੰ ਓਵਰਰਾਈਟ ਕਰਦੀ ਹੈ। ਸਮੱਗਰੀ ਵਰਤਣ ਤੋਂ
ਪਹਿਲਾਂ ਯਕੀਨੀ ਬਣਾਓ ਕਿ ਕਮਾਂਡ ਸਫਲਤਾਪੂਰਵਕ ਪੂਰੀ ਹੋਈ। ਗਲਤੀਆਂ stderr ਉੱਤੇ ਲਿਖੀਆਂ
ਜਾਂਦੀਆਂ ਹਨ; ਖਾਲੀ ਫਾਇਲ ਡਾਟਾ ਨਾ ਹੋਣ ਦਾ ਸਬੂਤ ਨਹੀਂ। ਐਕਸਪੋਰਟ ਫਾਇਲ ਵਿੱਚ ਨਿੱਜੀ
ਜਾਣਕਾਰੀ ਹੋ ਸਕਦੀ ਹੈ — ਇਸਨੂੰ ਨਿੱਜੀ ਰੱਖੋ।

## ਪ੍ਰੋਫਾਇਲ ਵਰਤਣਾ

ਸਟੇਟ `~/.omi/config.toml` ਵਿੱਚ ਸੁਰੱਖਿਅਤ ਹੁੰਦੀ ਹੈ (`$OMI_CONFIG` ਨਾਲ ਬਦਲੀ ਜਾ
ਸਕਦੀ ਹੈ)। ਹਰ ਪ੍ਰੋਫਾਇਲ ਦਾ ਆਪਣਾ ਪ੍ਰਮਾਣੀਕਰਣ ਢੰਗ ਅਤੇ API ਪਤਾ ਹੁੰਦਾ ਹੈ।
`--profile` ਨਾਲ ਬਦਲੋ:

```sh
omi config profile use ਕੰਮ
omi auth login
omi --profile ਨਿੱਜੀ memory list
```

ਆਮ ਕੌਂਫਿਗਰੇਸ਼ਨ ਕਮਾਂਡਾਂ:

```sh
omi config show
omi config path
omi config profile list
```

## ਐਗਜ਼ਿਟ ਕੋਡ

ਇਹ ਐਗਜ਼ਿਟ ਕੋਡ ਸਥਿਰ ਹਨ ਅਤੇ ਸਕ੍ਰਿਪਟਾਂ ਜਾਂ ਏਜੰਟਾਂ ਲਈ ਉਪਯੋਗੀ ਹਨ:

| ਕੋਡ | ਅਰਥ | ਉਦਾਹਰਣ ਸਥਿਤੀ |
| ---: | --- | --- |
| 0 | ਸਫਲਤਾ | ਕਮਾਂਡ ਪੂਰੀ ਹੋਈ |
| 1 | ਵਰਤੋਂ-ਗਲਤੀ | ਗਲਤ ਫਲੈਗ, ਘੱਟ ਆਰਗੂਮੈਂਟ ਜਾਂ ਅਸਫਲ ਵੈਲੀਡੇਸ਼ਨ |
| 2 | ਪ੍ਰਮਾਣੀਕਰਨ-ਗਲਤੀ | credentials ਨਹੀਂ, ਟੋਕਨ ਦੀ ਮਿਆਦ ਖਤਮ ਜਾਂ ਇਜਾਜ਼ਤ ਘੱਟ |
| 3 | ਸਰਵਰ-ਗਲਤੀ | ਸਰਵਰ 5xx ਜਾਂ ਕਨੈਕਸ਼ਨ ਅਸਫਲ |
| 4 | ਦਰ-ਸੀਮਾ | ਸਰਵਰ ਨੇ HTTP 429 ਮੋੜਿਆ |
| 5 | ਨਹੀਂ ਮਿਲਿਆ | ਸਰਵਰ ਨੇ HTTP 404 ਮੋੜਿਆ |

## ਲੌਗਆਉਟ

```sh
omi auth logout
```

ਸਥਾਨਕ ਤੌਰ 'ਤੇ ਸੁਰੱਖਿਅਤ credentials ਹਟਾਉਂਦਾ ਹੈ। ਸਰਵਰ ਉੱਤੇ key ਰੱਦ ਕਰਨ ਲਈ ਆਪਣੇ
ਖਾਤੇ ਦਾ developer key ਪ੍ਰਬੰਧਨ ਵਰਤੋ।

ਹੋਰ ਕਮਾਂਡਾਂ ਅਤੇ ਵਿਕਲਪਾਂ ਲਈ [ਅੰਗਰੇਜ਼ੀ ਮੁੱਖ README](../README.md) ਵੇਖੋ ਅਤੇ
`omi --help` ਚਲਾਓ।
