# omi-cli жылдам бастау нұсқаулығы (Kazakh Quickstart)

> Omi-мен тікелей терминалдан жұмыс істеуге арналған практикалық нұсқаулық — әзірлеушілер мен автономды AI агенттері үшін жасалған.

`omi-cli` — [Omi](https://omi.me) платформасының әзірлеуші API-іне арналған ресми командалық жол интерфейсі (CLI). Ол жүйе сақтайтын төрт негізгі ресурсқа құрылымдалған және агенттерге ыңғайлы қолжетімділікті қамтамасыз етеді: **естеліктер** (memories), **әңгімелер** (conversations), **іс-қимыл элементтері** (action items) және **мақсаттар** (goals).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Ресми құжаттама:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Бастапқы код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

## 1. Орнату (Installation)

Пакеттер қайшылығын болдырмау және таза ортаны сақтау үшін `pipx` құралын пайдалану ұсынылады:

```bash
# Ұсынылатын әдіс: pipx арқылы оқшауланған орнату
pipx install omi-cli

# Стандартты pip арқылы баламалы орнату (мысалы, виртуалды ортада)
pip install omi-cli
```

> **Маңызды айырмашылық: Пакет атауы мен бұйрық атауы**
> * Орнату кезіндегі пакет атауы — **`omi-cli`**.
> * Терминалда іске қосылатын бұйрық — **`omi`**.

Орнатудың дұрыстығын тексеру:

```bash
omi --version
```

## 2. Аутентификация (Authentication)

`omi-cli` аутентификацияның екі негізгі әдісін қолдайды: **Браузер арқылы OAuth** (интерактивті пайдаланушылар үшін) және **Әзірлеушінің API кілті** (автоматтандыру және AI агенттері үшін).

### А әдісі: Браузер арқылы кіру (Пайдаланушылар)

Әдепкі кіру әдісі Google есептік жазбасын пайдаланады:

```bash
omi auth login
```

Немесе Apple ID арқылы кіріңіз:

```bash
omi auth login --provider apple
```

Бұл команда сәйкестендіру үшін веб-шолғыш терезесін ашады және кіру токенін `~/.omi/config.toml` конфигурациялық файлында сақтайды.

### Б әдісі: Әзірлеушінің API кілті (Скрипттер мен Агенттер)

Фондық қызметтер, CI/CD процестері немесе автономды агенттер үшін әзірлеушінің API кілтін (`omi_dev_*`) пайдаланыңыз:

```bash
# 1-нұсқа: Орта айнымалысын (Environment Variable) орнату (серверлер үшін ең тиімді тәжірибе)
export OMI_API_KEY="omi_dev_your_key_here"

# 2-нұсқа: Жүйеге кіру және кілтті жергілікті конфигурацияда сақтау
omi auth login --api-key "omi_dev_your_key_here"
```

### Аутентификация күйін тексеру

Күйді тексеру үшін екі команда қолжетімді:

```bash
# Желілік сұраусыз жергілікті тексеру (конфигурацияны немесе орта айнымалыларын оқиды)
omi auth status

# Серверде белсенді тексеру (сессияның жарамдылығын тексереді және профиль деректерін қайтарады)
omi auth whoami
```

### Жүйеден шығу (Logout)

Сақталған тіркелгі деректерін жергілікті жүйеден өшіру үшін:

```bash
omi auth logout
```

## 3. Естеліктерді басқару (Memories)

Естеліктер — Omi сіз туралы жадында сақтайтын жеке жазбалар мен контекстік фактілер.

```bash
# Соңғы естеліктер тізімі (әдепкі бойынша 25 жазба)
omi memory list

# Көрсетілетін естеліктер санын шектеу
omi memory list --limit 10

# Беттеу (алғашқы жазбаларды өткізіп жіберу)
omi memory list --limit 10 --offset 20

# Нақты естеліктің мәліметтерін ID бойынша қарау
omi memory get <memory-id>

# Жаңа естелікті қолмен жасау
omi memory create "Команданың сүйікті бағдарламалау тілі — Python."
```

## 4. Әңгімелер, тапсырмалар және мақсаттар

### Әңгімелер (Conversations)

```bash
# Соңғы әңгімелер тізімі
omi conversation list

# Нақты әңгіменің толық мәліметтері мен транскриптін қарау
omi conversation get <conversation-id>
```

### Іс-қимыл элементтері / Тапсырмалар (Action Items)

Әңгіме барысында анықталған немесе қолмен қосылған тапсырмалар:

```bash
# Қазіргі уақытта ашық тапсырмалар тізімі
omi action-item list

# Жаңа тапсырма жасау
omi action-item create "Кездесуге дейін кодты қарап шығу есебін дайындау."
```

### Мақсаттар (Goals)

Сіз бақылайтын ұзақ мерзімді мақсаттар мен прогресс көрсеткіштері:

```bash
# Барлық белсенді мақсаттардың тізімі
omi goal list

# Жаңа мақсат қосу
omi goal create "Тоқсанның соңына дейін Omi CLI құралын интеграциялауды аяқтау."
```

## 5. JSON пішімі және құбырлар интеграциясы (jq)

Автоматтандыру скрипттерімен және AI агенттерімен интеграциялау үшін жаһандық `--json` жалаушасын пайдаланыңыз.

> **Маңызды ереже:** `--json` жалаушасы ішкі бұйрықтан **бұрын** көрсетілуі тиіс (before the subcommand):

```bash
# Дұрыс:
omi --json memory list

# Қате (Click талдаушысының қатесіне әкеледі):
omi memory list --json
```

### `jq` құралымен сүзу мысалдары:

```bash
# Тек естеліктердің ID мәндерін алу
omi --json memory list | jq -r '.[].id'

# Естеліктердің мазмұнын жеке мәтін жолдары ретінде шығару
omi --json memory list | jq -r '.[].content'

# Әңгіменің ID мен тақырыбын жинақы пішімде көрсету
omi --json conversation list | jq -r '.[] | "\(.id): \(.structured.title)"'

# Ашық тапсырмалардың жалпы санын есептеу
omi --json action-item list | jq 'length'
```

## 6. Шығу кодтары және қателерді өңдеу

`omi-cli` `omi_cli/errors.py` файлында нақты анықталған шығу кодтарын қолданады:

| Код | Тұрақты | Санат | Мағынасы және ұсынылатын әрекет |
| :---: | :--- | :--- | :--- |
| **`0`** | `EXIT_OK` | Сәтті | Бұйрық сәтті және толық орындалды. |
| **`1`** | `EXIT_USAGE` | Қате қолдану | `omi-cli` ішкі тексеру қатесі (мысалы, бір уақытта `--browser` және `--api-key` көрсету). *Ескертпе:* Click талдаушысының стандартты синтаксистік қателері **2** кодын қайтарады. |
| **`2`** | `EXIT_AUTH` | Аутентификация | Жарамсыз API кілті, мерзімі өткен сессия немесе жоқ токен. Сондай-ақ Click талдаушысының қателері. |
| **`3`** | `EXIT_SERVER` | Сервер / Желі қатесі | HTTP 5xx жауабы немесе желі байланысының үзілуі. Серверде деректердің сақталуына кепілдік берілмейді. |
| **`4`** | `EXIT_RATE_LIMITED` | Сұрау лимитінен асу | HTTP 429 жауабы. CLI `Retry-After` тақырыбын ескере отырып, сұрауды автоматты түрде қайталайды. |
| **`5`** | `EXIT_NOT_FOUND` | Ресурс табылмады | HTTP 404 жауабы. Көрсетілген ресурс немесе ID табылмады. |

> **Кіру токенін жаңарту:** `omi auth refresh` бұйрығы тек браузер (OAuth) сессияларына арналған. Әзірлеушінің API кілттерін пайдаланған кезде бұл бұйрық қате қайтарады (шығу коды 1), себебі жаңартатын токен жоқ.

## 7. Автоматтандыру скрипттерінің мысалдары

### Bash скрипті: Қателерді өңдей отырып естелік жасау

```bash
#!/usr/bin/env bash
set -euo pipefail

TEXT="Команданың апталық жиналысы дүйсенбі сағат 11:00-ге белгіленді."

echo "Жаңа естелік жасалуда..."
if RESPONSE=$(omi --json memory create "$TEXT" 2>&1); then
  MEMORY_ID=$(echo "$RESPONSE" | jq -r '.id // empty')
  echo "Сәтті орындалды! Жаңа естелік ID: $MEMORY_ID"
else
  STATUS=$?
  echo "Естелік жасау кезінде қате орын алды (Шығу коды: $STATUS)"
  case $STATUS in
    2) echo "Аутентификация қатесі: OMI_API_KEY айнымалысын тексеріңіз немесе 'omi auth login' іске қосыңыз." ;;
    3) echo "Сервер немесе желі қатесі. Кейінірек қайталап көріңіз." ;;
    4) echo "Сұрау шегі асып кетті." ;;
    *) echo "Қате орын алды: $RESPONSE" ;;
  esac
  exit $STATUS
fi
```

### PowerShell скрипті: Тапсырмаларды өңдеу

```powershell
$response = omi --json action-item list | ConvertFrom-Json

foreach ($item in $response) {
    [PSCustomObject]@{
        Id          = $item.id
        Description = $item.description
        CreatedAt   = $item.created_at
    }
}
```

## 8. Кеңейтілген мүмкіндіктер

### Жергілікті Desktop API-ге қосылу

Егер компьютеріңізде Omi десктоптық қосымшасы жұмыс істеп тұрса, `omi-cli` бұлтқа жібермей-ақ тікелей `47778` порты арқылы `local` ішкі бұйрықтары үшін байланыса алады:

```bash
# Жергілікті API үшін орта айнымалыларын баптау
export OMI_LOCAL_API_URL="http://localhost:47778"
export OMI_LOCAL_TOKEN="your_local_security_token"

# Жергілікті қызмет күйін тексеру
omi local status
```

### Профильдерді басқару және сынақ ортасы (Staging)

`--profile` жалаушасы бірнеше тәуелсіз конфигурациялармен жұмыс істеуге мүмкіндік береді (мысалы, жеке, жұмыс немесе сынақ ортасы). Баптаулар `~/.omi/config.toml` файлында сақталады:

```bash
# Әртүрлі профильдерге кіру
omi --profile personal auth login
omi --profile work auth login

# Бұйрықтарды нақты профиль аясында орындау
omi --profile work memory list

# Staging ортасында сынақтан өткізу
omi --profile staging --api-base https://api.staging.omi.me memory list
```

## 9. Қауіпсіздік және озық тәжірибелер

* **Құпия кілттерді қорғау:** `omi_dev_*` кілттерін Git-тің ашық репозиторийлерінде ешқашан сақтамаңыз. Орта айнымалыларын немесе қауіպсіз құпияларды басқару жүйелерін (Secret Managers) пайдаланыңыз.
* **Файл рұқсаттары (Unix):** Конфигурация қалтасын қатаң рұқсаттармен қорғаңыз:
  ```bash
  chmod 700 ~/.omi
  ```
* **Уақытша сессияларды тазалау:** Ортақ немесе уақытша жұмыс станцияларында жұмысты аяқтағаннан кейін сессия деректерін жойыңыз:
  ```bash
  unset OMI_API_KEY
  omi auth logout
  ```
