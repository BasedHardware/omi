# omi-cli Ръководство за бърз старт (Bulgarian Quickstart)

> Практическо ръководство за използване на Omi директно от терминала — създадено за разработчици и автономни AI агенти.

`omi-cli` е официалният интерфейс с команден ред (CLI) за API за разработчици на [Omi](https://omi.me). Той предоставя структуриран достъп до 4-те основни ресурса на Omi: спомени (memories), разговори (conversations), задачи / действия (action items) и цели (goals).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Официална документация:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Изходен код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Инсталация

За да избегнете конфликти между системни зависимости и да поддържате изолирана среда, силно се препоръчва използването на `pipx`:

```bash
# Препоръчителен метод: изолирана инсталация чрез pipx
pipx install omi-cli

# Алтернативна инсталация чрез стандартен pip (напр. във виртуална среда)
pip install omi-cli
```

> **Важно уточнение: Име на пакета спрямо име на командата**
> * Официалното име на пакета в PyPI е **`omi-cli`** (пакетът `omi` е отделен и несвързан проект).
> * Командата, която се изпълнява в терминала, е директно: **`omi`**.

Проверете дали инсталацията е успешна чрез показване на версията и помощното меню:

```bash
omi --version
omi --help
```

## 2. Удостоверяване (Authentication)

`omi-cli` поддържа два основни метода за удостоверяване:

| Метод | Предназначение | Примерна команда |
| :--- | :--- | :--- |
| **API ключ за разработчици (`omi_dev_*`)** | Автоматизация, CI/CD, headless сървъри, AI агенти | `omi auth login --api-key ...` или `OMI_API_KEY` |
| **OAuth вход през браузър (Google/Apple)** | Локална разработка на личен компютър | `omi auth login --browser` (Google) / `--provider apple` |

### Интерактивен вход
Изпълнението на командата без допълнителни параметри стартира интерактивно меню:

```bash
omi auth login
# 1) Browser — Вход с Google през браузър (за вход с Apple използвайте флага `--provider apple`)
# 2) API key — Поставяне на разработчески API ключ от app.omi.me
```

### Директен вход през браузър
```bash
# Стандартен вход с Google акаунт
omi auth login --browser

# Алтернативен вход с Apple профил
omi auth login --browser --provider apple
```

### Вход с API ключ за разработчици
Генерирайте API ключ от таблото за управление на [app.omi.me](https://app.omi.me) в секцията **Developer → API Keys**:

```bash
# Запазване на ключа в текущия локален профил
omi auth login --api-key omi_dev_...

# Или чрез експортиране на променлива на средата (идеално за Docker контейнери и CI/CD):
# Забележка: Ако в профила вече има съхранен ключ, първо изпълнете `omi auth logout`.
export OMI_API_KEY="omi_dev_вашият_ключ_тук"
```

### Проверка на състоянието на удостоверяване
* `omi auth status`: Показва активния профил и маскиран идентификатор без мрежова заявка (работи офлайн).
* `omi auth whoami`: Изпраща валидираща заявка до сървъра на Omi за потвърждение на валидността на сесията (изисква връзка с интернет).

```bash
omi auth status
omi auth whoami
```

### Изход от системата (Logout)
```bash
omi auth logout
# Ако сте използвали променлива на средата OMI_API_KEY, премахнете я от сесията (Bash/Zsh: `unset OMI_API_KEY`).
```

## 3. Основни команди

### Спомени (Memories)
Контекстуални бележки и наблюдения, съхранени от Omi:

```bash
# Извеждане на списък със запазените спомени
omi memory list

# Създаване на нов спомен
omi memory create "Предпочита кратки и технически издържани отговори с примери на Python" --category work

# Извличане на конкретен спомен по идентификатор
omi memory get <MEMORY_ID>
```

### Разговори (Conversations)
Записани разговори и транскрипции от Omi устройства:

```bash
# Списък на последните 5 разговора
omi conversation list --limit 5

# Извличане на разговор заедно с пълната стенограма
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Задачи и действия (Action Items)
Автоматично разпознати задачи от проведените разговори:

```bash
# Извеждане на отворените задачи
omi action-item list --open

# Маркиране на задача като завършена
omi action-item complete <ACTION_ITEM_ID>
```

### Цели (Goals)
Дългосрочни цели и проследяване на напредъка:

```bash
# Списък на активните цели
omi goal list

# Създаване на количествена цел
omi goal create "Пий по 2 литра вода дневно" --type numeric --target 2 --unit liters
```

## 4. Структурирана автоматизация и JSON изход (`--json`)

`omi-cli` е оптимизиран за скриптова интеграция и захранване на AI агенти. Глобалният флаг `--json` връща валиден JSON формат за обработка с инструменти като `jq`:

```bash
# Списък със спомени във формат JSON и филтриране с jq
omi --json memory list | jq '.[] | {id, content, category}'

# Извличане на заглавията на последните разговори
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Извеждане на отворените задачи в суров JSON вид
omi --json action-item list --open | jq '.'
```

> **Важно правило за синтаксиса:**
> Флагът `--json` е **глобална опция**, което означава, че трябва да бъде поставен **преди** подкомандата:
> * Правилно: `omi --json memory list`
> * Грешно: `omi memory list --json`

### Пагинация и експорт във файлове
Използвайте параметрите `--limit` и `--offset` за обхождане на големи обеми от данни:

```bash
# Пагинация на резултатите
omi --json memory list --limit 25 --offset 0 > spomeni-stranica-1.json
omi --json memory list --limit 25 --offset 25 > spomeni-stranica-2.json
```

Пренасочването към файл презаписва или създава файла локално. Винаги проверявайте кода за изход на командата преди обработка. Грешките се извеждат в стандартния поток за грешки (stderr), така че наличието на празен файл не е гаранция за липса на данни. Експортираните файлове могат да съдържат лични данни — пазете ги съгласно политиките си за сигурност.

## 5. Кодове за изход (Exit Codes)

Надеждно прихващане на грешки в CLI скриптове и CI/CD тръбопроводи:

| Код | Значение | Описание |
| :---: | :--- | :--- |
| `0` | **Успех (`EXIT_OK`)** | Командата се изпълни успешно без грешки. |
| `1` | **Грешка при използване / синтаксис (`EXIT_USAGE`)** | Невалидни стойности, непознати Click флагове или липсващи аргументи. |
| `2` | **Грешка при удостоверяване (`EXIT_AUTH`)** | Липсващи идентификационни данни, изтекъл ключ или недостатъчни права за достъп. |
| `3` | **Сървърна или мрежова грешка (`EXIT_SERVER`)** | HTTP 5xx отговор, прекъсване на връзката или таймаут на заявката. |
| `4` | **Ограничение на заявките (`EXIT_RATE_LIMITED`)** | HTTP 429 отговор — твърде много заявки за кратък интервал от време. |
| `5` | **Ресурсът не е намерен (`EXIT_NOT_FOUND`)** | HTTP 404 отговор — търсеният обект не съществува. |

## 6. Примери за различни терминални среди

### Bash / Zsh (Linux / macOS)
```bash
export OMI_API_KEY="omi_dev_вашият_ключ_тук"

# Изпълнение на команда и проверка на кода за изход
omi --json memory list --limit 10
if [ $? -ne 0 ]; then
    echo "Възникна грешка при извличане на спомените." >&2
fi
```

### PowerShell (Windows)
```powershell
$env:OMI_API_KEY = "omi_dev_вашият_ключ_тук"

# Конвертиране на JSON изхода директно в PowerShell обект
$memories = omi --json memory list | ConvertFrom-Json
$memories | Select-Object id, content, category

# Проверка за грешка чрез $LASTEXITCODE
if ($LASTEXITCODE -ne 0) {
    Write-Error "Командата на Omi завърши с код за грешка: $LASTEXITCODE."
}
```

## 7. Интеграция с локалното десктоп приложение (Local Desktop API)

Ако десктоп приложението Omi работи на същия компютър, можете да правите заявки към локалната хронология на екрана без достъп до облака:

```bash
# Задаване на локален адрес и токен за достъп
export OMI_LOCAL_API_URL="http://127.0.0.1:47778"
read -r -s -p "Въведете десктоп токен: " OMI_LOCAL_TOKEN; echo
export OMI_LOCAL_TOKEN

# Проверка на състоянието на локалната услуга
omi --json local status

# Търсене в екранната хронология
omi --json local search-screen "Тримесечен отчет" --days 7 --app Safari
```

## 8. Работа с множество профили (Profiles)

Флагът `--profile` ви дава възможност да разделяте работни, лични акаунти или среди за тестване. Конфигурацията се съхранява в `~/.omi/config.toml`:

```bash
# Създаване и вход в личен профил
omi --profile personal auth login

# Създаване и вход в служебен профил
omi --profile work auth login

# Изпълнение на команда с определен профил
omi --profile work memory list

# Използване на тестова среда (staging)
omi --profile staging --api-base https://api.staging.omi.me memory list
```

## 9. Сигурност и добри практики

* **Не записвайте ключове в Git:** Никога не добавяйте API ключове в публични хранилища; използвайте мениджър за тайни или файлове за среда, описани в `.gitignore`.
* **Защита на терминалната история:** На споделени машини избягвайте подаването на ключове като параметри на команди; използвайте интерактивния вход или променливата `OMI_API_KEY`.
* **Права за достъп до файлове:** В среди с Unix задайте ограничителни права за конфигурационната директория `~/.omi/` (`chmod 700 ~/.omi`).
