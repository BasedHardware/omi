# omi-cli արագ մեկնարկի ուղեցույց (Armenian Quickstart)

> Գործնական ուղեցույց Omi-ի հետ տերմինալից աշխատելու համար՝ ստեղծված ծրագրավորողների և ինքնավար AI գործակալների համար:

`omi-cli`-ն հանդիսանում է [Omi](https://omi.me) հարթակի ծրագրավորողի API-ի պաշտոնական հրամանային տողի ինտերֆեյսը (CLI): Այն ապահովում է կառուցվածքային և գործակալների համար օպտիմալացված հասանելիություն չորս հիմնական ռեսուրսներին՝ **հիշողություններ** (memories), **խոսակցություններ** (conversations), **գործողությունների կետեր** (action items) և **նպատակներ** (goals):

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Պաշտոնական փաստաթղթավորում:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Ելակետային կոդ:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

## 1. Տեղադրում (Installation)

Փաթեթների կոնֆլիկտներից խուսափելու և մաքուր միջավայր պահպանելու համար խորհուրդ է տրվում օգտագործել `pipx`:

```bash
# Խորհուրդ տրվող եղանակ՝ մեկուսացված տեղադրում pipx-ի միջոցով
pipx install omi-cli

# Այլընտրանքային տեղադրում ստանդարտ pip-ի միջոցով (օր. վիրտուալ միջավայրում)
pip install omi-cli
```

> **Կարևոր տարբերություն՝ Փաթեթի անվանում vs. Հրամանի անվանում**
> * Տեղադրման ժամանակ փաթեթի անվանումն է **`omi-cli`**:
> * Տերմինալում գործարկվող հրամանն է **`omi`**:

Ստուգեք տեղադրման ճշգրտությունը.

```bash
omi --version
```

## 2. Նույնականացում (Authentication)

`omi-cli`-ն ապահովում է նույնականացման երկու հիմնական մեթոդ՝ **OAuth բրաուզերի միջոցով** (ինտերակտիվ օգտատերերի համար) և **Ծրագրավորողի API բանալի** (ավտոմատացման և AI գործակալների համար):

### Մեթոդ A: Մուտք բրաուզերի միջոցով (Օգտատերեր)

Լռելյայն մեթոդն օգտագործում է Google-ի հաշիվը.

```bash
omi auth login
```

Կամ մուտք գործեք Apple ID-ով.

```bash
omi auth login --provider apple
```

Այս հրամանը բացում է վեբ բրաուզերի պատուհան ինքնությունը հաստատելու համար և մուտքի տոկենը պահպանում է `~/.omi/config.toml` կոնֆիգուրացիոն ֆայլում:

### Մեթոդ B: Ծրագրավորողի API բանալի (Սկրիպտներ և AI գործակալներ)

Ֆոնային ծառայությունների, CI/CD գործընթացների կամ ինքնավար գործակալների համար օգտագործեք ծրագրավորողի API բանալին (`omi_dev_*`).

```bash
# Տարբերակ 1: Միջավայրի փոփոխականի (Environment Variable) սահմանում (լավագույն տարբերակ սերվերների համար)
export OMI_API_KEY="omi_dev_your_key_here"

# Տարբերակ 2: Մուտք գործել և պահպանել տեղական կոնֆիգուրացիայում
omi auth login --api-key "omi_dev_your_key_here"
```

### Նույնականացման կարգավիճակի ստուգում

Կարգավիճակը ստուգելու համար հասանելի են երկու հրամաններ.

```bash
# Տեղական ստուգում առանց ցանցային հարցման (կարդում է կոնֆիգուրացիան կամ միջավայրի փոփոխականները)
omi auth status

# Ակտիվ ստուգում սերվերում (ստուգում է սեսիայի վավերականությունը և վերադարձնում պրոֆիլի տվյալները)
omi auth whoami
```

### Ելք համակարգից (Logout)

Պահպանված տվյալները համակարգից ջնջելու համար.

```bash
omi auth logout
```

## 3. Հիշողությունների կառավարում (Memories)

Հիշողությունները ներկայացնում են առանձին գրառումներ և կոնտեքստային փաստեր, որոնք Omi-ն հիշում է ձեր մասին:

```bash
# Վերջին հիշողությունների ցուցակ (լռելյայն՝ 25 գրառում)
omi memory list

# Ցուցադրվող հիշողությունների քանակի սահմանափակում
omi memory list --limit 10

# Էջավորում (սկզբնական գրառումների բաց թողնում)
omi memory list --limit 10 --offset 20

# Կոնկրետ հիշողության մանրամասների դիտում ID-ով
omi memory get <memory-id>

# Նոր հիշողության ստեղծում ձեռքով
omi memory create "Թիմի սիրելի ծրագրավորման լեզուն Python-ն է:"
```

## 4. Խոսակցություններ, գործողությունների կետեր և նպատակներ

### Խոսակցություններ (Conversations)

```bash
# Վերջին խոսակցությունների ցանկը
omi conversation list

# Կոնկրետ խոսակցության մանրամասների և տրանսկրիպտի դիտում
omi conversation get <conversation-id>
```

### Գործողությունների կետեր (Action Items)

Խոսակցությունների ընթացքում ֆիքսված կամ ձեռքով ավելացված առաջադրանքներ.

```bash
# Ընթացիկ ակտիվ առաջադրանքների դիտում
omi action-item list

# Նոր գործողության կետի ստեղծում
omi action-item create "Հանդիպումից առաջ պատրաստել կոդի վերանայման հաշվետվությունը:"
```

### Նպատակներ (Goals)

Երկարաժամկետ նպատակներ և առաջընթացի չափանիշներ.

```bash
# Բոլոր ակտիվ նպատակների ցանկը
omi goal list

# Նոր նպատակի ավելացում
omi goal create "Ավարտել Omi CLI գործիքի ինտեգրումը մինչև եռամսյակի վերջ:"
```

## 5. JSON ձևաչափ և խողովակաշարերի ինտեգրում (jq)

Ավտոմատացման սկրիպտների և AI գործակալների հետ ինտեգրվելու համար օգտագործեք գլոբալ `--json` դրոշակը:

> **Կարևոր կանոն՝** `--json` դրոշակը պետք է նշվի ենթահրամանից **առաջ** (before the subcommand).

```bash
# Ճիշտ է՝
omi --json memory list

# Սխալ է (կառաջացնի Click պարսերի սխալ)՝
omi memory list --json
```

### Ֆիլտրման օրինակներ `jq` գործիքով.

```bash
# Միայն հիշողությունների ID-ների ստացում
omi --json memory list | jq -r '.[].id'

# Հիշողությունների բովանդակության արտածում տեքստային տողերով
omi --json memory list | jq -r '.[].content'

# Խոսակցության ID-ի և վերնագրի արտածում հակիրճ ձևաչափով
omi --json conversation list | jq -r '.[] | "\(.id): \(.structured.title)"'

# Բաց գործողությունների կետերի ընդհանուր քանակի հաշվարկ
omi --json action-item list | jq 'length'
```

## 6. Ելքային կոդեր և սխալների կառավարում

`omi-cli`-ն իրականացնում է հստակ սահմանված ելքային կոդեր, որոնք նկարագրված են `omi_cli/errors.py` ֆայլում.

| Կոդ | Հաստատուն | Կատեգորիա | Նշանակություն և առաջարկվող գործողություն |
| :---: | :--- | :--- | :--- |
| **`0`** | `EXIT_OK` | Հաջողություն | Հրամանը հաջողությամբ և ամբողջությամբ կատարվել է: |
| **`1`** | `EXIT_USAGE` | Սխալ կիրառում | Ներքին վալիդացիայի սխալ `omi-cli`-ում (օր. `--browser` և `--api-key` միաժամանակ նշելը): *Նշում՝* Click պարսերի ստանդարտ սինտաքսային սխալները վերադարձնում են **2** կոդը: |
| **`2`** | `EXIT_AUTH` | Նույնականացում | Անվավեր API բանալի, ժամկետանց սեսիա կամ բացակայող տոկեն: Նաև Click պարսերի սխալներ: |
| **`3`** | `EXIT_SERVER` | Սերվերի / Ցանցի սխալ | HTTP 5xx պատասխան կամ ցանցային կապի ընդհատում: Սերվերում տվյալների պահպանումը երաշխավորված չէ: |
| **`4`** | `EXIT_RATE_LIMITED` | Հարցումների սահմանաչափի գերազանցում | HTTP 429 պատասխան: CLI-ն ավտոմատ կրկնում է հարցումը՝ հաշվի առնելով `Retry-After` վերնագիրը: |
| **`5`** | `EXIT_NOT_FOUND` | Ռեսուրսը չի գտնվել | HTTP 404 պատասխան: Նշված ռեսուրսը կամ ID-ն գոյություն չունի: |

> **Մուտքի տոկենի թարմացում՝** `omi auth refresh` հրամանը նախատեսված է միայն բրաուզերի (OAuth) սեսիաների համար: Ծրագրավորողի API բանալիների դեպքում այս հրամանը վերադարձնում է սխալ (ելքային կոդ 1), քանի որ թարմացման ենթակա տոկեն գոյություն չունի:

## 7. Ավտոմատացման սկրիպտների օրինակներ

### Bash սկրիպտ՝ Հիշողության ստեղծում սխալների մշակմամբ

```bash
#!/usr/bin/env bash
set -euo pipefail

TEXT="Թիմի շաբաթական հանդիպումը նշանակված է երկուշաբթի, ժամը 11:00-ին:"

echo "Նոր հիշողության ստեղծում..."
if RESPONSE=$(omi --json memory create "$TEXT" 2>&1); then
  MEMORY_ID=$(echo "$RESPONSE" | jq -r '.id // empty')
  echo "Հաջողություն: Նոր հիշողության ID՝ $MEMORY_ID"
else
  STATUS=$?
  echo "Սխալ հիշողություն ստեղծելիս (Ելքային կոդ՝ $STATUS)"
  case $STATUS in
    2) echo "Նույնականացման սխալ: Ստուգեք OMI_API_KEY-ը կամ գործարկեք 'omi auth login':" ;;
    3) echo "Սերվերի կամ ցանցի սխալ: Փորձեք ավելի ուշ:" ;;
    4) echo "Հարցումների սահմանաչափը գերազանցված է:" ;;
    *) echo "Առաջացել է սխալ՝ $RESPONSE" ;;
  esac
  exit $STATUS
fi
```

### PowerShell սկրիպտ՝ Գործողությունների կետերի ստացում

```powershell
$ErrorActionPreference = "Stop"

# Ստուգել նույնականացման կարգավիճակը
omi auth status | Out-Null
if ($LASTEXITCODE -ne 0) {
    Write-Error "Omi նույնականացումը բացակայում է: Գործարկեք 'omi auth login':"
    exit 2
}

# Ստանալ բաց գործողությունների կետերը JSON ձևաչափով
$itemsJson = omi --json action-item list
$items = $itemsJson | ConvertFrom-Json

Write-Host "Հաջողությամբ բեռնվել է $($items.Count) առաջադրանք:"
$items | ForEach-Object {
    Write-Host "- [$($_.id)] $($_.description)"
}
```

## 8. Լրացուցիչ հնարավորություններ

### Կապ տեղական Desktop API-ի հետ

Եթե ձեր համակարգչում գործարկված է Omi դեսկտոպ հավելվածը, `omi-cli`-ն կարող է ուղղակիորեն կապ հաստատել նրա հետ `47778` պորտի միջոցով `local` ենթահրամանների համար.

```bash
# Միջավայրի փոփոխականների կարգավորում տեղական API-ի համար
export OMI_LOCAL_API_URL="http://localhost:47778"
```

### Պրոֆիլների կառավարում և թեստավորում (Staging)

`--profile` դրոշակը թույլ է տալիս աշխատել մի քանի անկախ կոնֆիգուրացիաների հետ (օր. անձնական, աշխատանքային կամ թեստային միջավայր): Կարգավորումները պահպանվում են `~/.omi/config.toml`-ում.

```bash
# Մուտք գործել տարբեր պրոֆիլներով
omi --profile personal auth login
omi --profile work auth login

# Հրամանների կատարում կոնկրետ պրոֆիլի ներքո
omi --profile work memory list

# Թեստավորում staging միջավայրում
omi --profile staging --api-base https://api.staging.omi.me memory list
```

## 9. Անվտանգություն և լավագույն փորձ

* **Գաղտնի բանալիների պաշտպանություն՝** Երբեք մի պահեք `omi_dev_*` բանալիները Git-ի հանրային ռեպոզիտորիաներում: Օգտագործեք միջավայրի փոփոխականներ կամ գաղտնիքների կառավարման ապահով համակարգեր (Secret Managers):
* **Ֆայլերի հասանելիության իրավունքներ (Unix)՝** Պաշտպանեք կոնֆիգուրացիոն պանակը խիստ թույլտվություններով.
  ```bash
  chmod 700 ~/.omi
  ```
* **Ժամանակավոր սեսիաների մաքրում՝** Ընդհանուր կամ ժամանակավոր աշխատանքային կայաններում աշխատանքն ավարտելուց հետո մաքրեք սեսիայի տվյալները.
  ```bash
  unset OMI_API_KEY
  omi auth logout
  ```
