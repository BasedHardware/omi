# omi-cli — хуткі пачатак на беларускай мове

> Практычны дапаможнік для працы з Omi з тэрмінала. Падыходзіць як людзям, так і AI-агентам.

`omi-cli` — афіцыйны камандны кліент API для распрацоўшчыкаў [Omi](https://omi.me).
Ён дае хуткі і скрыптавальны доступ да чатырох асноўных сутнасцей Omi:
успаміны, размовы, задачы і мэты.

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Дакументацыя:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Крыніца:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Усталяванне

Рэкамендаваны спосаб — `pipx`: ён усталёўвае інструмент у ізаляванае асяроддзе,
каб яго залежнасці не канфліктавалі з вашымі праектамі.

```bash
# рэкамендавана: усталяванне праз pipx
pipx install omi-cli

# або праз pip
pip install omi-cli
```

> **Важна: назва пакета і назва каманды розныя.**
> * Пакет, які ўсталёўваецца, — **`omi-cli`** (асобны пакет `omi` — іншы праект, без сувязі).
> * Пасля ўсталявання вы выконваеце каманду **`omi`**.

Пераканайцеся, што ўсё працуе:

```bash
omi --version
omi --help
```

## 2. Аўтэнтыфікацыя

`omi-cli` падтрымлівае два спосабы ўваходу.

| Спосаб | Для каго | Каманда |
| :--- | :--- | :--- |
| **Ключ распрацоўшчыка (`omi_dev_*`)** | CI/CD, скрыпты, AI-агенты | `omi auth login --api-key ...` або зменная асяроддзя |
| **Уваход праз браўзэр (Google/Apple)** | Праца на ўласнай машыне | `omi auth login --browser` |

### Інтэрактыўны ўваход

Без параметраў каманда сама пытае, які спосаб выкарыстоўваць:

```bash
omi auth login
# 1) Browser — уваход праз Google або Apple (зручна для людзей)
# 2) API key — уставіць ключ распрацоўшчыка з app.omi.me (зручна для агентаў і CI)
```

Калі вы выбіраеце ключ, увод хаваецца, каб ключ не застаўся ў гісторыі тэрмінала.

### Непасрэдна праз браўзэр

```bash
omi auth login --browser
```

### Праз ключ распрацоўшчыка

Ключ бярэцца на [app.omi.me](https://app.omi.me) у раздзеле **Developer → API Keys**.

```bash
# захаваць ключ у канфігурацыі
omi auth login --api-key omi_dev_...

# або перадаць праз асяроддзе — пераважна для CI/CD і кантэйнераў
export OMI_API_KEY=omi_dev_...
```

Зменная асяроддзя `OMI_API_KEY` выкарыстоўваецца, калі ў актыўным профілі ключ не захаваны;
у кантэйнеры таму нічога не трэба запісваць на дыск.
Калі профіль ужо мае ключ, ён мае прыярытэт над зменнай асяроддзя.

### Праверка злучэння

Дзве каманды адказваюць на два розныя пытанні і не павінны блытацца:

* `omi auth status` — тое, што захавана **лакальна**: профіль, замаскіраваны ключ, дата заканчэння.
  Працуе без сеткі.
* `omi auth whoami` — запыт **да сервера Omi**: правярае, што ключ сапраўды прыняты.
  Патрабуе сеткі.

```bash
omi auth status    # лакальная праверка, афлайн
omi auth whoami    # праверка на баку сервера
```

Абнавіць токен, які хутка скончыцца, без паўторнага ўваходу — гэта каманда
датычыцца **толькі сесій браўзэра/OAuth**. Для профілю, аўтэнтыфікаванага ключом API (`omi_dev_*`),
`omi auth refresh` сканчаецца памылкай выкарыстання (код 1): няма токена для абнаўлення —
павярніце ключ у вэб-праграме Omi, калі гэта неабходна:

```bash
omi auth refresh
```

Выйсці:

```bash
omi auth logout
```

## 3. Асноўныя каманды

### Успаміны (memories)

Факты і веды, якія сістэма запомніла пра вас.

```bash
# спіс успамінаў
omi memory list

# стварыць новы
omi memory create "Карыстальнік аддае перавагу цёмнай тэме" --category lifestyle

# паглядзець пэўны ўспамін
omi memory get <MEMORY_ID>
```

### Размовы (conversations)

Гісторыя голасу і тэксту з прылады або праграмы.

```bash
# 5 апошніх размоў
omi conversation list --limit 5

# поўная размова з транскрыпцыяй
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Задачы (action items)

Задачы, якія Omi вывеў з размоў.

```bash
# толькі адкрытыя задачы
omi action-item list --open

# пазначыць як выкананую
omi action-item complete <ACTION_ITEM_ID>
```

### Мэты (goals)

```bash
# спіс мэт
omi goal list

# запісаць новае значэнне прагрэсу (патрэбны АБОДВА аргументы: мэта і значэнне)
omi goal progress <GOAL_ID> 25

# гісторыя змен
omi goal history <GOAL_ID>
```

## Задаваць пытанні сваімі словамі (`ask`)

Асобная каманда верхняга ўзроўню: задае пытанне натуральнай мовай,
а адказ будуецца з вашых уласных размоў.

```bash
omi ask "што я вырашыў наконт пераезду"
omi --json ask "якія задачы я абяцаў завяршыць на гэтым тыдні"
```

## 4. JSON і скрыпты (`--json`)

`omi-cli` можа выдаваць JSON, прыдатны для машыннага чытання. Параметр `--json` **глабальны**
і таму ставіцца **перад** падкамандай.

```bash
# успаміны: выняць id, тэкст і катэгорыю
omi --json memory list | jq '.[] | {id, content, category}'

# загалоўкі апошніх размоў
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# адкрытыя задачы
omi --json action-item list --open | jq '.'
```

> **Частая памылка.** `--json` стаіць перад падкамандай, а не пасля яе.
> * Правільна: `omi --json memory list`
> * Няправільна: `omi memory list --json`

У рэжыме `--json` на stdout не выводзіцца нічога, акрамя самога JSON —
скрыпты могуць на гэта разлічваць.

## 5. Коды выхаду

Коды стабільныя: логіка скрыптоў і CI можа на іх абапірацца.

| Код | Значэнне | Калі |
| :---: | :--- | :--- |
| `0` | Поспех | Каманда выканалася |
| `1` | Памылка выкліку | Валідацыя, уласцівая omi-cli (напр. `--browser` і `--api-key` разам, няправільны выбар уваходу, пусты stdin) |
| `2` | Памылка доступу | Не ўвайшлі, ключ няправільны або скончыўся |
| `3` | Памылка сервера | Адказ 5xx, тайм-аўт, няма злучэння |
| `4` | Занадта шмат запытаў | 429 Too Many Requests |
| `5` | Не знойдзена | 404, ідэнтыфікатар не існуе |

> **Заўвага.** Невядомыя параметры і адсутныя аргументы перахопліваюцца Click і даюць код `2`.

Прыклад праверкі ў Bash:

```bash
if omi --json auth whoami > /dev/null 2>&1; then
  echo "ключ працуе"
else
  code=$?
  [ "$code" -eq 2 ] && echo "увайдзіце зноў"
  [ "$code" -eq 3 ] && echo "сервер не працуе, паспрабуйце пазней"
fi
```

## 6. Зменныя асяроддзя

### Bash / Zsh (Linux, macOS)

```bash
export OMI_API_KEY="omi_dev_ваш_ключ"

omi --json memory list --limit 10
```

Каб ключ загружаўся ў новых сесіях, дадайце радок у `~/.bashrc` або `~/.zshrc`.

### PowerShell (Windows)

```powershell
$env:OMI_API_KEY = "omi_dev_ваш_ключ"

# разбор JSON сродкамі PowerShell
(omi --json memory list | ConvertFrom-Json) | Select-Object id, content
```

Для пастаяннай налады:

```powershell
[Environment]::SetEnvironmentVariable("OMI_API_KEY", "omi_dev_ваш_ключ", "User")
```

## 7. Праграма Omi Desktop лакальна

Калі настольная праграма Omi запушчана, частка даных
даступная непасрэдна, без звароту да воблака.

```bash
# паказаць адрас лакальнага API
omi local configure --url http://127.0.0.1:47778 --token ВАШ_ТОКЕН

# праверыць, што ён адказвае
omi --json local status

# пошук у гісторыі экрана
omi --json local search-screen "цэны" --days 7 --app Safari

# скрыншот па ідэнтыфікатары
omi --json local screenshot 123 --output /tmp/omi-shot.jpg

# адвольны SQL да лакальнай базы
omi --json local sql "SELECT appName, COUNT(*) FROM screenshots GROUP BY appName"
```

Парадак дзеянняў: спачатку `local status`, потым `local tools` — каб убачыць
даступныя інструменты і іх параметры — і толькі потым выклікі.

## 8. Профілі

Калі ў вас некалькі ўліковых запісаў або асяроддзяў, раздзяляйце іх профілямі.
Налады захоўваюцца ў `~/.omi/config.toml`.

```bash
# уваход у асабісты профіль
omi --profile personal auth login

# уваход у працоўны профіль
omi --profile work auth login

# выканаць каманду ў пэўным профілі
omi --profile work memory list
```

Профіль вызначаецца ў такім парадку: параметр `--profile` (або `-p`) мае прыярытэт
над усім; затым зменная асяроддзя `OMI_PROFILE`; затым актыўны профіль, вызначаны ў
`~/.omi/config.toml`; і ў апошнюю чаргу профіль `default`.

Прагледзець і змяніць саму канфігурацыю:

```bash
# што наладжана цяпер
omi config show

# дзе знаходзіцца файл канфігурацыі
omi config path

# змяніць значэнне
omi config set api_base https://api.omi.me
```
