# omi-cli Кіраўніцтва па хуткім старце (Belarusian Quickstart)

> Практычнае кіраўніцтва па выкарыстанні Omi наўпрост з тэрмінала — створана для распрацоўшчыкаў і аўтаномных AI-агентаў.

`omi-cli` — гэта афіцыйны інтэрфейс каманднага радка (CLI) для API распрацоўшчыкаў [Omi](https://omi.me). Ён дае структураваны доступ да 4 асноўных рэсурсаў Omi: успамінаў (memories), размоў (conversations), задач / дзеянняў (action items) і мэт (goals).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Афіцыйная дакументацыя:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Зыходны код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

## 1. Усталяванне

Каб пазбегнуць канфліктаў сістэмных залежнасцей і забяспечыць ізаляванае асяроддзе, настойліва рэкамендуецца выкарыстоўваць `pipx`:

```bash
# Рэкамендаваны спосаб: ізаляванае ўсталяванне праз pipx
pipx install omi-cli

# Альтэрнатыўнае ўсталяванне праз стандартны pip (напрыклад, у віртуальным асяроддзі)
pip install omi-cli
```

> **Важнае ўдакладненне: назва пакета і назва каманды**
> * Афіцыйная назва пакета ў PyPI — **`omi-cli`** (пакет `omi` з'яўляецца асобным і іншым праектам).
> * Каманда, якая выконваецца ў тэрмінале, называецца проста: **`omi`**.

Праверце паспяховасць усталявання шляхам прагляду версіі і даведачнага меню:

```bash
omi --version
omi --help
```

## 2. Аўтэнтыфікацыя (Authentication)

`omi-cli` падтрымлівае два асноўныя спосабы аўтэнтыфікацыі:

| Метад | Прызначэнне | Прыклад каманды |
| :--- | :--- | :--- |
| **API-ключ распрацоўшчыка (`omi_dev_*`)** | Аўтаматызацыя, CI/CD, headless-серверы, AI-агенты | `omi auth login --api-key ...` або `OMI_API_KEY` |
| **OAuth-уваход праз браўзер (Google/Apple)** | Лакальная распрацоўка на персанальным камп'ютары | `omi auth login --browser` (Google) / `--provider apple` |

### Інтэрактыўны ўваход
Выкананне каманды без дадатковых сцягоў запускае інтэрактыўнае меню:

```bash
omi auth login
# 1) Browser — Уваход праз Google у браўзеры (для ўваходу праз Apple выкарыстоўвайце сцяг `--provider apple`)
# 2) API key — Устаўка API-ключа распрацоўшчыка з app.omi.me
```

### Прамы ўваход праз браўзер
```bash
# Стандартны ўваход праз акаўнт Google
omi auth login --browser

# Альтэрнатыўны ўваход праз профіль Apple
omi auth login --browser --provider apple
```

### Уваход з дапамогай API-ключа распрацоўшчыка
Стварыце API-ключ на панэлі кіравання [app.omi.me](https://app.omi.me) у раздзеле **Developer → API Keys**:

```bash
# Захаванне ключа ў бягучым лакальным профілі
omi auth login --api-key omi_dev_...

# Або праз пераменную асяроддзя (ідэальна для Docker і CI/CD):
# Заўвага: калі ў профілі ўжо захаваны ключ, спачатку выканайце `omi auth logout`.
export OMI_API_KEY="omi_dev_ваш_ключ_тут"
```

### Праверка стану аўтэнтыфікацыі
* `omi auth status`: Паказвае актыўны профіль і маскіраваны ідэнтыфікатар без сеткавых запытаў (працуе афлайн).
* `omi auth whoami`: Адпраўляе запыт да сервера Omi для праверкі сапраўднасці сесіі (патрабуе падключэння да інтэрнэту).

```bash
omi auth status
omi auth whoami
```

### Выхад з сістэмы (Logout)
```bash
omi auth logout
# Калі вы выкарыстоўвалі пераменную асяроддзя OMI_API_KEY, выдаліце яе з сесіі (Bash/Zsh: `unset OMI_API_KEY`).
```

## 3. Асноўныя каманды

### Успаміны (Memories)
Кантэкстныя нататкі і назіранні, захаваныя Omi:

```bash
# Прагляд спіса захаваных успамінаў
omi memory list

# Стварэнне новага ўспаміну
omi memory create "Аддае перавагу лаканічным і тэхнічна дакладным адказам з прыкладамі на Python" --category work

# Атрыманне канкрэтнага ўспаміну па ідэнтыфікатары
omi memory get <MEMORY_ID>
```

### Размовы (Conversations)
Запісаныя дыялогі і транскрыпцыі з прылад Omi:

```bash
# Спіс апошніх 5 размоў
omi conversation list --limit 5

# Атрыманне размовы разам з поўнай стэнаграмай
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Задачы і дзеянні (Action Items)
Аўтаматычна распазнаныя задачы з праведзеных гутарак:

```bash
# Спіс адкрытых задач
omi action-item list --open

# Пазначэнне задачы як выкананай
omi action-item complete <ACTION_ITEM_ID>
```

### Мэты (Goals)
Доўгатэрміновыя мэты і адсочванне прагрэсу:

```bash
# Спіс актыўных мэт
omi goal list

# Стварэнне колькаснай мэты
omi goal create "Піць па 2 літры вады штодня" --type numeric --target 2 --unit liters
```

## 4. Структураваная аўтаматызацыя і JSON-вывад (`--json`)

`omi-cli` аптымізаваны для сцэнарыяў аўтаматызацыі і інтэграцыі з AI-агентамі. Глабальны сцяг `--json` вяртае валідны JSON для апрацоўкі такімі ўтылітамі, як `jq`:

```bash
# Спіс успамінаў у фармаце JSON і фільтрацыя праз jq
omi --json memory list | jq '.[] | {id, content, category}'

# Атрыманне загалоўкаў апошніх размоў
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Вывад адкрытых задач у сырым выглядзе JSON
omi --json action-item list --open | jq '.'
```

> **Важнае правіла сінтаксісу:**
> Сцяг `--json` з'яўляецца **глабальнай опцыяй**, што азначае, што ён павінен пазначацца **перад** падкамандай:
> * Правільна: `omi --json memory list`
> * Няправільна: `omi memory list --json`

### Пагінацыя і экспарт у файлы
Выкарыстоўвайце параметры `--limit` і `--offset` для паслядоўнага атрымання вялікіх аб'ёмаў даных:

```bash
# Пагінацыя вынікаў
omi --json memory list --limit 25 --offset 0 > uspaminy-staronka-1.json
omi --json memory list --limit 25 --offset 25 > uspaminy-staronka-2.json
```

Перанакіраванне вываду ў файл перазапісвае або стварае файл лакальна. Заўсёды правярайце код выхаду каманды перад далейшай апрацоўкай. Паведамленні пра памылкі выводзяцца ў стандартны паток памылак (stderr), таму наяўнасць пустога файла не з'яўляецца гарантыяй адсутнасці даных. Экспартаваныя файлы могуць утрымліваць прыватную інфармацыю — абараняйце іх у адпаведнасці з правіламі бяспекі.

## 5. Коды выхаду (Exit Codes)

Надзейны перахоп памылак у скрыптах і канвеерах CI/CD:

| Код | Значэнне | Апісанне |
| :---: | :--- | :--- |
| `0` | **Поспех (`EXIT_OK`)** | Каманда выканана паспяхова без памылак. |
| `1` | **Памылка выкарыстання / сінтаксісу (`EXIT_USAGE`)** | Няправільныя значэнні, невядомыя сцягі Click або адсутныя аргументы. |
| `2` | **Памылка аўтэнтыфікацыі (`EXIT_AUTH`)** | Адсутнічаюць уліковыя даныя, скончыўся тэрмін дзеяння ключа або недастаткова правоў. |
| `3` | **Серверная або сеткавая памылка (`EXIT_SERVER`)** | Адказ HTTP 5xx, страта злучэння або таймаўт запыту. |
| `4` | **Абмежаванне запытаў (`EXIT_RATE_LIMITED`)** | Адказ HTTP 429 — занадта шмат запытаў за кароткі прамежак часу. |
| `5` | **Рэсурс не знойдзены (`EXIT_NOT_FOUND`)** | Адказ HTTP 404 — запытаны аб'ект не існуе. |

## 6. Прыклады для розных тэрмінальных асяроддзяў

### Bash / Zsh (Linux / macOS)
```bash
export OMI_API_KEY="omi_dev_ваш_ключ_тут"

# Выкананне каманды і праверка кода выхаду
omi --json memory list --limit 10
if [ $? -ne 0 ]; then
    echo "Адбылася памылка пры атрыманні ўспамінаў." >&2
fi
```

### PowerShell (Windows)
```powershell
$env:OMI_API_KEY = "omi_dev_ваш_ключ_тут"

# Пераўтварэнне вываду JSON непасрэдна ў аб'ект PowerShell
$memories = omi --json memory list | ConvertFrom-Json
$memories | Select-Object id, content, category

# Праверка на наяўнасць памылак праз $LASTEXITCODE
if ($LASTEXITCODE -ne 0) {
    Write-Error "Каманда Omi завяршылася з кодам памылкі: $LASTEXITCODE."
}
```

## 7. Інтэграцыя з лакальнай праграмай для працоўнага стала (Local Desktop API)

Калі дэсктопная праграма Omi запушчана на тым жа камп'ютары, вы можаце рабіць запыты да лакальнай гісторыі экрана без звароту да воблака:

```bash
# Заданне лакальнага адраса і токена доступу
export OMI_LOCAL_API_URL="http://127.0.0.1:47778"
read -r -s -p "Увядзіце дэсктопны токен: " OMI_LOCAL_TOKEN; echo
export OMI_LOCAL_TOKEN

# Праверка стану лакальнай службы
omi --json local status

# Пошук у гісторыі экрана
omi --json local search-screen "Квартальная справаздача" --days 7 --app Safari
```

## 8. Праца з некалькімі профілямі (Profiles)

Сцяг `--profile` дазваляе падзяляць працоўныя, асабістыя акаўнты або тэставыя асяроддзі. Канфігурацыя захоўваецца ў файле `~/.omi/config.toml`:

```bash
# Стварэнне і ўваход у асабісты профіль
omi --profile personal auth login

# Стварэнне і ўваход у працоўны профіль
omi --profile work auth login

# Выкананне каманды ад імя пэўнага профілю
omi --profile work memory list

# Выкарыстанне тэставага асяроддзя (staging)
omi --profile staging --api-base https://api.staging.omi.me memory list
```

## 9. Бяспека і лепшыя практыкі

* **Не захоўвайце ключы ў Git:** Ніколі не дадавайце API-ключы ў публічныя рэпазіторыі; выкарыстоўвайце менеджэры сакрэтаў або файлы асяроддзя, пазначаныя ў `.gitignore`.
* **Абарона гісторыі тэрмінала:** На агульных машынах пазбягайце перадачы ключоў праз параметры каманд; выкарыстоўвайце інтэрактыўны ўваход альбо пераменную `OMI_API_KEY`.
* **Правы доступу да файлаў:** У асяроддзі Unix усталёўвайце строгія правы доступу да каталога канфігурацыі `~/.omi/` (`chmod 700 ~/.omi`).
