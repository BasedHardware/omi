# คู่มือเริ่มต้นอย่างรวดเร็ว omi-cli (ภาษาไทย)

> คู่มือเชิงปฏิบัติสำหรับการโต้ตอบกับ Omi จากเทอร์มินัล เหมาะสำหรับทั้งมนุษย์และเอเจนต์ AI

`omi-cli` เป็นอินเทอร์เฟซบรรทัดคำสั่งอย่างเป็นทางการสำหรับการโต้ตอบกับ API สำหรับนักพัฒนาของ [Omi](https://omi.me) จัดการทรัพยากรหลักสี่อย่างของ Omi — **ความทรงจำ การสนทนา รายการดำเนินการ และเป้าหมาย** — อย่างมีประสิทธิภาพและเขียนสคริปต์ได้

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **เอกสารอย่างเป็นทางการ:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **ซอร์สโค้ด:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. การติดตั้ง

วิธีการติดตั้งที่แนะนำคือใช้ `pipx` เพื่อแยกการพึ่งพา

```bash
# แนะนำ: ติดตั้งด้วย pipx
pipx install omi-cli

# หรือใช้ pip
pip install omi-cli
```

> **สำคัญ: ความแตกต่างระหว่างชื่อแพ็คเกจและชื่อคำสั่ง**
> * แพ็คเกจ Python ที่ติดตั้งชื่อ **`omi-cli`** (แพ็คเกจ `omi` แบบสแตนด์อโลนเป็นแพ็คเกจอื่นที่ไม่เกี่ยวข้อง)
> * คำสั่งที่รันได้ในเทอร์มินัลหลังการติดตั้งชื่อ **`omi`**

หลังการติดตั้ง ตรวจสอบเวอร์ชันและความช่วยเหลือ

```bash
omi --version
omi --help
```

## 2. การยืนยันตัวตน

`omi-cli` รองรับวิธีการยืนยันตัวตนสองวิธี

| วิธี | การใช้งานที่แนะนำ | ตัวอย่างคำสั่ง |
| :--- | :--- | :--- |
| **คีย์ API สำหรับนักพัฒนา (`omi_dev_*`)** | CI/CD, สคริปต์อัตโนมัติ, เอเจนต์ AI | `omi auth login --api-key ...` หรือตัวแปรสภาพแวดล้อม |
| **OAuth ในเบราว์เซอร์ (Google/Apple)** | PC / แล็ปท็อปของนักพัฒนา | `omi auth login --browser` |

### การเข้าสู่ระบบแบบโต้ตอบ
หากไม่มีตัวเลือก ระบบจะขอให้คุณเลือกระหว่างการเข้าสู่ระบบผ่านเบราว์เซอร์หรือการป้อนคีย์ API

```bash
omi auth login
# 1) เบราว์เซอร์ — เข้าสู่ระบบด้วยบัญชี Google หรือ Apple (สำหรับมนุษย์)
# 2) คีย์ API — วางคีย์นักพัฒนาจาก app.omi.me (สำหรับเอเจนต์/CI)
```

### การเข้าสู่ระบบผ่านเบราว์เซอร์โดยตรง
```bash
omi auth login --browser
```

### การใช้คีย์ API
รับคีย์นักพัฒนาจาก **Developer → API Keys** บน [app.omi.me](https://app.omi.me) แล้วตั้งค่า

```bash
# ตั้งผ่านคำสั่ง
omi auth login --api-key omi_dev_...

# หรือผ่านตัวแปรสภาพแวดล้อม (เหมาะสำหรับ CI/CD หรือคอนเทนเนอร์)
export OMI_API_KEY=omi_dev_...
```

### ตรวจสอบสถานะการยืนยันตัวตน
* `omi auth status`: แสดงโปรไฟล์ในเครื่อง โทเค็นที่ถูกปิดบัง และวันหมดอายุ (ทำงานแบบออฟไลน์)
* `omi auth whoami`: ส่งคำขอยืนยันตัวตนจริงไปยังเซิร์ฟเวอร์ Omi (ต้องมีการเชื่อมต่อเครือข่าย)

```bash
omi auth status
omi auth whoami
```

หากต้องการออกจากระบบ:
```bash
omi auth logout
```

## 3. การใช้งานพื้นฐาน

คุณสามารถแสดงรายการและจัดการทรัพยากรหลักสี่อย่างของ Omi

### ความทรงจำ (Memories)
จัดการข้อเท็จจริงและความรู้ที่ระบบเรียนรู้

```bash
# แสดงความทรงจำทั้งหมด
omi memory list

# สร้างความทรงจำใหม่
omi memory create "ผู้ใช้ชอบโหมดมืด" --category lifestyle

# แสดงรายละเอียดของความทรงจำเฉพาะ
omi memory get <MEMORY_ID>
```

### การสนทนา (Conversations)
ประวัติเสียงหรือข้อความของการสนทนาที่บันทึกโดยอุปกรณ์สวมใส่หรือแอป

```bash
# รับการสนทนา 5 รายการล่าสุด
omi conversation list --limit 5

# แสดงรายละเอียดการสนทนาและการถอดเสียง
omi conversation get <CONVERSATION_ID> --include-transcript
```

### รายการดำเนินการ (Action Items)
งานหรือรายการติดตามที่ดึงมาจากการสนทนาโดยอัตโนมัติ

```bash
# แสดงเฉพาะรายการดำเนินการที่เปิดอยู่
omi action-item list --open

# ทำเครื่องหมายรายการดำเนินการว่าเสร็จสิ้น
omi action-item complete <ACTION_ITEM_ID>
```

### เป้าหมาย (Goals)
จัดการเป้าหมายที่มีการติดตามความคืบหน้า

```bash
# แสดงเป้าหมายทั้งหมด
omi goal list
```

## 4. การประมวลผลสคริปต์และเอาต์พุต JSON (`--json`)

`omi-cli` รองรับเอาต์พุต JSON โดยธรรมชาติ เมื่อใช้ร่วมกับ `jq` หรือสคริปต์ Python **ตัวเลือกส่วนกลาง** `--json` ต้องอยู่ก่อนคำสั่งย่อย

```bash
# รับรายการความทรงจำเป็น JSON และแยก ID และเนื้อหา
omi --json memory list | jq '.[] | {id, content, category}'

# รับชื่อเรื่องของการสนทนา 5 รายการล่าสุด
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# แสดงรายการดำเนินการที่เปิดอยู่
omi --json action-item list --open | jq '.[] | {id, description, due_at}'

# แสดงเป้าหมาย
omi --json goal list | jq '.[] | {id, title, current: .current_value, target: .target_value}'
```

## 5. การวินิจฉัยเซสชัน

ใช้สองคำสั่งนี้คู่กันเพื่อแก้ปัญหาอย่างรวดเร็ว

```bash
# 1) ตรวจสอบการกำหนดค่าในเครื่องก่อน
omi auth status

# 2) ยืนยันกับเซิร์ฟเวอร์ Omi
omi auth whoami

# 3) หากจำเป็น ให้เริ่มการเข้าสู่ระบบใหม่
omi auth login
```

## 6. แนวปฏิบัติที่ดีที่สุด

* **ใช้ `--json` ในสคริปต์:** หลีกเลี่ยงการแยกวิเคราะห์ข้อความอิสระ พึ่งพาเอาต์พุต JSON ที่มีโครงสร้างเสมอ
* **แยกสภาพแวดล้อมด้วย `pipx`:** หลีกเลี่ยงความขัดแย้งของการพึ่งพากับแพ็คเกจ Python อื่นๆ
* **อย่าแบ่งปันคีย์ API:** คีย์ `omi_dev_*` ให้สิทธิ์เข้าถึงบัญชีเต็มรูปแบบ จัดเก็บไว้ในตัวจัดการความลับหรือตัวแปรสภาพแวดล้อม
* **ออกจากระบบจากอุปกรณ์ที่ใช้ร่วมกัน:** ใช้ `omi auth logout` หลังจากใช้งานบนเครื่องที่ใช้ร่วมกัน

## 7. การแก้ปัญหา

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
| :--- | :--- | :--- |
| `command not found: omi` | PATH ไม่มีไดเรกทอรี bin ของ pipx | รัน `pipx ensurepath` และรีสตาร์ทเทอร์มินัล |
| `401 Unauthorized` | คีย์ API ไม่ถูกต้องหรือหมดอายุ | สร้างคีย์ใหม่บน app.omi.me และอัปเดต |
| `connection refused` | ไม่มีการเข้าถึงเครือข่ายไปยังเซิร์ฟเวอร์ Omi | ตรวจสอบการเชื่อมต่ออินเทอร์เน็ตและการตั้งค่าพร็อกซี |
| `permission denied` บนไฟล์การกำหนดค่า | ไดเรกทอรีการกำหนดค่าไม่สามารถเขียนได้ | ตรวจสอบสิทธิ์ของ `~/.omi/config.toml` |
