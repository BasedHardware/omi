# เริ่มต้นใช้งาน omi-cli

คู่มือนี้สรุปคำสั่งแรก ๆ ของ omi-cli เป็นภาษาไทย ชื่อคำสั่งและข้อความของโปรแกรมยังคงเป็นภาษาอังกฤษ ตัวอย่างคำสั่งในคู่มือนี้ไม่แก้ไขความทรงจำ บทสนทนา รายการสิ่งที่ต้องทำ หรือเป้าหมายของคุณ

> `README.md` ฉบับภาษาอังกฤษยังคงเป็นแหล่งอ้างอิงหลัก (source of truth)
> สำหรับทุกอย่างที่สรุปไว้สั้น ๆ ที่นี่

## การติดตั้ง

ต้องมี Python 3.10 ขึ้นไป และบัญชี Omi

ถ้าติดตั้ง `pipx` ไว้แล้ว:

```sh
pipx install omi-cli
omi --help
```

หรือติดตั้งภายใน virtual environment ที่เปิดใช้งานอยู่:

```sh
python -m pip install omi-cli
omi --help
```

หมายเหตุ: ชื่อแพ็กเกจ Python คือ `omi-cli` ส่วนคำสั่งที่พิมพ์ในเทอร์มินัลคือ `omi` อย่าติดตั้งแพ็กเกจชื่อ `omi` จาก PyPI — เป็นแพ็กเกจอื่นที่ไม่เกี่ยวข้อง ถ้าเทอร์มินัลหา `omi` ไม่เจอ ให้ตรวจสอบว่าเปิดใช้งาน virtual environment อยู่ หรือโฟลเดอร์ที่ `pipx` ติดตั้งไฟล์รันคำสั่งอยู่ใน `PATH` แล้ว

## การเข้าสู่ระบบ

เริ่มเข้าสู่ระบบแบบโต้ตอบ:

```sh
omi auth login
```

เลือกได้ระหว่างเข้าสู่ระบบผ่านเบราว์เซอร์ หรือวางคีย์ API สำหรับนักพัฒนา การป้อนแบบโต้ตอบจะซ่อนคีย์ — เลี่ยงการพิมพ์คีย์ลงในคำสั่งโดยตรง เพราะคำสั่งนั้นจะถูกบันทึกไว้ในประวัติของเทอร์มินัล

เข้าสู่ระบบผ่านเบราว์เซอร์โดยตรง:

```sh
omi auth login --browser
```

ควรเข้าสู่ระบบบนเครื่องเดียวกับที่รันเทอร์มินัล เพราะการตอบกลับใช้ที่อยู่ภายในเครื่อง ปฏิบัติตามคำแนะนำที่แสดงบนหน้าจอ

เมื่อเข้าสู่ระบบเสร็จแล้ว ตรวจสอบการตั้งค่าและการเข้าถึง API:

```sh
omi auth status
omi auth whoami
```

`status` แสดงสถานะในเครื่องและปิดบังส่วนที่เป็นความลับ แต่ไม่ได้ตรวจสอบว่าข้อมูลรับรองยังใช้ได้บนเซิร์ฟเวอร์หรือไม่ ส่วน `whoami` จะส่งคำขอที่ยืนยันตัวตนแล้ว หากสำเร็จจะยืนยันว่าข้อมูลรับรองใช้งานได้ แม้อาจไม่แสดงชื่อของคุณ

การตั้งค่าถูกบันทึกไว้ที่ `~/.omi/config.toml` ตามค่าเริ่มต้น อย่าแชร์ไฟล์นี้ — ไฟล์อาจมีข้อมูลรับรองของคุณอยู่

สำหรับงานอัตโนมัติ ใช้ตัวแปรสภาพแวดล้อม `OMI_API_KEY` ได้เมื่อโปรไฟล์ที่ใช้งานอยู่ไม่มีคีย์บันทึกไว้ มิฉะนั้นระบบจะใช้คีย์จากโปรไฟล์:

```sh
export OMI_API_KEY=omi_dev_...
omi memory list
```

ต้องการออกจากระบบ ให้รัน `omi auth logout` — คำสั่งนี้ลบข้อมูลรับรองที่บันทึกไว้ในเครื่องเท่านั้น หากต้องการเพิกถอนคีย์บนเซิร์ฟเวอร์ ให้ใช้หน้าจัดการคีย์สำหรับนักพัฒนาในบัญชีของคุณ

## ดูข้อมูลของคุณ

```sh
omi memory list --limit 5
omi conversation list --limit 5
omi action-item list --open
omi goal list
```

รายการว่างอาจหมายความง่าย ๆ ว่าไม่มีรายการที่ตรงกับเงื่อนไข ดูตัวกรองของแต่ละคำสั่งได้จากหน้าช่วยเหลือ:

```sh
omi memory list --help
omi action-item list --help
```

## เอาต์พุต JSON และการแบ่งหน้า

วางตัวเลือกส่วนกลาง `--json` **ไว้ก่อน**กลุ่มคำสั่ง:

```sh
omi --json memory list --limit 25 --offset 0
omi --json memory list --limit 25 --offset 25
```

คำสั่งแรกขอความทรงจำ 25 รายการแรก ส่วนคำสั่งที่สองขอ 25 รายการถัดไป ดังนั้นหน้าเดียวจึงไม่ใช่สำเนาข้อมูลทั้งหมด เอาต์พุต JSON เก็บตัวระบุ (ID) แบบเต็ม ขณะที่ตารางอาจย่อ ID เพื่อให้อ่านง่าย

การบันทึกหนึ่งหน้าไว้ในไฟล์:

```sh
omi --json memory list --limit 25 --offset 0 > memories-page-1.json
```

การเปลี่ยนเส้นทางแบบนี้จะสร้างหรือเขียนทับไฟล์ในเครื่อง ตรวจสอบว่าคำสั่งทำงานสำเร็จก่อนนำเนื้อหาไปใช้ ข้อผิดพลาดจะถูกเขียนไปยังเอาต์พุตข้อผิดพลาด (standard error) — ไฟล์ว่างไม่ได้แปลว่าไม่มีข้อมูล ไฟล์ที่ส่งออกอาจมีข้อมูลส่วนตัว ควรเก็บไว้เป็นความลับ

## โปรไฟล์

ถ้าใช้หลายบัญชีหรือหลายสภาพแวดล้อม ให้ใช้ตัวเลือก `--profile` (หรือ `-p`):

```sh
omi --profile work auth login
omi --profile work memory list
```

ถ้าไม่ระบุ ระบบจะใช้โปรไฟล์จากตัวแปร `OMI_PROFILE` ก่อน แล้วจึงใช้โปรไฟล์ที่ใช้งานอยู่จากไฟล์ตั้งค่า (ค่าเริ่มต้นคือ `default`) โปรไฟล์ทั้งหมดถูกเก็บไว้ใน `~/.omi/config.toml`

## รหัสออก (Exit Codes)

สำหรับสคริปต์และงานอัตโนมัติ CLI กำหนดรหัสออกที่แน่นอนไว้:

| รหัส | ความหมาย | รายละเอียด |
| :---: | :--- | :--- |
| `0` | สำเร็จ | คำสั่งทำงานเสร็จสมบูรณ์ |
| `1` | ข้อผิดพลาดในการใช้คำสั่ง | CLI ตรวจพบการใช้ผิดวิธี เช่น ใช้ตัวเลือกที่ใช้ร่วมกันไม่ได้ |
| `2` | ข้อผิดพลาดด้านการยืนยันตัวตนหรืออาร์กิวเมนต์ | ไม่มีข้อมูลรับรอง โทเคนหมดอายุ หรือสิทธิ์ไม่เพียงพอ รวมถึงข้อผิดพลาดด้านอาร์กิวเมนต์ (ตัวเลือกไม่รู้จัก อาร์กิวเมนต์หายไป ค่านอกช่วง) |
| `3` | ข้อผิดพลาดของเซิร์ฟเวอร์ | การตอบกลับ 5xx การเชื่อมต่อล้มเหลว ปัญหาเครือข่าย |
| `4` | ถูกจำกัดอัตราการเรียกใช้ | 429 Too Many Requests |
| `5` | ไม่พบข้อมูล | 404 Not Found (ไม่พบ ID ที่ขอ) |

รหัส `4` มักเป็นชั่วคราว — รอสักครู่แล้วลองใหม่ CLI จะลองคำขอที่ถูกจำกัดอัตรา (429) ให้อัตโนมัติ และปฏิบัติตาม `Retry-After` เมื่อเซิร์ฟเวอร์ส่งมา รหัส `3` มักเป็นชั่วคราวสำหรับการอ่าน แต่สำหรับการเขียนอาจหมายความว่าผลลัพธ์ไม่ทราบแน่ชัด (`outcome unknown`) — เซิร์ฟเวอร์อาจใช้การเปลี่ยนแปลงไปแล้ว ตรวจสอบทรัพยากรก่อนลองใหม่ รหัส `2` มีสาเหตุพบบ่อยสองแบบ: ถ้าข้อความแสดงปัญหาการยืนยันตัวตน (ไม่มีข้อมูลรับรองหรือโทเคนหมดอายุ) ให้รัน `omi auth login` ใหม่ แต่ถ้าเป็นข้อผิดพลาดด้านอาร์กิวเมนต์ (ตัวเลือกไม่รู้จัก อาร์กิวเมนต์หายไป ค่านอกช่วง) ให้แก้ไขคำสั่ง รหัส `5` หมายความว่า ID ที่ขอไม่มีอยู่หรือไม่สามารถเข้าถึงได้

สำหรับคำสั่งอื่น ๆ และตัวเลือกขั้นสูง ดู [README หลักฉบับภาษาอังกฤษ](../README.md) และ `omi --help`
