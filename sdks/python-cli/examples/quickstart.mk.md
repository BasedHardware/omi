# omi-cli Упатство за брз почеток (Macedonian Quickstart)

> Практичен водич за користење на Omi директно од терминалот — наменет за програмери и автономни агенти за вештачка интелигенција (AI).

`omi-cli` е официјалниот интерфејс на командна линија (CLI) за програмерскиот API на [Omi](https://omi.me). Овозможува структуриран пристап до 4-те клучни ресурси на Omi: спомени (*memories*), разговори (*conversations*), акциони точки и задачи (*action items*) и цели (*goals*).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Официјална документација:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Изворен код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Инсталација

За да обезбедите изолирана средина и да спречите конфликти со системските Python зависности, силно се препорачува користење на алатката `pipx`:

```bash
# Препорачан метод: изолирана инсталација преку pipx
pipx install omi-cli

# Алтернативна инсталација со pip (на пр. во виртуелна средина)
pip install omi-cli
```

> **Важно појаснување: Име на пакетот во споредба со името на командата**
> * Официјалното име на пакетот на PyPI е **`omi-cli`** (пакетот со име `omi` е сосема различен и неповрзан проект).
> * Командата што се извршува во терминалот е директно: **`omi`**.

Проверете ја инсталацијата со прикажување на верзијата и помошното мени:

```bash
omi --version
omi --help
```

## 2. Автентикација (Authentication)

`omi-cli` поддржува два главни методи за потврда на идентитетот:

| Метод | Идеална намена | Пример на команда |
| :--- | :--- | :--- |
| **Развојнички API клуч (`omi_dev_*`)** | Скрипти, CI/CD процеси, сервери, AI агенти | `omi auth login --api-key ...` или `OMI_API_KEY` |
| **OAuth најава преку прелистувач** | Локален развој на личен компјутер | `omi auth login --browser` (Google) / `--provider apple` |

### Интерактивна најава

Извршувањето на командата без дополнителни знаменца отвора интерактивно мени:

```bash
omi auth login
# 1) Browser — Најава преку прелистувач (Google или Apple)
# 2) API key — Внесување на развојнички клуч од app.omi.me
```

### Најава преку веб-прелистувач

```bash
# Стандардна најава со Google сметка
omi auth login --browser

# Алтернативна најава со Apple сметка
omi auth login --browser --provider apple
```

### Најава со развојнички API клуч

Генерирајте API клуч на контролната табла [app.omi.me](https://app.omi.me) во делот **Developer → API Keys**:

```bash
# Зачувување на клучот во тековниот локален профил
omi auth login --api-key omi_dev_vasiot_kluc_tuka

# Или поставување како променлива на средината (препорачано за Docker и CI/CD процеси):
export OMI_API_KEY="omi_dev_vasiot_kluc_tuka"
```

> **Безбедносна забелешка и приоритет:**
> * Користењето на знаменцето `--api-key` директно во командната линија го остава клучот видлив во историјата на терминалот (`shell history`) и табелата на системски процеси. На споделени машини претпочитајте интерактивно внесување (`omi auth login`) или променливата на средината `OMI_API_KEY`.
> * Доколку активниот профил веќе има зачуван клуч во конфигурацијата, тој има предност пред променливата на средината. За користење на `OMI_API_KEY`, прво одјавете се со `omi auth logout` или користете нов профил.

### Проверка на статусот на сесијата

* `omi auth status`: Го прикажува активниот профил и маскираниот идентификатор од локалната конфигурација (работи офлајн).
* `omi auth whoami`: Испраќа мрежно барање до серверите на Omi за потврда на валидноста на сесијата.

```bash
omi auth status
omi auth whoami
```

### Одјава (Logout)

За отстранување на локално зачуваните акредитиви:

```bash
omi auth logout
# Доколку сте ја користеле променливата OMI_API_KEY, отстранете ја од сесијата:
unset OMI_API_KEY
```

> **Безбедносна забелешка:** Конфигурацијата се чува во датотеката `~/.omi/config.toml`. На Unix/Linux системи, се препорачува ограничување на дозволите: `chmod 700 ~/.omi && chmod 600 ~/.omi/config.toml`.

## 3. Основни команди

### Спомени (Memories)

Зачувување и пребарување на трајни контекстуални забелешки и факти:

```bash
# Список на зачувани спомени
omi memory list

# Создавање нов спомен
omi memory create "Корисникот претпочита концизни технички одговори со примери во Python" --category work

# Преземање на конкретен спомен според идентификатор
omi memory get <ID_НА_СПОМЕН>
```

### Разговори (Conversations)

Аудио записи и текстуални транскрипции од Omi уредите:

```bash
# Список на последните 5 разговори
omi conversation list --limit 5

# Преземање разговор заедно со целосниот транскрипт
omi conversation get <ID_НА_РАЗГОВОР> --include-transcript
```

### Акциони точки и задачи (Action Items)

Задачи и заклучоци автоматски препознаени од разговорите:

```bash
# Список на отворени задачи
omi action-item list --open

# Означување на задача како завршена
omi action-item complete <ID_НА_ЗАДАЧА>
```

### Цели (Goals)

Следење на долгорочни цели и напредок:

```bash
# Список на активни цели
omi goal list

# Создавање нова нумеричка цел (насловот се наведува како позиционен аргумент)
omi goal create "Дневен внес на вода" --type numeric --target 2500 --unit "ml"
```

## 4. Структурирана автоматизација и JSON излез (`--json`)

`omi-cli` е прилагоден за лесна интеграција во скрипти и автоматизирани AI процеси. Глобалното знаменце `--json` обезбедува чист JSON излез погоден за обработка со алатки како `jq`:

```bash
# Преземање спомени во JSON формат и филтрирање со jq
omi --json memory list | jq '.[] | {id, content, category}'

# Извлекување на насловите на последните 5 разговори
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Список на отворени задачи
omi --json action-item list --open | jq '.'
```

> **Клучно правило за синтакса:**
> Знаменцето `--json` е **глобална опција** и мора секогаш да стои **пред** поткомандата:
> * Точно: `omi --json memory list`
> * Грешно: `omi memory list --json`

### Пагинација и извоз на податоци

При работа со поголеми количини податоци користете ги параметрите `--limit` и `--offset`:

```bash
# Преземање на податоците по страници
omi --json memory list --limit 25 --offset 0 > spomeni-stranica-1.json
omi --json memory list --limit 25 --offset 25 > spomeni-stranica-2.json
```

Пренасочувањето во датотека создава или препишува локална датотека. Секогаш проверувајте го излезниот код на командата пред обработката. Пораките за грешка одат во стандардниот тек за грешки (`stderr`), па празна датотека не гарантира отсуство на податоци. Извезените датотеки може да содржат доверливи податоци — чувајте ги во согласност со безбедносните прописи.

## 5. Излезни кодови (Exit Codes Contract)

`omi-cli` следи прецизен договор за излезни кодови за сигурно справување со грешки во скрипти и CI/CD системи (согласно `omi_cli/errors.py`):

| Код | Ознака | Значење и опис |
| :---: | :--- | :--- |
| `0` | **Успех (`EXIT_OK`)** | Командата се изврши успешно без грешки. |
| `1` | **Грешка при користење / Валидација (`EXIT_USAGE`)** | Валидациска грешка на ниво на апликација (`UsageError`, на пр. истовремено користење на заемно исклучувачките опции `--browser` и `--api-key`). |
| `2` | **Грешка при автентикација / Парсер (`EXIT_AUTH`)** | Недостасуваат акредитиви, истечен клуч или недоволни овластувања. Синтаксни грешки и невалидни вредности на опциите на Click/Typer парсерот (непознати опции, вредности надвор од опсег за `--limit`, невалидни вредности за избор или недостасувачки аргументи) исто така враќаат код 2. |
| `3` | **Серверска или мрежна грешка (`EXIT_SERVER`)** | HTTP 5xx одговор од Omi серверот или прекин на мрежната врска. |
| `4` | **Надминат лимит на барања (`EXIT_RATE_LIMITED`)** | HTTP 429 одговор — премногу испратени барања во краток временски интервал. |
| `5` | **Ресурсот не е пронајден (`EXIT_NOT_FOUND`)** | HTTP 404 одговор — побараниот ресурс не постои. |

## 6. Примери за различни терминалски средини

### Bash / Zsh (Linux и macOS)

```bash
#!/usr/bin/env bash
set -euo pipefail

if omi --json memory list --limit 5 > /tmp/memories.json; then
    echo "Успешно преземени $(jq 'length' /tmp/memories.json) спомени."
else
    code=$?
    echo "Грешка при преземање на спомените (излезен код: $code)" >&2
    exit "$code"
fi
```

### PowerShell (Windows / macOS / Linux)

```powershell
$ErrorActionPreference = "Continue"

omi --json memory list --limit 5 | Out-File -FilePath "$env:TEMP\memories.json" -Encoding utf8
if ($LASTEXITCODE -ne 0) {
    Write-Error "Командата не успеа со излезен код $LASTEXITCODE"
    exit $LASTEXITCODE
}
Write-Host "Податоците се успешно зачувани."
```

### Windows Command Prompt (`cmd.exe`)

```cmd
omi --json memory list --limit 5 > "%TEMP%\memories.json"
if %ERRORLEVEL% NEQ 0 (
    echo Настана грешка со излезен код %ERRORLEVEL%
    exit /b %ERRORLEVEL%
)
echo Операцијата заврши успешно.
```

## 7. Управување со профили и тестна средина (Staging)

Опцијата `--profile` овозможува водење на повеќе независни конфигурации (на пр. лична, работна или тестна). За тестната средина можете трајно да ја поставите базната URL адреса на профилот:

```bash
# Трајно поставување на базната URL адреса за staging профилот
omi --profile staging config set api_base https://api.staging.omi.me

# Најава во профилот за тестна средина (staging)
omi --profile staging auth login --api-key omi_dev_staging_kluc

# Извршување на команда во staging профилот (трајно насочен кон staging средината)
omi --profile staging memory list

# Или привремено надминување за конкретна поединечна команда:
# omi --profile staging --api-base https://api.staging.omi.me memory list
```

> **Важна забелешка за `--api-base`:** Знаменцето `--api-base` служи само како привремено надминување за таа конкретна команда и не се зачувува автоматски во конфигурацијата. За постојана употреба користете `config set api_base <url>`.

## 8. Интеграција со локалниот десктоп API (Local Desktop API)

Доколку десктоп апликацијата Omi се извршува на истиот компјутер, можете да комуницирате директно со локалниот сервер без испраќање податоци на облак. Пред извршување на `omi local status` или пребарувања, осигурајте се дека се поставени адресата и безбедносниот токен:

```bash
# 1. Поставување на локална адреса (стандардна порта 47778) и токен:
export OMI_LOCAL_API_URL="http://127.0.0.1:47778"
export OMI_LOCAL_TOKEN="vasiot_lokalen_zeton"

# Или трајно зачувување во профилот:
# omi local configure --url http://127.0.0.1:47778 --token "vasiot_lokalen_zeton"

# 2. Проверка на состојбата на локалната услуга (бара претходно поставени параметри)
omi local status

# 3. Пребарување низ историјата на екранот по барање и апликација
omi local search-screen "неделен состанок" --days 1 --app "Slack"
```

## 9. Безбедност и најдобри практики

1. **Позиција на знаменцето `--json`:** Секогаш наведувајте го пред поткомандата (`omi --json memory list`).
2. **Обработка на излезни кодови:** Во автоматизација секогаш следете ги и обработувајте ги кодовите од 1 до 5.
3. **Безбедност на акредитиви:** Никогаш не поставувајте API клучеви во јавни складишта. Во продукција и CI/CD користете ја променливата `OMI_API_KEY`.
