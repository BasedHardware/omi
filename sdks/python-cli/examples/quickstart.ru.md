# Краткое руководство omi-cli (Русский)

> Практическое руководство по взаимодействию с Omi из терминала. Подходит как для людей, так и для AI-агентов.

`omi-cli` — это официальный интерфейс командной строки для взаимодействия с API разработчика [Omi](https://omi.me). Он эффективно и скриптуемо обрабатывает четыре ключевых ресурса Omi — **воспоминания, разговоры, элементы действий и цели**.

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Официальная документация:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Исходный код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Установка

Рекомендуемый метод установки использует `pipx` для изоляции зависимостей.

```bash
# Рекомендуется: установка через pipx
pipx install omi-cli

# Альтернативно: используйте pip
pip install omi-cli
```

> **Важно: разница между именем пакета и именем команды**
> * Устанавливаемый Python-пакет называется **`omi-cli`** (автономный пакет `omi` — это другой, несвязанный пакет).
> * Исполняемая команда в терминале после установки называется **`omi`**.

После установки проверьте версию и справку.

```bash
omi --version
omi --help
```

## 2. Аутентификация

`omi-cli` поддерживает два способа аутентификации.

| Способ | Рекомендуемое использование | Пример команды |
| :--- | :--- | :--- |
| **API-ключ разработчика (`omi_dev_*`)** | CI/CD, автоматизированные скрипты, AI-агенты | `omi auth login --api-key ...` или переменная среды |
| **OAuth в браузере (Google/Apple)** | ПК разработчика / ноутбук | `omi auth login --browser` |

### Интерактивный вход
Без опций вам будет предложено выбрать между входом через браузер и вводом API-ключа.

```bash
omi auth login
# 1) Браузер — войдите с помощью учётной записи Google или Apple (для людей)
# 2) API-ключ — вставьте ключ разработчика из app.omi.me (для агентов/CI)
```

### Прямой вход через браузер
```bash
omi auth login --browser
```

### Использование API-ключа
Получите ключ разработчика в **Developer → API Keys** на [app.omi.me](https://app.omi.me), а затем настройте его.

```bash
# Установить через команду
omi auth login --api-key omi_dev_...

# Или через переменную среды (идеально для CI/CD или контейнеров)
export OMI_API_KEY=omi_dev_...
```

### Проверка статуса аутентификации
* `omi auth status`: показывает локальный профиль, замаскированный токен и дату истечения (работает офлайн).
* `omi auth whoami`: отправляет реальный запрос аутентификации на сервер Omi (требуется подключение к сети).

```bash
omi auth status
omi auth whoami
```

Чтобы выйти:
```bash
omi auth logout
```

## 3. Базовое использование

Вы можете перечислять и управлять четырьмя ключевыми ресурсами Omi.

### Воспоминания (Memories)
Управляйте фактами и знаниями, которые система усвоила.

```bash
# Перечислить все воспоминания
omi memory list

# Создать новое воспоминание
omi memory create "Пользователь предпочитает тёмный режим" --category lifestyle

# Показать детали конкретного воспоминания
omi memory get <MEMORY_ID>
```

### Разговоры (Conversations)
История аудио или текста разговоров, записанных носимым устройством или приложением.

```bash
# Получить последние 5 разговоров
omi conversation list --limit 5

# Показать детали разговора и транскрипцию
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Элементы действий (Action Items)
Задачи или последующие пункты, автоматически извлечённые из разговоров.

```bash
# Перечислить только открытые элементы действий
omi action-item list --open

# Отметить элемент действия как завершённый
omi action-item complete <ACTION_ITEM_ID>
```

### Цели (Goals)
Управляйте целями, чей прогресс отслеживается.

```bash
# Перечислить все цели
omi goal list
```

## 4. Обработка скриптов и вывод JSON (`--json`)

`omi-cli` поддерживает вывод JSON нативно. В сочетании с `jq` или Python-скриптами **глобальная опция** `--json` должна быть размещена перед подкомандой.

```bash
# Получить список воспоминаний в JSON и извлечь ID и содержимое
omi --json memory list | jq '.[] | {id, content, category}'

# Получить заголовки последних 5 разговоров
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Перечислить открытые элементы действий
omi --json action-item list --open | jq '.[] | {id, title, due_at}'

# Перечислить цели
omi --json goal list | jq '.[] | {id, title, progress: .progress_percent}'
```

## 5. Диагностика сессии

Используйте эти две команды в паре для быстрого устранения проблем.

```bash
# 1) Сначала проверьте локальную конфигурацию
omi auth status

# 2) Подтвердите с сервером Omi
omi auth whoami

# 3) Если необходимо, перезапустите вход
omi auth login
```

## 6. Лучшие практики

* **Используйте `--json` в скриптах:** Избегайте парсинга свободного текста; всегда полагайтесь на структурированный вывод JSON.
* **Изолируйте среды с помощью `pipx`:** Избегает конфликтов зависимостей с другими Python-пакетами.
* **Не делитесь API-ключами:** Ключи `omi_dev_*` предоставляют полный доступ к аккаунту — храните их в менеджере секретов или переменных среды.
* **Выходите из системы на общих устройствах:** Используйте `omi auth logout` после сеансов на общих машинах.

## 7. Устранение неполадок

| Симптом | Вероятная причина | Решение |
| :--- | :--- | :--- |
| `command not found: omi` | PATH не содержит каталог bin pipx | Выполните `pipx ensurepath` и перезапустите терминал |
| `401 Unauthorized` | API-ключ недействителен или просрочен | Сгенерируйте новый ключ на app.omi.me и обновите |
| `connection refused` | Нет доступа к сети сервера Omi | Проверьте подключение к Интернету и настройки прокси |
| `permission denied` на файлах конфигурации | Каталог конфигурации недоступен для записи | Проверьте права доступа к `~/.config/omi` |
