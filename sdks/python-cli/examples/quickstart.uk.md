# Практичний посібник з omi-cli (Ukrainian Quickstart)

> Практичний посібник для роботи з Omi безпосередньо з вашого термінала — створено як для розробників, так і для автономних AI-агентів.

`omi-cli` — це офіційний інтерфейс командного рядка для API розробника [Omi](https://omi.me). Він дозволяє у структурований та автоматизований спосіб керувати чотирма основними ресурсами системи: спогадами (memories), розмовами (conversations), завданнями (action items) та цілями (goals).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Офіційна документація:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Вихідний код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Встановлення

Рекомендований спосіб встановлення — через `pipx`, що ізолює залежності в окремому віртуальному середовищі:

```bash
# Рекомендовано: ізольоване встановлення через pipx
pipx install omi-cli

# Або через стандартний pip
pip install omi-cli
```

> **Увага: Назва пакета vs. Назва команди**
> * Назва пакета на PyPI — **`omi-cli`** (назва `omi` належить іншому сторонньому пакету).
> * Виконувана команда у вашому терміналі — просто **`omi`**.

Перевірте коректність встановлення за допомогою команди перевірки версії та довідки:

```bash
omi --version
omi --help
```

## 2. Автентифікація (Authentication)

`omi-cli` підтримує два основні способи автентифікації:

| Метод | Призначення | Приклад команди |
| :--- | :--- | :--- |
| **Ключ API розробника (`omi_dev_*`)** | Автоматизація, CI/CD, headless-сервери, AI-агенти | `omi auth login --api-key ...` або `OMI_API_KEY` |
| **OAuth через браузер (Google/Apple)** | Локальні робочі станції розробників | `omi auth login --browser` (Google) / `--provider apple` |

### Інтерактивний вхід
Якщо запустити команду без додаткових прапорців, з'явиться діалог вибору:

```bash
omi auth login
# 1) Browser — Вхід через Google у браузері (для Apple вкажіть `--provider apple`)
# 2) API key — Введіть ключ розробника, згенерований на app.omi.me
```

### Прямий вхід через браузер
```bash
# Стандартний вхід через Google
omi auth login --browser

# Альтернативний вхід через Apple
omi auth login --browser --provider apple
```

### Використання ключа API розробника
Отримайте ключ на панелі [app.omi.me](https://app.omi.me) у розділі **Developer → API Keys**:

```bash
# Зберегти назавжди у локальному профілі (вводьте інтерактивно, щоб захистити історію термінала)
omi auth login --api-key

# Або встановити як змінну середовища (ідеально для контейнерів та CI/CD)
# Примітка: якщо у поточному профілі вже збережено ключ, спочатку виконайте `omi auth logout`.
export OMI_API_KEY="omi_dev_your_actual_key_here"
```

### Перевірка статусу автентифікації
* `omi auth status`: Показує активний локальний профіль і масковані облікові дані; термін дії відображається лише для профілів OAuth (працює офлайн).
* `omi auth whoami`: Відправляє запит до сервера Omi для підтвердження дійсності сесії в реальному часі (потребує інтернет-з'єднання).

```bash
omi auth status
omi auth whoami
```

Завершення сесії:
```bash
omi auth logout
# Якщо встановлено змінну середовища OMI_API_KEY, видаліть її із сесії (Bash/Zsh: `unset OMI_API_KEY`).
```

## 3. Основні команди

### Спогади (Memories)
Атомарні одиниці контексту, зафіксовані Omi:

```bash
# Переглянути збережені спогади
omi memory list

# Створити новий спогад
omi memory create "Надає перевагу лаконічним технічним відповідям із прикладами на Python" --category work

# Отримати деталі конкретного спогаду
omi memory get <MEMORY_ID>
```

### Розмови (Conversations)
Історія аудіозаписів та розшифрованих діалогів із пристроїв Omi:

```bash
# Показати останні 5 розмов
omi conversation list --limit 5

# Отримати деталі та повну текстову транскрипцію розмови
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Завдання та дії (Action Items)
Пункти дій, автоматично виділені з діалогів:

```bash
# Список відкритих завдань
omi action-item list --open

# Позначити завдання як виконане
omi action-item complete <ACTION_ITEM_ID>
```

### Цілі (Goals)
Метрики прогресу та довгострокові цілі:

```bash
# Список активних цілей
omi goal list

# Створити нову кількісну ціль
omi goal create "Випивати 2л води щодня" --type numeric --target 2 --unit liters
```

## 4. Структурована автоматизація та вивід JSON (`--json`)

`omi-cli` розроблено з першочерговою підтримкою автоматизованих конвеєрів обробки даних. Додавання глобального прапорця `--json` повертає відповіді у валідному форматі JSON:

```bash
# Список спогадів у JSON із фільтрацією через jq
omi --json memory list | jq '.[] | {id, content, category}'

# Отримати назви останніх розмов
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Переглянути відкриті завдання у форматі JSON
omi --json action-item list --open | jq '.'
```

> **Важливе правило синтаксису:**
> Прапорець `--json` є **глобальним параметром** і має вказуватися **перед** підкомандою:
> * Правильно: `omi --json memory list`
> * Неправильно: `omi memory list --json`

## 5. Таблиця кодів виходу (Exit Codes)

Для надійної обробки помилок у скриптах та пайплайнах CI/CD:

| Код виходу | Значення | Опис |
| :---: | :--- | :--- |
| `0` | **Успіх (Success)** | Команда виконана успішно. |
| `1` | **Помилка використання (Валідація)** | Недійсні значення або помилка валідації застосунку; синтаксичні помилки парсера Click повертають код `2`. |
| `2` | **Помилка автентифікації / Синтаксису CLI** | Відсутня авторизація, застарілий токен або невідомі прапорці парсера Click. |
| `3` | **Помилка сервера / Мережі (Server Error)** | Відповідь HTTP 5xx, тайм-аут з'єднання або сервер недоступний. |
| `4` | **Обмеження запитів (Rate Limited)** | Відповідь HTTP 429 — перевищено ліміт запитів. |
| `5` | **Не знайдено (Not Found)** | Відповідь HTTP 404 — запитуваний ресурс не існує. |

## 6. Приклади для різних командних оболонок

### Bash / Zsh (Linux / macOS)
```bash
# Встановлення ключа сесії
export OMI_API_KEY="omi_dev_your_actual_key_here"

# Виконання команди з перевіркою коду виходу
omi --json memory list --limit 10
if [ $? -ne 0 ]; then
    echo "Помилка під час отримання спогадів користувача." >&2
fi
```

### PowerShell (Windows)
```powershell
# Встановлення змінної середовища у PowerShell
$env:OMI_API_KEY = "omi_dev_your_actual_key_here"

# Пряме перетворення JSON-виводу на об'єкти PowerShell
$memories = omi --json memory list | ConvertFrom-Json
$memories | Select-Object id, content, category

# Перевірка помилок за допомогою $LASTEXITCODE
if ($LASTEXITCODE -ne 0) {
    Write-Error "Команда Omi завершилася з кодом помилки $LASTEXITCODE"
}
```

## 7. Інтеграція з локальним Desktop API

Коли на комп'ютері запущено програму Omi Desktop, CLI може надсилати запити до локальних знімків екрана без хмарних запитів:

```bash
# Налаштування локальної точки доступу (змінні середовища захищають токен)
export OMI_LOCAL_API_URL="http://127.0.0.1:47778"
read -r -s -p "Desktop token: " OMI_LOCAL_TOKEN; echo
export OMI_LOCAL_TOKEN

# Перевірка локального підключення
omi --json local status

# Пошук по нещодавній візуальній шкалі
omi --json local search-screen "Квартальний звіт" --days 7 --app Safari
```

## 8. Керування декількома профілями (Profiles)

Для перемикання між особистими, робочими акаунтами та тестовими середовищами використовуйте параметр `--profile`. Налаштування зберігаються у файлі `~/.omi/config.toml`:

```bash
# Створити особистий профіль та увійти
omi --profile personal auth login

# Створити робочий профіль та увійти
omi --profile work auth login

# Виконати команду з конкретним профілем
omi --profile work memory list

# Запуск із тестовою точкою доступу
omi --profile staging --api-base https://api-staging.omi.me memory list
```

## 9. Рекомендації з безпеки

* **Не зберігайте ключі в Git:** Ніколи не фіксуйте API-ключі у загальнодоступних репозиторіях; використовуйте менеджери секретів або файли `.env`, додані до `.gitignore`.
* **Історія термінала:** Уникайте передачі ключів у відкритому вигляді через аргументи командного рядка; віддавайте перевагу інтерактивному введенню або змінній `OMI_API_KEY`.
* **Права доступу:** На Unix-системах обмежуйте права доступу до директорії налаштувань `~/.omi/` (`chmod 700 ~/.omi`).
