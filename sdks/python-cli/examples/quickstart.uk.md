# Короткий посібник omi-cli (Українська)

> Практичний посібник для взаємодії з Omi з терміналу. Підходить як для людей, так і для AI-агентів.

`omi-cli` — це офіційний інтерфейс командного рядка для взаємодії з API розробника [Omi](https://omi.me). Він ефективно та програмовано обробляє чотири ключові ресурси Omi — **спогади, розмови, елементи дій і цілі**.

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Офіційна документація:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Вихідний код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Встановлення

Рекомендований метод встановлення використовує `pipx` для ізоляції залежностей.

```bash
# Рекомендовано: встановлення через pipx
pipx install omi-cli

# Альтернативно: використовуйте pip
pip install omi-cli
```

> **Важливо: різниця між назвою пакета та назвою команди**
> * Встановлений Python-пакет називається **`omi-cli`** (окремий пакет `omi` — це інший, непов'язаний пакет).
> * Виконувана команда в терміналі після встановлення називається **`omi`**.

Після встановлення перевірте версію та довідку.

```bash
omi --version
omi --help
```

## 2. Автентифікація

`omi-cli` підтримує два способи автентифікації.

| Спосіб | Рекомендоване використання | Приклад команди |
| :--- | :--- | :--- |
| **API-ключ розробника (`omi_dev_*`)** | CI/CD, автоматизовані скрипти, AI-агенти | `omi auth login --api-key ...` або змінна середовища |
| **OAuth у браузері (Google/Apple)** | ПК розробника / ноутбук | `omi auth login --browser` |

### Інтерактивний вхід
Без опцій вам буде запропоновано вибрати між входом через браузер та введенням API-ключа.

```bash
omi auth login
# 1) Браузер — увійдіть за допомогою облікового запису Google або Apple (для людей)
# 2) API-ключ — вставте ключ розробника з app.omi.me (для агентів/CI)
```

### Прямий вхід через браузер
```bash
omi auth login --browser
```

### Використання API-ключа
Отримайте ключ розробника в **Developer → API Keys** на [app.omi.me](https://app.omi.me), а потім налаштуйте його.

```bash
# Встановити через команду
omi auth login --api-key omi_dev_...

# Або через змінну середовища (ідеально для CI/CD або контейнерів)
export OMI_API_KEY=omi_dev_...
```

### Перевірка стану автентифікації
* `omi auth status`: показує локальний профіль, замаскований токен і дату закінчення (працює офлайн).
* `omi auth whoami`: надсилає справжній запит автентифікації на сервер Omi (потрібне підключення до мережі).

```bash
omi auth status
omi auth whoami
```

Щоб вийти:
```bash
omi auth logout
```

## 3. Базове використання

Ви можете перелічувати та керувати чотирма ключовими ресурсами Omi.

### Спогади (Memories)
Керуйте фактами та знаннями, які система засвоїла.

```bash
# Перелічити всі спогади
omi memory list

# Створити новий спогад
omi memory create "Користувач надає перевагу темному режиму" --category lifestyle

# Показати деталі конкретного спогаду
omi memory get <MEMORY_ID>
```

### Розмови (Conversations)
Історія аудіо або тексту розмов, записаних носимим пристроєм або додатком.

```bash
# Отримати останні 5 розмов
omi conversation list --limit 5

# Показати деталі розмови та транскрипцію
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Елементи дій (Action Items)
Завдання або наступні кроки, автоматично витягнуті з розмов.

```bash
# Перелічити лише відкриті елементи дій
omi action-item list --open

# Позначити елемент дії як завершений
omi action-item complete <ACTION_ITEM_ID>
```

### Цілі (Goals)
Керуйте цілями, чий прогрес відстежується.

```bash
# Перелічити всі цілі
omi goal list
```

## 4. Обробка скриптів та JSON-виведення (`--json`)

`omi-cli` підтримує JSON-виведення нативно. У поєднанні з `jq` або Python-скриптами **глобальна опція** `--json` повинна бути розміщена перед підкомандою.

```bash
# Отримати список спогадів у JSON та витягти ID і вміст
omi --json memory list | jq '.[] | {id, content, category}'

# Отримати заголовки останніх 5 розмов
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# Перелічити відкриті елементи дій
omi --json action-item list --open | jq '.[] | {id, title, due_at}'

# Перелічити цілі
omi --json goal list | jq '.[] | {id, title, progress: .progress_percent}'
```

## 5. Діагностика сесії

Використовуйте ці дві команди в парі для швидкого усунення проблем.

```bash
# 1) Спочатку перевірте локальну конфігурацію
omi auth status

# 2) Підтвердіть з сервером Omi
omi auth whoami

# 3) Якщо потрібно, перезапустіть вхід
omi auth login
```

## 6. Найкращі практики

* **Використовуйте `--json` у скриптах:** Уникайте парсингу вільного тексту; завжди покладайтеся на структуроване JSON-виведення.
* **Ізолюйте середовища за допомогою `pipx`:** Уникає конфліктів залежностей з іншими Python-пакетами.
* **Не діліться API-ключами:** Ключі `omi_dev_*` надають повний доступ до облікового запису — зберігайте їх у менеджері секретів або змінних середовища.
* **Виходьте із системи на спільних пристроях:** Використовуйте `omi auth logout` після сеансів на спільних машинах.

## 7. Усунення несправностей

| Симптом | Ймовірна причина | Рішення |
| :--- | :--- | :--- |
| `command not found: omi` | PATH не містить каталог bin pipx | Виконайте `pipx ensurepath` і перезапустіть термінал |
| `401 Unauthorized` | API-ключ недійсний або прострочений | Згенеруйте новий ключ на app.omi.me та оновіть |
| `connection refused` | Немає доступу до мережі сервера Omi | Перевірте підключення до Інтернету та налаштування проксі |
| `permission denied` на файлах конфігурації | Каталог конфігурації недоступний для запису | Перевірте дозволи `~/.config/omi` |
