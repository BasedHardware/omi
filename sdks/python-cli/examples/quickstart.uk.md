# omi-cli — український посібник швидкого старту

> Практичний посібник для роботи з Omi з термінала. Підходить і людям, і ШІ-агентам.

`omi-cli` — офіційний клієнт командного рядка для API розробників [Omi](https://omi.me).
Він дає швидкий і сценарний доступ до чотирьох основних сутностей Omi:
спогади, розмови, елементи дій та цілі.

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **Документація:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **Вихідний код:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

---

## 1. Встановлення

Рекомендований спосіб — `pipx`: він встановлює інструмент в ізольоване середовище,
тож його залежності не конфліктують з вашими проєктами.

```bash
# рекомендовано: встановлення через pipx
pipx install omi-cli

# або через pip
pip install omi-cli
```

> **Важливо: назва пакета і назва команди різні.**
> * Встановлюваний пакет — це **`omi-cli`** (окремий пакет `omi` — це інший, непов'язаний проєкт).
> * Після встановлення виконується команда **`omi`**.

Перевірте, що все працює:

```bash
omi --version
omi --help
```

## 2. Автентифікація

`omi-cli` підтримує два способи входу.

| Спосіб | Підходить для | Команда |
| :--- | :--- | :--- |
| **Ключ розробника (`omi_dev_*`)** | CI/CD, сценарії, ШІ-агенти | `omi auth login --api-key ...` або змінна середовища |
| **Вхід через браузер (Google/Apple)** | Робота на власному комп'ютері | `omi auth login --browser` |

### Інтерактивний вхід

Запустіть без параметрів — програма запитає, який спосіб використати.

```bash
omi auth login
# 1) Browser — вхід через Google або Apple (для людей)
# 2) API key — вставте ключ розробника з app.omi.me (для агентів/CI)
```

Якщо ви виберете ключ, введення буде приховано, тож ключ не залишиться в історії термінала.

### Вхід безпосередньо через браузер

```bash
omi auth login --browser
```

### Вхід ключом розробника

Отримайте ключ на [app.omi.me](https://app.omi.me) у розділі **Developer → API Keys**.

```bash
# збережіть ключ у конфігурацію
omi auth login --api-key omi_dev_...

# або передайте через середовище — зручніше для CI/CD та контейнерів
export OMI_API_KEY=omi_dev_...
```

Змінна середовища `OMI_API_KEY` використовується, коли в активному профілі немає
збереженого ключа, тож у контейнері нічого не потрібно записувати на диск. Якщо профіль
вже має ключ, він має пріоритет над змінною середовища.

### Перевірте доступ

Дві команди відповідають на різні питання — не плутайте їх:

* `omi auth status` — що збережено **локально**: профіль, замаскований ключ, дата закінчення.
  Працює без мережі.
* `omi auth whoami` — запит **до сервера Omi**: перевіряє, чи ключ справді приймається.
  Потребує мережі.

```bash
omi auth status    # локальна перевірка, офлайн
omi auth whoami    # перевірка на сервері
```

Оновіть токен, що закінчується, без повторного входу — ця команда дійсна
**лише для сесій браузера/OAuth**. Для профілю, автентифікованого ключем API
(`omi_dev_*`), `omi auth refresh` не вдається з помилкою використання (код 1):
немає токена для оновлення — замініть ключ у вебзастосунку Omi за потреби:

```bash
omi auth refresh
```

Вихід:

```bash
omi auth logout
```

## 3. Базові команди

### Спогади (memories)

Факти та знання, які система запам'ятала про вас.

```bash
# список спогадів
omi memory list

# створити новий
omi memory create "Користувач надає перевагу темній темі" --category lifestyle

# переглянути конкретний
omi memory get <MEMORY_ID>
```

### Розмови (conversations)

Історія голосу та тексту з пристрою або застосунку.

```bash
# 5 найновіших розмов
omi conversation list --limit 5

# повна розмова з транскрипцією
omi conversation get <CONVERSATION_ID> --include-transcript
```

### Елементи дій (action items)

Завдання, які Omi вивів із розмов.

```bash
# лише відкриті
omi action-item list --open

# позначити як виконане
omi action-item complete <ACTION_ITEM_ID>
```

### Цілі (goals)

```bash
# список цілей
omi goal list

# записати нове значення прогресу (потрібні ОБИДВА аргументи: ціль і значення)
omi goal progress <GOAL_ID> 25

# історія змін
omi goal history <GOAL_ID>
```

## Питання природною мовою (`ask`)

Окрема команда верхнього рівня: приймає питання природною мовою,
а відповідь будується з ваших розмов.

```bash
omi ask "що я вирішив щодо переїзду"
omi --json ask "які елементи дій я пообіцяв завершити цього тижня"
```

## 4. JSON та сценарії (`--json`)

`omi-cli` може видавати JSON, читабельний для машин. Параметр `--json` є
**глобальним** і має стояти **перед** підкомандою.

```bash
# спогади: витягніть id, текст і категорію
omi --json memory list | jq '.[] | {id, content, category}'

# заголовки останніх розмов
omi --json conversation list --limit 5 | jq '.[] | {id, title: .structured.title, started_at}'

# відкриті елементи дій
omi --json action-item list --open | jq '.'
```

> **Поширена помилка.** `--json` стоїть перед підкомандою, а не після.
> * Правильно: `omi --json memory list`
> * Неправильно: `omi memory list --json`

У режимі `--json` зникають повідомлення про прогрес і спінери для людей —
stdout містить лише один валідний JSON-документ. Помилки йдуть у stderr
у формі `{"error": "...", "detail": "..."}`.

## 5. Коди виходу

Стабільні коди виходу для розгалуження у сценаріях.

| Код | Значення |
| :--- | :--- |
| `0` | Успіх |
| `1` | Помилка використання (неправильний прапорець, відсутній обов'язковий аргумент) |
| `2` | Автентифікація не вдалася — потрібен вхід |
| `3` | Помилка сервера/мережі |
| `4` | Обмеження швидкості — спробуйте пізніше |
| `5` | Ресурс не знайдено |

```bash
if ! omi memory get "$MEMO_ID" --json > /tmp/m.json; then
  code=$?
  case $code in
    2) omi auth login --browser ;;
    5) echo "такого спогаду немає" ;;
    *) echo "помилка $code" ;;
  esac
fi
```

## 6. Профілі та конфігурація

Якщо у вас кілька облікових записів або середовищ, розділіть їх профілями.
Налаштування зберігаються у `~/.omi/config.toml`.

```bash
# вхід до особистого профілю
omi --profile personal auth login

# вхід до робочого профілю
omi --profile work auth login

# виконати команду у певному профілі
omi --profile work memory list
```

Профіль, що використовується, визначається в такому порядку: параметр `--profile`
(або `-p`) має пріоритет над усім; потім змінна середовища `OMI_PROFILE`; потім
активний профіль у `~/.omi/config.toml`; і нарешті профіль `default` як запасний.

Перегляньте та змініть саму конфігурацію:

```bash
# що зараз налаштовано
omi config show

# де файл конфігурації
omi config path

# змініть значення
omi config set api_base https://api.omi.me
```
