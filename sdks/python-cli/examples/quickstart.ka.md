# omi-cli სწრაფი დაწყების სახელმძღვანელო (Georgian Quickstart)

> პრაქტიკული სახელმძღვანელო Omi-სთან ტერმინალიდან მუშაობისთვის — შექმნილი დეველოპერებისა და ავტონომიური ხელოვნური ინტელექტის აგენტებისთვის.

`omi-cli` არის ოფიციალური ბრძანებათა სტრიქონის ინტერფეისი (CLI) [Omi](https://omi.me) პლატფორმის დეველოპერის API-სთვის. ის უზრუნველყოფს სტრუქტურირებულ, აგენტებისთვის ოპტიმიზებულ წვდომას ოთხ ძირითად რესურსზე: **მოგონებები** (memories), **საუბრები** (conversations), **სამოქმედო პუნქტები** (action items) და **მიზნები** (goals).

* **PyPI:** [pypi.org/project/omi-cli](https://pypi.org/project/omi-cli/)
* **ოფიციალური დოკუმენტაცია:** [docs.omi.me/doc/developer/cli/introduction](https://docs.omi.me/doc/developer/cli/introduction)
* **საწყისი კოდი:** [github.com/BasedHardware/omi/tree/main/sdks/python-cli](https://github.com/BasedHardware/omi/tree/main/sdks/python-cli)

## 1. ინსტალაცია

პაკეტების კონფლიქტის თავიდან ასაცილებლად და სუფთა გარემოს შესანარჩუნებლად რეკომენდებულია `pipx`-ის გამოყენება:

```bash
# რეკომენდებული მეთოდი: იზოლირებული ინსტალაცია pipx-ის მეშვეობით
pipx install omi-cli

# ალტერნატიული ინსტალაცია სტანდარტული pip-ის გამოყენებით (მაგ. ვირტუალურ გარემოში)
pip install omi-cli
```

> **მნიშვნელოვანი განსხვავება: პაკეტის სახელი vs. ბრძანების სახელი**
> * ინსტალაციისას პაკეტის სახელია **`omi-cli`**.
> * ტერმინალში გასაშვები ბრძანება არის **`omi`**.

ინსტალაციის სისწორის შემოწმება:

```bash
omi --version
```

## 2. ავთენტიფიკაცია

`omi-cli` მხარს უჭერს ავთენტიფიკაციის ორ ძირითად მეთოდს: **OAuth ბრაუზერის მეშვეობით** (ინტერაქტიული მომხმარებლებისთვის) და **დეველოპერის API გასაღები** (ავტომატიზაციისა და AI აგენტებისთვის).

### მეთოდი A: შესვლა ბრაუზერის მეშვეობით (მომხმარებლებისთვის)

ნაგულისხმევი მეთოდი იყენებს Google-ის ანგარიშს:

```bash
omi auth login
```

ან ავტორიზაცია Apple ID-ით:

```bash
omi auth login --provider apple
```

ეს ბრძანება ხსნის ვებ-ბრაუზერის ფანჯარას იდენტიფიკაციისთვის და ინახავს წვდომის ტოკენს კონფიგურაციის ფაილში `~/.omi/config.toml`.

### მეთოდი B: დეველოპერის API გასაღები (სკრიპტები და აგენტები)

ფონური სერვისებისთვის, CI/CD პროცესებისთვის ან ავტონომიური აგენტებისთვის გამოიყენეთ დეველოპერის API გასაღები (`omi_dev_*`):

```bash
# ვარიანტი 1: გარემოს ცვლადის (Environment Variable) მინიჭება (საუკეთესო პრაქტიკა კონტეინერებისთვის)
export OMI_API_KEY="omi_dev_your_key_here"

# ვარიანტი 2: შესვლა და გასაღების შენახვა ლოკალურ კონფიგურაციაში
omi auth login --api-key "omi_dev_your_key_here"
```

### ავთენტიფიკაციის სტატუსის შემოწმება

სტატუსის შესამოწმებლად ხელმისაწვდომია ორი ბრძანება:

```bash
# ლოკალური შემოწმება ქსელური მოთხოვნის გარეშე (კითხულობს კონფიგურაციას ან გარემოს ცვლადებს)
omi auth status

# აქტიური შემოწმება სერვერზე (ამოწმებს სესიის ვალიდურობას და აბრუნებს პროფილის მონაცემებს)
omi auth whoami
```

### სისტემიდან გამოსვლა

შენახული წვდომის მონაცემების ლოკალური სისტემიდან წასაშლელად:

```bash
omi auth logout
```

## 3. მოგონებების მართვა (Memories)

მოგონებები წარმოადგენს ცალკეულ ჩანაწერებსა და კონტექსტურ ფაქტებს, რომლებსაც Omi იმახსოვრებს თქვენთვის.

```bash
# ბოლო მოგონებების ჩამონათვალი (ნაგულისხმევად 25 ჩანაწერი)
omi memory list

# ნაჩვენები მოგონებების რაოდენობის შეზღუდვა
omi memory list --limit 10

# პაგინაცია (საწყისი ჩანაწერების გამოტოვება)
omi memory list --limit 10 --offset 20

# კონკრეტული მოგონების დეტალების ნახვა ID-ით
omi memory get <memory-id>

# ახალი მოგონების ხელით შექმნა
omi memory create "გუნდის საყვარელი პროგრამირების ენა არის Python."
```

## 4. საუბრები, სამოქმედო პუნქტები და მიზნები

### საუბრები (Conversations)

```bash
# ბოლოდროინდელი საუბრების სია
omi conversation list

# კონკრეტული საუბრის დეტალებისა და ტრანსკრიპტის ნახვა
omi conversation get <conversation-id>
```

### სამოქმედო პუნქტები (Action Items)

საუბრის დროს დაფიქსირებული ან ხელით დამატებული დავალებები:

```bash
# მიმდინარე აქტიური სამოქმედო პუნქტების ნახვა
omi action-item list

# ახალი სამოქმედო პუნქტის შექმნა
omi action-item create "შეხვედრამდე მოამზადეთ კოდის მიმოხილვის ანგარიში."
```

### მიზნები (Goals)

გრძელვადიანი მიზნები და პროგრესის მაჩვენებლები:

```bash
# ყველა აქტიური მიზნის ჩამონათვალი
omi goal list

# ახალი მიზნის დამატება
omi goal create "კვარტლის ბოლომდე Omi CLI ინსტრუმენტის ინტეგრაციის დასრულება."
```

## 5. JSON ფორმატი და მილსადენების ინტეგრაცია (jq)

ავტომატიზაციის სკრიპტებთან და AI აგენტებთან ინტეგრაციისთვის გამოიყენეთ გლობალური ალამი `--json`.

> **მნიშვნელოვანი წესი:** `--json` ალამი აუცილებლად უნდა მიეთითოს ქვე-ბრძანებამდე (**before** the subcommand):

```bash
# სწორია:
omi --json memory list

# არასწორია (გამოიწვევს Click პარსერის შეცდომას):
omi memory list --json
```

### `jq` ხელსაწყოთი ფილტრაციის მაგალითები:

```bash
# მხოლოდ მოგონებების ID-ების ამოღება
omi --json memory list | jq -r '.[].id'

# მოგონებების შინაარსის ტექსტურ ხაზებად გამოტანა
omi --json memory list | jq -r '.[].content'

# საუბრის ID-ისა და სათაურის გამოტანა კომპაქტურ ფორმატში
omi --json conversation list | jq -r '.[] | "\(.id): \(.structured.title)"'

# ღია სამოქმედო პუნქტების საერთო რაოდენობის დათვლა
omi --json action-item list | jq 'length'
```

## 6. გამოსვლის კოდები და შეცდომების მართვა

`omi-cli` იყენებს მკაცრად განსაზღვრულ გამოსვლის კოდებს, რომლებიც გაწერილია `omi_cli/errors.py`-ში:

| კოდი | მუდმივა | კატეგორია | მნიშვნელობა და რეკომენდებული ქმედება |
| :---: | :--- | :--- | :--- |
| **`0`** | `EXIT_OK` | წარმატება | ბრძანება წარმატებით და სრულად შესრულდა. |
| **`1`** | `EXIT_USAGE` | არასწორი გამოყენება | შიდა ვალიდაციის შეცდომა `omi-cli`-ში (მაგ. `--browser` და `--api-key` ერთდროულად მითითება). *შენიშვნა:* Click პარსერის სტანდარტული სინტაქსური შეცდომები აბრუნებს კოდს **2**. |
| **`2`** | `EXIT_AUTH` | ავთენტიფიკაცია | არასწორი API გასაღები, ვადაგასული სესია ან არარსებული ტოკენი. ასევე Click პარსერის შეცდომები. |
| **`3`** | `EXIT_SERVER` | სერვერის / ქსელის შეცდომა | HTTP 5xx პასუხი ან ქსელური კავშირის შეწყვეტა. მონაცემთა შენახვა სერვერზე გარანტირებული არ არის. |
| **`4`** | `EXIT_RATE_LIMITED` | მოთხოვნების ლიმიტის გადაჭარბება | HTTP 429 პასუხი. CLI ავტომატურად იმეორებს მოთხოვნას `Retry-After` სათაურის გათვალისწინებით. |
| **`5`** | `EXIT_NOT_FOUND` | რესურსი ვერ მოიძებნა | HTTP 404 პასუხი. მითითებული რესურსი ან ID არ არსებობს. |

> **წვდომის ტოკენის განახლება:** ბრძანება `omi auth refresh` განკუთვნილია მხოლოდ ბრაუზერის (OAuth) სესიებისთვის. დეველოპერის API გასაღებების გამოყენებისას ეს ბრძანება აბრუნებს შეცდომას (გამოსვლის კოდი 1), რადგან განსაახლებელი ტოკენი არ არსებობს.

## 7. ავტომატიზაციის სკრიპტების მაგალითები

### Bash სკრიპტი: მოგონების შექმნა შეცდომების დამუშავებით

```bash
#!/usr/bin/env bash
set -euo pipefail

TEXT="გუნდის სინქრონიზაციის შეხვედრა დაინიშნა ორშაბათს, 11:00 საათზე."

echo "ახალი მოგონების შექმნა..."
if RESPONSE=$(omi --json memory create "$TEXT" 2>&1); then
  MEMORY_ID=$(echo "$RESPONSE" | jq -r '.id // empty')
  echo "წარმატება! მოგონების ID: $MEMORY_ID"
else
  STATUS=$?
  echo "შეცდომა მოგონების შექმნისას (გამოსვლის კოდი: $STATUS)"
  case $STATUS in
    2) echo "ავთენტიფიკაციის შეცდომა: შეამოწმეთ OMI_API_KEY ან გაუშვით 'omi auth login'." ;;
    3) echo "სერვერის ან ქსელის შეცდომა. სცადეთ მოგვიანებით." ;;
    4) echo "მოთხოვნების ლიმიტი გადაჭარბებულია." ;;
    *) echo "დაფიქსირდა შეცდომა: $RESPONSE" ;;
  esac
  exit $STATUS
fi
```

### PowerShell სკრიპტი: სამოქმედო პუნქტების დამუშავება

```powershell
$response = omi --json action-item list | ConvertFrom-Json

foreach ($item in $response) {
    [PSCustomObject]@{
        Id          = $item.id
        Description = $item.description
        CreatedAt   = $item.created_at
    }
}
```

## 8. გაფართოებული შესაძლებლობები

### ლოკალურ Desktop API-სთან დაკავშირება

თუ თქვენს კომპიუტერზე გაშვებულია Omi-ს დესკტოპ აპლიკაცია, `omi-cli`-ს შეუძლია პირდაპირ დაუკავშირდეს მას პორტზე `47778` ღრუბლოვანი სერვისების გარეშე:

```bash
# გარემოს ცვლადების კონფიგურაცია ლოკალური API-სთვის
export OMI_LOCAL_API_URL="http://localhost:47778"
export OMI_LOCAL_TOKEN="your_local_security_token"

# ლოკალური სერვისის სტატუსის შემოწმება
omi --json local status
```

### პროფილების მართვა და ტესტირება (Staging)

ალამი `--profile` გაძლევთ საშუალებას იმუშაოთ რამდენიმე დამოუკიდებელ კონფიგურაციასთან (მაგ. პირადი, სამსახურებრივი ან სატესტო გარემო). კონფიგურაცია ინახება `~/.omi/config.toml`-ში:

```bash
# შესვლა სხვადასხვა პროფილზე
omi --profile personal auth login
omi --profile work auth login

# ბრძანებების გაშვება კონკრეტული პროფილის ქვეშ
omi --profile work memory list

# ტესტირება staging გარემოში
omi --profile staging --api-base https://api.staging.omi.me memory list
```

## 9. უსაფრთხოება და საუკეთესო პრაქტიკა

* **საიდუმლო გასაღებების დაცვა:** არასოდეს შეინახოთ `omi_dev_*` გასაღებები Git-ის საჯარო საცავებში. გამოიყენეთ გარემოს ცვლადები ან გასაღებების მართვის უსაფრთხო სისტემები (Secret Managers).
* **ფაილის წვდომის უფლებები (Unix):** დაიცავით კონფიგურაციის საქაღალდე მკაცრი წვდომის ნებართვებით:
  ```bash
  chmod 700 ~/.omi
  ```
