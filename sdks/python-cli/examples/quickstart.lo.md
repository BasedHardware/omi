# ເລີ່ມຕົ້ນນຳໃຊ້ omi-cli

ຄູ່ມືນີ້ສະຫຼຸບຄຳສັ່ງທຳອິດຂອງ omi-cli ເປັນພາສາລາວ ຊື່ຄຳສັ່ງ ແລະ ຂໍ້ຄວາມຂອງໂປຣແກຣມຍັງຄົງເປັນພາສາອັງກິດ ຕົວຢ່າງຄຳສັ່ງໃນຄູ່ມືນີ້ບໍ່ໄດ້ແກ້ໄຂຄວາມຊົງຈຳ, ບົດສົນທະນາ, ລາຍການສິ່ງທີ່ຕ້ອງເຮັດ ຫຼື ເປົ້າໝາຍຂອງທ່ານ

> `README.md` ສະບັບພາສາອັງກິດຍັງຄົງເປັນແຫຼ່ງອ້າງອີງຫຼັກ (source of truth)
> ສຳລັບທຸກຢ່າງທີ່ສະຫຼຸບໄວ້ສັ້ນໆ ຢູ່ນີ້

## ການຕິດຕັ້ງ

ຕ້ອງມີ Python 3.10 ຂຶ້ນໄປ ແລະ ບັນຊີ Omi

ຖ້າຕິດຕັ້ງ `pipx` ໄວ້ແລ້ວ:

```sh
pipx install omi-cli
omi --help
```

ຫຼື ຕິດຕັ້ງພາຍໃນ virtual environment ທີ່ເປີດໃຊ້ງານຢູ່:

```sh
python -m pip install omi-cli
omi --help
```

ໝາຍເຫດ: ຊື່ແພັກເກຈ Python ແມ່ນ `omi-cli` ສ່ວນຄຳສັ່ງທີ່ພິມໃນເທິມີນໍແມ່ນ `omi` ຫ້າມຕິດຕັ້ງແພັກເກຈຊື່ `omi` ຈາກ PyPI — ເປັນແພັກເກຈອື່ນທີ່ບໍ່ກ່ຽວຂ້ອງ ຖ້າເທິມີນໍຊອກ `omi` ບໍ່ເຫັນ ໃຫ້ກວດສອບວ່າເປີດໃຊ້ງານ virtual environment ຢູ່ ຫຼື ໂຟນເດີທີ່ `pipx` ຕິດຕັ້ງຟາຍລັນຄຳສັ່ງຢູ່ໃນ `PATH` ແລ້ວ

## ການເຂົ້າສູ່ລະບົບ

ເລີ່ມເຂົ້າສູ່ລະບົບແບບໂຕ້ຕອບ:

```sh
omi auth login
```

ເລືອກໄດ້ລະຫວ່າງເຂົ້າສູ່ລະບົບຜ່ານບຣາວເຊີ ຫຼື ວາງຄີ API ສຳລັບນັກພັດທະນາ ການປ້ອນແບບໂຕ້ຕອບຈະເຊື່ອງຄີ — ຫຼີກລ່ຽງການພິມຄີລົງໃນຄຳສັ່ງໂດຍກົງ ເພາະຄຳສັ່ງນັ້ນຈະຖືກບັນທຶກໄວ້ໃນປະຫວັດຂອງເທິມີນໍ

ເຂົ້າສູ່ລະບົບຜ່ານບຣາວເຊີໂດຍກົງ:

```sh
omi auth login --browser
```

ຄວນເຂົ້າສູ່ລະບົບເທິງເຄື່ອງດຽວກັບທີ່ລັນເທິມີນໍ ເພາະການຕອບກັບໃຊ້ທີ່ຢູ່ພາຍໃນເຄື່ອງ ປະຕິບັດຕາມຄຳແນະນຳທີ່ສະແດງເທິງໜ້າຈໍ

ເມື່ອເຂົ້າສູ່ລະບົບສຳເລັດແລ້ວ ກວດສອບການຕັ້ງຄ່າ ແລະ ການເຂົ້າເຖິງ API:

```sh
omi auth status
omi auth whoami
```

`status` ສະແດງສະຖານະໃນເຄື່ອງ ແລະ ປິດບັງສ່ວນທີ່ເປັນຄວາມລັບ ແຕ່ບໍ່ໄດ້ກວດສອບວ່າຂໍ້ມູນການຢືນຢັນຕົວຍັງໃຊ້ໄດ້ເທິງເຊີເວີຫຼືບໍ່ ສ່ວນ `whoami` ຈະສົ່ງຄຳຂໍທີ່ຢືນຢັນຕົວຕົນແລ້ວ ຫາກສຳເລັດຈະຢືນຢັນວ່າຂໍ້ມູນການຢືນຢັນຕົວຕົນໃຊ້ງານໄດ້ ເຖິງແມ່ນອາດຈະບໍ່ສະແດງຊື່ຂອງທ່ານ

ການຕັ້ງຄ່າຖືກບັນທຶກໄວ້ທີ່ `~/.omi/config.toml` ຕາມຄ່າເລີ່ມຕົ້ນ ຫ້າມແບ່ງປັນຟາຍນີ້ — ຟາຍອາດມີຂໍ້ມູນການຢືນຢັນຕົວຕົນຂອງທ່ານຢູ່

ສຳລັບວຽກອັດຕະໂນມັດ ໃຊ້ຕົວປ່ຽນສະພາບແວດລ້ອມ `OMI_API_KEY` ໄດ້ເມື່ອໂປຣໄຟລ໌ທີ່ໃຊ້ງານຢູ່ບໍ່ມີຄີບັນທຶກໄວ້ ບໍ່ດັ່ງນັ້ນລະບົບຈະໃຊ້ຄີຈາກໂປຣໄຟລ໌:

```sh
export OMI_API_KEY=omi_dev_...
omi memory list
```

ຕ້ອງການອອກຈາກລະບົບ ໃຫ້ລັນ `omi auth logout` — ຄຳສັ່ງນີ້ລຶບຂໍ້ມູນການຢືນຢັນຕົວຕົນທີ່ບັນທຶກໄວ້ໃນເຄື່ອງເທົ່ານັ້ນ ຫາກຕ້ອງການຍົກເລີກຄີເທິງເຊີເວີ ໃຫ້ໃຊ້ໜ້າຈັດການຄີສຳລັບນັກພັດທະນາໃນບັນຊີຂອງທ່ານ

## ເບິ່ງຂໍ້ມູນຂອງທ່ານ

```sh
omi memory list --limit 5
omi conversation list --limit 5
omi action-item list --open
omi goal list
```

ລາຍການຫວ່າງເປົ່າອາດໝາຍຄວາມງ່າຍໆ ວ່າບໍ່ມີລາຍການທີ່ກົງກັບເງື່ອນໄຂ ເບິ່ງຕົວກັ່ນຕອງຂອງແຕ່ລະຄຳສັ່ງໄດ້ຈາກໜ້າຊ່ວຍເຫຼືອ:

```sh
omi memory list --help
omi action-item list --help
```

## ເອົາຕ໌ພຸດ JSON ແລະ ການແບ່ງໜ້າ

ວາງຕົວເລືອກສ່ວນກາງ `--json` **ໄວ້ກ່ອນ**ກຸ່ມຄຳສັ່ງ:

```sh
omi --json memory list --limit 25 --offset 0
omi --json memory list --limit 25 --offset 25
```

ຄຳສັ່ງທຳອິດຂໍຄວາມຊົງຈຳ 25 ລາຍການທຳອິດ ສ່ວນຄຳສັ່ງທີສອງຂໍ 25 ລາຍການຖັດໄປ ດັ່ງນັ້ນໜ້າດຽວຈຶ່ງບໍ່ແມ່ນສຳເນົາຂໍ້ມູນທັງໝົດ ເອົາຕ໌ພຸດ JSON ເກັບຕົວກຳນົດ (ID) ແບບເຕັມ ໃນຂະນະທີ່ຕາຕະລາງອາດຫຍໍ້ ID ເພື່ອໃຫ້ອ່ານງ່າຍ

ການບັນທຶກໜຶ່ງໜ້າໄວ້ໃນຟາຍ:

```sh
omi --json memory list --limit 25 --offset 0 > memories-page-1.json
```

ການປ່ຽນເສັ້ນທາງແບບນີ້ຈະສ້າງ ຫຼື ຂຽນທັບຟາຍໃນເຄື່ອງ ກວດສອບວ່າຄຳສັ່ງເຮັດວຽກສຳເລັດກ່ອນນຳເນື້ອຫາໄປໃຊ້ ຂໍ້ຜິດພາດຈະຖືກຂຽນໄປຍັງເອົາຕ໌ພຸດຂໍ້ຜິດພາດ (standard error) — ຟາຍຫວ່າງເປົ່າບໍ່ໄດ້ແປວ່າບໍ່ມີຂໍ້ມູນ ຟາຍທີ່ສົ່ງອອກອາດມີຂໍ້ມູນສ່ວນຕົວ ຄວນເກັບຮັກສາໄວ້ເປັນຄວາມລັບ

## ໂປຣໄຟລ໌

ຖ້າໃຊ້ຫຼາຍບັນຊີ ຫຼື ຫຼາຍສະພາບແວດລ້ອມ ໃຫ້ໃຊ້ຕົວເລືອກ `--profile` (ຫຼື `-p`):

```sh
omi --profile work auth login
omi --profile work memory list
```

ຖ້າບໍ່ລະບຸ ລະບົບຈະໃຊ້ໂປຣໄຟລ໌ຈາກຕົວປ່ຽນ `OMI_PROFILE` ກ່ອນ ແລ້ວຈຶ່ງໃຊ້ໂປຣໄຟລ໌ທີ່ໃຊ້ງານຢູ່ຈາກຟາຍຕັ້ງຄ່າ (ຄ່າເລີ່ມຕົ້ນແມ່ນ `default`) ໂປຣໄຟລ໌ທັງໝົດຖືກເກັບໄວ້ໃນ `~/.omi/config.toml`

## ລະຫັດອອກ (Exit Codes)

ສຳລັບສະຄຣິບ ແລະ ວຽກອັດຕະໂນມັດ CLI ກຳນົດລະຫັດອອກທີ່ແນ່ນອນໄວ້:

| ລະຫັດ | ຄວາມໝາຍ | ລາຍລະອຽດ |
| :---: | :--- | :--- |
| `0` | ສຳເລັດ | ຄຳສັ່ງເຮັດວຽກສຳເລັດສົມບູນ |
| `1` | ຂໍ້ຜິດພາດໃນການໃຊ້ຄຳສັ່ງ | CLI ກວດພົບການໃຊ້ຜິດວິທີ ເຊັ່ນ ໃຊ້ຕົວເລືອກທີ່ໃຊ້ຮ່ວມກັນບໍ່ໄດ້ |
| `2` | ຂໍ້ຜິດພາດດ້ານການຢືນຢັນຕົວຕົນ ຫຼື ອາຣ໌ກິວເມນຕ໌ | ບໍ່ມີຂໍ້ມູນການຢືນຢັນຕົວຕົນ, ໂທເຄນໝົດອາຍຸ ຫຼື ສິດບໍ່ພຽງພໍ ລວມເຖິງຂໍ້ຜິດພາດດ້ານອາຣ໌ກິວເມນຕ໌ (ຕົວເລືອກບໍ່ຮູ້ຈັກ, ອາຣ໌ກິວເມນຕ໌ຫາຍ, ຄ່ານອກຂອບເຂດ) |
| `3` | ຂໍ້ຜິດພາດຂອງເຊີເວີ | ການຕອບກັບ 5xx, ການເຊື່ອມຕໍ່ຫຼົ້ມເຫຼວ, ບັນຫາເຄືອຂ່າຍ |
| `4` | ຖືກຈຳກັດອັດຕາການຮຽກໃຊ້ | 429 Too Many Requests |
| `5` | ບໍ່ພົບຂໍ້ມູນ | 404 Not Found (ບໍ່ພົບ ID ທີ່ຮ້ອງຂໍ) |

ລະຫັດ `4` ມັກຈະເປັນຊົ່ວຄາວ — ລໍຖ້າຈັກໜ່ອຍແລ້ວລອງໃໝ່ CLI ຈະລອງຄຳຂໍທີ່ຖືກຈຳກັດອັດຕາ (429) ໃຫ້ອັດຕະໂນມັດ ແລະ ປະຕິບັດຕາມ `Retry-After` ເມື່ອເຊີເວີສົ່ງມາ ລະຫັດ `3` ມັກຈະເປັນຊົ່ວຄາວສຳລັບການອ່ານ ແຕ່ສຳລັບການຂຽນອາດໝາຍຄວາມວ່າຜົນລັບບໍ່ຊັດເຈນ (`outcome unknown`) — ເຊີເວີອາດນຳໃຊ້ການປ່ຽນແປງໄປແລ້ວ ກວດສອບຊັບພະຍາກອນກ່ອນລອງໃໝ່ ລະຫັດ `2` ມີສາເຫດພົບເລື້ອຍໆ ສອງແບບ: ຖ້າຂໍ້ຄວາມສະແດງບັນຫາການຢືນຢັນຕົວຕົນ (ບໍ່ມີຂໍ້ມູນການຢືນຢັນຕົວຕົນ ຫຼື ໂທເຄນໝົດອາຍຸ) ໃຫ້ລັນ `omi auth login` ໃໝ່ ແຕ່ຖ້າເປັນຂໍ້ຜິດພາດດ້ານອາຣ໌ກິວເມນຕ໌ (ຕົວເລືອກບໍ່ຮູ້ຈັກ, ອາຣ໌ກິວເມນຕ໌ຫາຍ, ຄ່ານອກຂອບເຂດ) ໃຫ້ແກ້ໄຂຄຳສັ່ງ ລະຫັດ `5` ໝາຍຄວາມວ່າ ID ທີ່ຮ້ອງຂໍບໍ່ມີຢູ່ ຫຼື ບໍ່ສາມາດເຂົ້າເຖິງໄດ້
