# Direct single-service integration evidence

`integration/dev-stack.sh` is the registered L3 entry point. It launches the sibling
platform service directly, builds the shared surface tree once, drives the macOS and iOS
shells, then joins producer and consumer evidence for one run.

## How to run

```bash
# Hermetic core-side guards and report/receipt arbitration
node integration/lanes.mjs L2

# Full two-shell lane; chooses a simulator deterministically
node integration/lanes.mjs L3

# Or name the simulator explicitly
integration/dev-stack.sh --device <simulator-udid> --assert

# Applied negative controls; each full run must finish red at its named assertion
integration/red-proof-assert.sh
```

The L3 runner uses a unique temporary run directory and writes the immutable receipt only
after it has read the exact report. The headed click-through is intentionally outside this
harness and is never emitted as a result.

## Platform companion contract

The launcher executes `apps/service/bin/dev-server.ts` directly with:

```text
OMI_PORT=4851
OMI_QA_DB=<run-directory>/service.sqlite
OMI_RUN_ID=<run-id>
OMI_DEV_READY_RECORD=<run-directory>/service-readiness.json
OMI_DEV_EVIDENCE=1
```

The service must write this readiness record before the bounded readiness probe can pass:

```json
{
  "schema": "omi.dev-service-readiness.v1",
  "runId": "run-...",
  "executable": "apps/service/bin/dev-server.ts",
  "baseUrl": "http://127.0.0.1:4851",
  "databasePath": "/run/path/service.sqlite",
  "storeSetId": "sqlite:run-...",
  "storeCount": 1,
  "pid": 123,
  "evidencePath": "/v1/qa/evidence",
  "devToken": "local-dev-only",
  "ownerAccountId": "local-synthetic-owner"
}
```

An absent record, a different executable/path/run, a PID other than the exact launched
process, or a readiness response without the record fails. The token is read only by the
host launcher, passed only to native shell
custody, removed with the temporary facts, and never copied into the report or receipt.

After both shells finish, `GET /v1/qa/evidence?run=<run-id>` must return
`omi.producer-evidence.v1` with `storeSetId: "sqlite:<run-id>"` and exactly 14 rows. Each row carries the same `runId` and `storeSetId`, a shell
(`macos` or `ios`), a domain, and `evidence: "served-outcome"`. Every non-Listen row has a
positive `http.successful`; Chat also has positive `chat.durableAccepted`. Listen has:

```json
{
  "protocolReady": 1,
  "acceptedBinaryFrames": 1,
  "acceptedBinaryBytes": 3200,
  "audioSha256": "42eca52026e58e70efa3f3c44ef029830b1d30b8747d7e6c60489d6bd485d70a",
  "transcript": "the transcript returned for those accepted bytes"
}
```

The deterministic payload is 100 ms of non-silent signed PCM16 mono at 16 kHz, generated by
`deterministicListenAudio()` in `integration/lib/evidence-matrix.mjs`. An upgrade, open event,
or ready frame without accepted binary bytes is red.

## Shell result contract

The host gives each native shell the same run id and host-owned attribution key
`<run-id>::<shell>`. Each shell writes `omi.consumer-evidence.v1` with its shell name and
exactly seven rows. Every row includes:

```json
{
  "runId": "run-...",
  "shell": "macos",
  "domain": "memories",
  "fixture": "none",
  "evidence": "rendered-semantic",
  "observation": {
    "route": "memories",
    "state": "ready",
    "semantic": "non-empty text observed in the rendered surface"
  },
  "shellTreeHash": "40-character tree hash",
  "surfaceTreeHash": "40-character tree hash"
}
```

The Listen row additionally carries the rendered `observation.transcript`, which must contain
the producer transcript. The launcher adds its actual exit code after collection; the app
cannot self-award launcher success.

The final `omi.shell-domain-matrix.v1` report and receipt contain the 14 joined producer and
consumer rows. Missing, duplicate, wrong-run, wrong-shell, fixture, stale-tree, aggregate,
dispatch-only, readiness-only, and screenshot-only evidence all fail.
