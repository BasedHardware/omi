## What is open

Everything needed to run and build on Omi lives in [BasedHardware/omi](https://github.com/BasedHardware/omi), under the [MIT License](https://github.com/BasedHardware/omi/blob/main/LICENSE):

| Component | In the repo |
|-----------|-------------|
| Mobile apps | `app/` — Flutter app for iOS and Android |
| Backend | `backend/` — the API, processing, and MCP server |
| Desktop apps | `desktop/` — the macOS app, plus community-maintained ports |
| Firmware | `omi/firmware/` — DevKit and consumer (CV1) firmware |
| Hardware files | schematics, Gerbers, KiCad sources, and mechanical files — see [Open Hardware Files](/doc/hardware/consumer/index) |
| Apps platform | `plugins/` — open-source community apps |

## What Omi Cloud adds

Omi Cloud is the hosted service the apps use: the backend at `api.omi.me`, the app store, firmware updates, and the processing that turns audio into conversations and memories. A free account covers the core loop, and paid plans add more usage and features. Current plans are on [omi.me](https://www.omi.me/#pricing).

The Developer API, MCP server, CLI, and SDKs all run against Omi Cloud with your own account. You can read, fork, and modify everything in the repository.

## Can I run it myself? Can I control my data?

The source is all here, and contributors run the backend locally for development ([Backend setup](/doc/developer/backend/Backend_Setup)). Running your own production copy of Omi is not supported or documented.
