## What is open

Everything needed to run and build on Omi lives in [BasedHardware/omi](https://github.com/BasedHardware/omi), under the [MIT License](https://github.com/BasedHardware/omi/blob/main/LICENSE):

| Component | In the repo |
|-----------|-------------|
| Mobile apps | `app/` — Flutter app for iOS and Android |
| Backend | `backend/` — the API, processing, and MCP server |
| Desktop app | `desktop/` — the macOS app |
| Firmware | `omi/firmware/` — DevKit and consumer (CV1) firmware |
| Hardware files | schematics, Gerbers, KiCad sources, and mechanical files — see [Open Hardware Files](/doc/hardware/consumer/index) |
| Apps platform | `plugins/` — open-source community apps |

## What Omi Cloud adds

Omi operates a hosted service — the backend at `api.omi.me`, the app store, OTA firmware updates, and the infrastructure that processes conversations end to end. Free accounts include the core capture and transcription loop; paid plans add higher usage limits and features. See [omi.me pricing](https://www.omi.me/#pricing) for current plans and limits (prices stay there, not in these docs).

You do not need Omi Cloud to build on the platform: the Developer API, MCP server, CLI, and SDKs all work against the hosted service with your own account, and the open components above can be inspected, forked, and modified freely.

## Can I run it myself? Can I control my data?

The repository gives you the source, and contributors run the backend and app locally every day — the [Backend Setup](/doc/developer/backend/Backend_Setup) page documents that contributor workflow. Omi Cloud is the supported way to use the product end to end; self-hosting the full service is not something the team currently offers or documents.

You keep control of your data either way:
