## Overview

DevKit 2 is a necklace-form-factor dev kit built on the Seeed Xiao nRF52840 (Sense). It streams audio to the Omi app over BLE and, unlike DevKit 1, can record standalone to a **removable microSD card** (FAT/exFAT; bring your own card) and sync through the app afterwards. It has a small speaker and a 250 mAh 1S LiPo battery charged over USB-C.

| Component | Specification |
|-----------|---------------|
| Processor | Seeed Xiao nRF52840 Sense (`xiao_ble_sense`) |
| Storage | Removable microSD card over SPI (FAT/exFAT) |
| Speaker | Yes (enabled in DevKit 2 firmware) |
| Battery | 250 mAh 1S LiPo, charged over USB-C |
| Button | Single multi-function button (see below) |

<Note>
Standalone recordings still need the Omi app for transcription — the device records audio; processing happens on the phone/backend.
</Note>

## Button, LEDs, and power

The firmware source is the authority for this table (`omi/firmware/devkit/src/button.c`, `main.c`):

| Interaction | What happens |
|-------------|--------------|
| **Single tap** | Sends a BLE button event to the app. The app maps it to voice-question mode: tap to start asking, tap again to send. |
| **Double tap** | Sends a BLE button event. The app's action is configurable in **Settings → Device Settings** (end & save conversation is the default). |
| **Hold 3 seconds** | Device powers off (short haptic pulse, LEDs off). |
| **Any press while off** | Powers the device on. Don't hold — a 3-second hold after waking turns it straight back off. |

There is no power switch and no push-to-talk mode: a long hold always means power off.

| LED | Meaning |
|-----|---------|
| Solid blue | On and connected to the phone |
| Solid red | On, not connected |
| Blinking green (with red or blue) | USB cable plugged in |
| All off | Powered off |

Boot briefly blinks red, green, blue, then white.

## Testing device storage over BLE

Standalone recordings land on the microSD card as `audio/a01.txt`, `audio/a02.txt`, … (raw Opus-in-ADTS style bytes). The app imports them automatically when it reconnects (device storage support). To read or clear them yourself, write 6-byte commands to the storage characteristic and read 6-byte responses back (`[status, file_num, b2, b3, b4, b5]`):

| Command | Bytes | Meaning |
|---------|-------|---------|
| Read | `0, n, off_1, off_2, off_3, off_4` | Read file `n` from big-endian byte offset (e.g. `0,1,0,0,0,255` = offset 255) |
| Clear | `1, n, …` | Clear file 1 (the file number is ignored — firmware always clears file 1) |
| Heartbeat | `50, …` | Keep the session alive while reading |

Response codes: `0` read OK · `100` write OK · `200` clear OK · `3` file out of range · `4` file has size 0 · `5` requested size too large · `6` invalid command.

Helper scripts for discovery, listing, downloading, decoding, and deleting live in [`omi/firmware/scripts/devkit/`](https://github.com/BasedHardware/omi/tree/main/omi/firmware/scripts/devkit). Button events over the button characteristic are `1` single tap, `2` double tap, and `5` release. A long press powers the device off and is not reported.
