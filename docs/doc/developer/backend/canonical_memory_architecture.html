Ownership rules

Capture owns breadth.

No new intake writes Long-term or Archive directly.

Consolidation owns routing.

No generic promotion pass or user-asserted fast track exists.

Atomic apply owns admission.

A new active Long-term item cannot exist without its current receipt and per-memory graph assertion.

Canonical state owns truth.

Shared graph, keyword, vector, and compatibility stores are rebuildable projections. Public canonical or retained-assertion graph delete/rebuild returns HTTP 409.

Review resolution is atomic.

Revision-scoped review commands validate source commit, item revision, content hash, and route while committing the item and redacted queue row together.

Privacy closes the lineage.

Hidden and superseded aliases are scrubbed with the survivor; shared standalone evidence remains only while another non-deleted item owns it.

Fail-closed boundaries

  • Conversation capture persists only transcript-grounded quote references; extraction failures preserve prior state and successful empty results fully retract it.
  • Incomplete, duplicate, or unknown consolidation routes mutate nothing.
  • Promotion conserves authoritative source subject identity and attribution.
  • Missing or stale admission receipts reject Short-term → Long-term.
  • The item and graph assertion commit or roll back together.
  • Knowledge-graph reads are bounded and return only edges whose endpoints are in the returned node page; filtering reports truncation.
  • Restricted content never reaches keyword, compatibility, embedding, or vector providers; only ID-scoped deletes purge prior state.
  • Reclaimed expired-processing events repair current authoritative provider state before acknowledgement.
  • Projection failures leave retryable outbox work; they do not rewrite canonical state.
  • Archive and pending raw text remain outside protected default retrieval.
  • Alias lineages return one logical survivor, preferring the active Long-term canonical row.
  • Stale or competing review decisions cannot mutate a newer canonical revision.
  • Consolidation leases each revision before an LLM call; three failed attempts use canonical review or blocked-review quarantine, and never call the model again.
  • Delete-all returns only after a final control-fenced rescan observes no remaining non-tombstoned item.
  • Account-deletion markers make projection delivery delete-only, and provider purge waits for active projection leases to drain.

Invalid output, recurrence handoff failure, and apply conflicts persist a revision-scoped attempt under memory_runs. Retrying sources are isolated from fresh items. After three failures the canonical apply boundary commits review; an Archive-route conflict falls back to a blocked Short-term review with projection deletes, which removes the quarantined revision from the eligible query. If storage blocks both terminal commits, later jobs retry only those routes without another LLM call. A durable cursor advances the stable ordered scan past a blocked page and resets after reaching later work, so the blocked page remains failed rather than reporting silent success without pinning newer sources.

Required processing queries active pending required rows, and negative user review moves a row to terminal processing_rejected. TTL selects active, processed, expired Short-term rows in expires_at, memory_id order; consolidation selects active, processed, source-active Short-term rows in captured_at, memory_id order. Eligibility filters precede server-owned query limits, so unrelated rows cannot starve overflow. Each pass drains every batch in its selected set; overflow remains immediately eligible on the next Scheduler run, without a 24-hour watermark delay.

Scheduled maintenance gate

Scheduled maintenance is gated globally by MEMORY_CANONICAL_MAINTENANCE_ENABLED and inventories the bounded universal maintenance registry. Cloud Scheduler owns cadence; no UID allowlist, promotion timer, or separate interval gate exists.
