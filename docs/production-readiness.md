## Remaining release blockers

1. Native validation: macOS Debug, iOS arm64 Simulator Debug, and Android arm64 Debug builds pass. Stale CocoaPods metadata and inconsistent native dependency paths are repaired. Windows was not built in this macOS environment. Android now has native browser OAuth with PKCE, AndroidKeyStore-backed session storage, refresh and cancellation. Android generation streaming now uses the native session, resumes event cursors and cancels real requests. Its production Java engine received NATIVE_SSE_READY in a real terminal frame from the isolated live-AI Worker. This is transport proof, not a completed signed-in Android app flow. The Android emulator and iOS simulator render Welcome. Android reaches the real Google sign-in form; browser Back followed by Cancel restores Sign in immediately, and a late callback leaves the app signed out. macOS renders Welcome and reaches the Google account chooser. Android Nearby devices denial and regrant were exercised; scan registers successfully and returns after its timeout. Account selection/callback completion and physical-device capture remain unverified. A normal installed Android APK cannot inherit shell environment configuration; its staged Worker origin still needs explicit native/build configuration for a full signed-in app-to-Worker check.
2. Backend completeness: canonical memories return `projection_unavailable`; audio is persisted but no transcription pipeline exists. Production identity/entitlement configuration remains staging-oriented. The ratified task-mutation contract and client adapter exist, but the Worker has no task-write route or account-epoch authority wired to them. Durable audio retry/recovery is also incomplete. The imported canonical service requires production PostgreSQL, account/control and grant authority, Firebase application bindings, persistent codec keys and a real rendering/cursor composition; its local bootstrap intentionally renders no memories. Legacy api.omi.me/v3/memories returns a different editable model and cannot replace this contract. Task writes likewise require the server-owned account epoch and write registry; no default epoch was fabricated.
3. Live integration: live model inference through the PWA now passes with synthetic text. Signed attachment upload/download, completed native authentication and production service configuration still need end-to-end validation. Read-only inspection of the deployed Worker found no R2 signing secrets. The local configuration now corrects a one-character R2 account-ID mismatch and pins the deployment account; its signer regression failed before the correction and passes afterward. No remote configuration was changed.
4. Rollout: read-only `wrangler d1 migrations list --remote` confirms migration 0005 is still pending on the configured staging database (`/tmp/omi-v5-remote-migrations-status.log`). Review it before remote application. It conservatively marks only nonempty legacy open recordings failed, retaining bytes/metadata and preserving historical completed/failed states. Previously completed recordings are not retroactively verified. Follow `apps/backend-worker/RELEASE.md` for migration evidence and deployment gates.

The final macOS visual check found dark-theme text on the native light window. Onboarding now uses the existing desktop ink palette for copy, logo and controls; the inspected screenshot `/tmp/omi-v5-macos-ink.png` confirms readable text and the eight-dot mark. Mobile retains its white mark.

Recording lifecycle verification now covers native disconnect while session creation is pending and reconnect while an earlier open, upload or completion is delayed. Each capture owns its queue and server session, so old work cannot consume new bytes. Completion failures display an unconfirmed-save message, and sign-out retires delayed work and errors. These are production-hook tests with controlled native/backend responses; physical pendant validation remains outstanding.

Pending recording work is retired on sign-out/unmount, with deferred-open/upload regressions preventing cross-session continuation.
